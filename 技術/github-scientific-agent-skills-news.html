5 萬星 Scientific Agent Skills：177 個科研技能

2026年10月16日 14:00 • 閱讀時間 4 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/K-Dense-AI/scientific-agent-skills

Scientific Agent Skills 是 K-Dense 維護的開源科研技能庫，在程式碼託管平台累積 50,261 顆星標與 4,480 次複製。專案以 177 個技能覆蓋生物資訊、化學資訊、藥物開發、臨床研究、物理、地球科學與科學傳播等領域，並遵循 Agent Skills 開放標準，可搭配 Claude Code、Codex、Cursor 與 Gemini CLI 等代理程式使用。本文依據儲存庫公開說明、arXiv 論文與版本更新紀錄整理，說明其技能結構、安裝方式、安全機制與維護狀況。

Scientific Agent Skills 是什麼？

它是一套收錄 177 個科研技能的開源技能庫，為 AI 代理補上套件用法、資料來源與驗證規範，由 K-Dense 維護並採 MIT 授權。

此專案的定位是為通用 AI 代理補足科研領域的程序性知識。AI 代理在原理上可以使用任何 Python 套件或 API，但缺少領域慣例時容易誤用參數、忽略單位換算，或跳過必要的驗證步驟。專案的做法是把每項工作流程寫成獨立的技能文件，內容涵蓋套件版本、標準作法、驗證檢查與已知邊界，讓代理在執行前先取得可依據的說明。

專案的命名與範圍在觀察期內曾經調整。它原本以 Claude Scientific Skills 為名，限定在特定代理程式生態內使用，其後更名為 Scientific Agent Skills，並擴展到任何支援 Agent Skills 開放標準的宿主。儲存庫說明亦指出，目前已有超過 25 萬名科學研究者使用這套技能，且社群貢獻的比例持續提高。

技能在結構上並非單純的文件集。多數技能除了 SKILL.md 說明之外，還附帶可執行輔助程式、參考文件與範本，帶有 scripts 目錄的技能另有對應測試套件與依賴清單。這種設計讓技能可以被結構化驗證，而不只是靠人工閱讀確認內容正確。

它涵蓋哪些科學領域與技能分類？

涵蓋生物資訊、化學資訊、蛋白質體學、臨床研究、材料科學與天文物理等領域，另含 100 多個科學資料庫與 70 多個 Python 套件技能。

資料庫與套件覆蓋是這套技能最實質的部分。Database Lookup 技能記錄了 80 個科學與財務資料庫，包含 PubChem、ChEMBL、UniProt、COSMIC、ClinicalTrials.gov 與 USPTO，並標示各來源的存取條件、端點選擇、分頁方式與來源追溯要求。另有獨立技能處理 DepMap、Imaging Data Commons、PrimeKG、NCATS ARAX 與 AlphaGenome 等特定資源，BioServices、Biopython 與 gget 等多資料庫套件則進一步擴大覆蓋。

套件層面提供超過 70 個版本感知的技能，涵蓋 RDKit、Scanpy、PyTorch Lightning、scikit-learn、PyTDC、PathML、pydicom、NeuroKit2、PufferLib、QuTiP、GeoPandas、pymatgen、Qiskit 與分子動力學工具鏈。這些技能會標明所依據的版本基線，例如 PathML 3.0.8、GeoPandas 1.2.0 與 lab-hardware-cad 所依據的 build123d 0.13.0，避免代理套用已過期的 API 寫法。

平台整合與流程工具構成第三層。Benchling、DNAnexus、LatchBio、OMERO、Protocols.io、Open Notebook、Ginkgo Cloud Lab、LabArchives 與 Opentrons 各有專屬技能，另有超過 30 項分析與傳播工具處理文獻回顧、可追溯寫作、同儕審查與簡報產出。較新的工作流程包括聚合 CRISPR 篩選對比、流式細胞儀補償與設閘、低溫電子顯微鏡半圖驗證，以及海水碳酸鹽化學的物種計算。

Agent Skills 開放標準對生態有什麼意義？

它讓同一套技能檔案在多個代理宿主間通用，技能以 SKILL.md 加上 YAML frontmatter 描述，可被不同工具發現與載入，避免內容被鎖定在單一供應商。

開放標準主要解決內容重複撰寫的問題。在標準出現之前，同一套領域知識若要支援不同代理程式，通常需要各自維護一份格式不同的指令檔。Agent Skills 標準以固定的目錄結構與 YAML frontmatter 描述技能，任何支援該標準的宿主都能掃描指定路徑並載入，內容因此可跨工具重複使用。

此專案同時符合 Agent Plugins 1.0.0 的封裝規範，根目錄提供 plugin.json，技能置於 skills 目錄之下。支援該規範的客戶端會自動發現每個含 SKILL.md 的子目錄，並可將整套技能以單一外掛的形式載入。這種雙標準並行的做法，讓同一個儲存庫既可用於逐一安裝的技能，也可作為整體套件發佈。

標準化的另一項效益是供應鏈可追溯。專案要求所有技能在 frontmatter 中以引號標示版本，貢獻內容必須使用區塊式 YAML，並由參考驗證器檢查格式。這些規則讓技能的來源、版本與結構在自動化流程中可以被檢核，也讓第三方工具能夠分析技能之間的重複與衝突。

它的安裝方式與支援的代理程式有哪些？

可透過 npx skills add 或 gh skill install 安裝，亦能手動複製到技能目錄，支援 Claude Code、Cursor 與 Gemini CLI 等宿主。

主要安裝路徑有三種。最簡便的方式是執行 npx skills add K-Dense-AI/scientific-agent-skills，由通用安裝器依宿主決定寫入位置。若使用 GitHub CLI 2.90.0 以上版本，則可用 gh skill install 互動式瀏覽或指定單一技能，並透過 –agent 參數指定目標宿主，安裝時會記錄來源元資料以供供應鏈追溯。

版本固定是正式環境需要留意的設定。gh skill install 支援 –pin 參數指定發行標籤或提交雜湊，讓同一套技能在不同機器上保持一致，必要時可用 gh skill update 檢查或批次更新。對於需要重現性的研究流程，固定版本可避免技能更新後行為改變，導致既有分析結果無法複製。

不支援上述工具時仍可手動安裝。儲存庫可克隆至使用者層級的 ~/.agents/skills/ 或專案層級的 .agents/skills/ 目錄，支援技能來源清單的宿主則可將此儲存庫加入為 tap。文件亦針對 OpenClaw、NemoClaw、Pi 與 Hermes 等宿主說明差異，並提醒在預設拒絕對外連線的沙箱環境中，需要先由操作者核准相關網域，套件安裝與 API 呼叫才能運作。

專案如何處理技能的安全風險？

所有技能以 Cisco AI Defense 掃描器每週增量檢查，至少每 30 天全量重掃一次，結果公開於儲存庫的安全報告，並要求使用者只安裝需要的技能。

安全風險的來源在於技能本身具有執行能力。代理技能可以指示 AI 執行任意程式碼、安裝套件、發出網路請求與修改檔案，因此一份撰寫不當或帶有惡意的技能，足以引導代理做出有害行為。專案在文件開頭即明示這項風險，並將最終判斷責任交回安裝者。

具體機制包括提交審查與自動化掃描。所有貢獻需經審查流程，且每個技能都會以 Cisco AI Defense Skill Scanner 進行行為導向的掃描，結果發布於儲存庫的安全報告文件中。掃描採增量方式進行，未變更的技能沿用先前的檢查結果，全部技能至少每 30 天完整重掃一次，掃描器或模型更新時亦會重跑。

文件同時給出多項操作建議。使用者應避免一次安裝整套技能，只挑選工作實際需要的項目；安裝前閱讀 SKILL.md，確認其使用的套件與連線的外部服務；並留意技能作者，由 K-Dense 本身撰寫的技能已通過內部審查，社群貢獻的技能則在有限資源下盡力審核。使用者亦可自行以掃描器在本機檢查第三方技能，發現異常時透過議題回報。

專案的數據與維護狀況如何？

專案累積 50,261 顆星標、4,480 次複製與 208 位關注者，提交次數約 760 次，發布超過 100 個版本，並有 59 位貢獻者參與，最新版本為 v2.72.0。

專案建立於 2025 年 10 月，在約一年的時間內累積約 760 次提交與超過 100 個版本發布，貢獻者人數為 59 位，未結議題約 34 個。程式語言組成以 Python 為主，約占 980 萬位元組，另有 TeX 與 BibTeX 樣式檔約 27 萬位元組，反映技能說明與論文撰寫工具在專案中的比重。觀測時點最新一次推送為 2026 年 10 月 12 日。

從複製與星標的比例觀察，此專案的複製數約為星標數的十一分之一，屬於文件與技能型專案的常見區間。專案另有一篇 arXiv 論文描述其設計，編號 2609.00065，標題為 Scientific Agent Skills: A Library of Procedural Knowledge for Research Agents，用於說明技能作為程序性知識載體的設計取向。這類論文的存在，讓專案的引用方式與一般軟體儲存庫有所不同。

維護節奏可從版本發布的密度觀察。v2.70.0、v2.71.0 與 v2.72.0 分別於 2026 年 9 月 29 日與 10 月 1 日發布，其中兩次僅相隔數小時，顯示維護者會在同一日內完成多輪更新。這種節奏與社群貢獻的批次合併相符，也意味著使用者在固定版本前應先確認該版本涵蓋的技能變更範圍。

Scientific Agent Skills 值得一試嗎？

若研究流程需要反覆使用特定科學套件或資料庫，且使用支援 Agent Skills 標準的代理程式，它能降低設定與驗證成本；若只是偶爾查詢文獻，直接使用通用代理已足夠。

判斷的關鍵在於重複程度。這套技能的價值來自把領域慣例事先寫定，因此當同一類工作會反覆執行，例如定期處理定序資料、批次篩選候選分子或重複產出符合期刊格式的圖表，事前載入技能可明顯減少來回修正。反之，若代理的用途只是單次問答或閱讀文件，額外安裝技能帶來的效益有限。

領域邊界亦需一併評估。專案在臨床與法規相關技能中明確標示限制，例如臨床報告技能僅能依經驗證的來源清單產生草稿結構供合格人員審閱，不得用於診斷、個別風險評估、治療建議或用藥決定；法規相關技能產出的文件亦定位為送審前的準備材料，而非認證或方法放行結論。這些界線在文件中有清楚交代，使用前應先確認自身情境是否落在允許範圍內。

部署條件相對單純，需要 Python 3.13 以上的環境與 uv 套件管理器，作業系統支援 macOS、Linux 與 Windows WSL2。文件提醒每個科學工作流程應使用獨立環境，因為部分技能要求的 Python 版本或套件版本互不相容。技能檔案的安裝與其依賴安裝是兩件事，載入技能不等於已備妥相關套件。

出處連結有哪些？

本文資訊整理自 Scientific Agent Skills 的 GitHub 儲存庫、arXiv 論文與版本更新紀錄，完整技能目錄、安裝說明與安全報告可由下列來源查證。

官方儲存庫位於 https://github.com/K-Dense-AI/scientific-agent-skills，內含完整技能目錄、貢獻指南與安全報告。專案論文見 https://arxiv.org/abs/2609.00065，標題為 Scientific Agent Skills: A Library of Procedural Knowledge for Research Agents。版本更新紀錄見 https://github.com/K-Dense-AI/scientific-agent-skills/releases，配套的桌面版 AI 共同研究者專案位於 https://github.com/K-Dense-AI/k-dense-byok。Agent Skills 開放標準的說明見 https://agentskills.io/。

常見問題有哪些？

常見疑問集中在三處：技能與一般文件的分別、安裝後是否需要另裝套件，以及臨床相關技能的使用界線，以下逐項說明。

技能與一般說明文件有什麼分別？

差別在於格式與可驗證性。技能以固定結構的 SKILL.md 描述用途、流程與版本，並可附帶可執行輔助程式、參考文件與範本；帶有腳本的技能另有測試套件與依賴清單，讓內容能被自動化檢核。一般說明文件缺乏統一的檔頭欄位與驗證機制，代理較難判斷適用版本，也難以在流程中被一致地載入與更新。

安裝技能之後還需要安裝科學套件嗎？

需要。安裝技能檔案只是把說明與工具放入代理可讀取的位置，並不會同時安裝 RDKit、Scanpy 或 pydicom 等科學套件。每個技能會在其相容性欄位中記錄所需的套件、系統工具、憑證與網路條件，使用者應依該欄位準備環境。文件亦建議為不同的科學工作流程建立獨立環境，因為部分技能要求的 Python 版本或套件版本互相衝突。

臨床與法規相關技能可以直接用於實際決策嗎？

不可以。專案在多個技能中明示其定位為研究輔助工具。臨床報告相關技能僅能在來源事實清單完整且經驗證的前提下產生明顯標示的草稿結構，供合格人員審閱，不得用於診斷、個別風險評估、治療建議或用藥決定。法規相關技能產出的文件屬於送審前準備材料，不能視為認證、認可或方法放行結論。

總結：哪些團隊適合使用 Scientific Agent Skills？

適合會反覆執行特定科學工作流程、已使用支援 Agent Skills 標準之代理程式，並能自行準備套件環境的研究團隊；若需求僅為單次問答或文獻檢索，通用代理已足夠。

此專案的核心價值在於把科研領域的程序性知識，轉換為代理可以直接載入的結構化技能。177 個技能、80 個資料庫的檢索規範與 70 多個套件的版本基線，構成一套可稽核的知識庫，而不是一次性的提示範例集。追隨開放標準的選擇，也讓同一份內容能在多個代理宿主之間重複使用。

採用時需要先行確認三項條件。技能本身不包含科學套件，環境需另行準備，且不同流程建議分開建置；臨床與法規相關技能有明確的使用界線，僅能作為研究輔助與送審前準備；安全風險由安裝者承擔，專案雖然提供每週掃描與公開報告，但文件仍要求使用者只安裝實際需要的技能並先閱讀內容。

就維護狀況而言，專案由 K-Dense 持續維護，約一年內累積約 760 次提交與超過 100 個版本，並有 arXiv 論文說明其設計。對於需要把 AI 代理導入既有研究流程的團隊，這套技能提供了一個可稽核的起點，但版本固定、環境隔離與領域界線的確認，仍是導入前必須完成的工作。
