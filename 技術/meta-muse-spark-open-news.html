Meta 開源 816B 模型：兩部 Mac 桌面直接跑代理

2026年10月17日 00:00 • 閱讀時間 2 分鐘 • Eric Chan • 來源：Meta AI Research

Meta 於 2026 年 10 月 15 日發布並開放 Muse Spark Open 的模型權重，官方稱其為美國歷來能力最強的同級開放權重模型。此模型具備 816B 總參數、42B 啟用參數與一百萬代幣上下文，原生支援多模態，並首次能在兩部 Apple M5 Ultra Mac Studio 上完整運行，主打編程與代理工作負載。

Muse Spark Open 是什麼？

它是一款原生多模態的開放權重模型，總參數 816B、啟用參數 42B，上下文長度達一百萬代幣，定位為編程與代理工作負載的主力模型，並可依需求自行微調。

此模型由 Meta 旗下的超級智慧團隊推出，並以開放權重形式釋出，官方形容為該公司至今最完整的開放成果。相較以往僅提供 API 存取的路線，這次直接把權重交給開發者，讓自建推論成為可行選項。

模型定位集中在長時間、多步驟的工作，例如大型重構、跨檔案修改與需要連續判斷的代理流程。官方在公告中強調長程任務、複雜軟體工程與多步推理三項能力，並以代理式流程作為主要測試場景。

值得注意的是，它與 Meta 自家的 Muse 系列代理產品共用代號，顯示模型並非單獨發布，而是整個代理產品線的底層引擎之一。

Muse Spark Open 的規格與架構有何特點？

模型採原生多模態設計，總參數 816B、啟用 42B，上下文可達一百萬代幣，並針對代理式與長期任務調整，同時保留以 PyTorch 自行微調的路徑。

參數規模是這次公告的核心數字。816B 總參數配合 42B 啟用參數，代表模型在單次推論中只會啟動其中一部分，這種稀疏結構正是讓巨型模型仍具備實用速度的關鍵。

一百萬代幣的上下文視窗，意味單次可讀入相當於數十份長篇文件的內容，適合需要整庫理解再作答的場景。原生多模態則令文字、圖像等輸入可以在同一個模型內處理，減少外部串接模型的複雜度。

官方亦提供優化後的推論核心。於 SGLang 內建的自動調校 Helion GPU 核心，在 NVIDIA 與 AMD 顯示卡上取得 1.03 至 3.95 倍的運算核心層加速，於 AMD MI350 的端到端測試則有約 3% 的提升。

為何它能在 Mac 桌面運行？

Apple M5 Ultra 的統一記憶體架構讓單機整合式 GPU 可用至 512GB 記憶體，頻寬達每秒 1.2TB，兩部 Mac Studio 合計即可容納整個模型。

桌面運行向來受限於記憶體容量，這次的突破口在硬件架構。每部 Mac Studio 的整合式 GPU 最多可取用 512GB 統一記憶體，兩部合計即接近一 TB，足以完整放下一組 816B 參數的模型。

頻寬同樣關鍵。每秒 1.2TB 的記憶體頻寬讓晶片能快速讀取每個代幣所需的小部分權重，官方形容兩部機器協同運作時，等同於一部具備一 TB 統一記憶體的電腦。

官方亦公布在裝置端運行的代理實測，包括以 Muse Code 驅動開源 Mastodon 客戶端 Ice Cubes，完成真實的 iOS 修改與建置，以及以代理方式操作 DaVinci Resolve，逐格檢視素材並自動裁切為直式畫面。

Muse Spark Open 有哪些使用途徑與生態支援？

權重可在 Hugging Face 及多家雲端模型目錄取得，推論則由 Baseten、Fireworks、Groq 與 OpenRouter 等七家服務商提供。

部署路徑分成自建與託管兩類。自建方面，模型支援 SGLang、vLLM、TensorRT-LLM、Hugging Face Transformers、Apple MLX、llama.cpp 與 Unsloth 等推論引擎，並針對 AMD、Apple、Intel 與 NVIDIA 晶片各自優化。

託管方面，官方的合作名單涵蓋七家推論服務商，讓不具備自建硬件的團隊也能以 API 方式呼叫。權重同時在四個雲端模型目錄上架，企業可直接沿用既有的雲端帳務與權限體系。

需要進一步客製的團隊，可透過 PyTorch 的 TorchTitan 進行調校；在 Apple 晶片上則以 MLX 直接從 Hugging Face 拉取權重運行。官方亦開放 Hugging Face 討論區，收集社群的使用案例。

它的授權條款與安全評估如何？

權重以 Muse Model License 釋出，附有限商業條款，多數開發者可免費使用；官方另表示模型已通過其超級智慧擴展框架所要求的安全門檻。

授權採用自訂的 Muse Model License，而非通用開源授權。條款允許許多開發者免費使用，但帶有商業限制，團隊在投入生產環境前，宜先逐條確認自身用途是否符合。

安全方面，開放權重被官方視為推廣個人超級智慧的其中一環。由於權重可被自由下載與微調，官方表示此版本已加入額外的安全後訓練，並依 Meta 的超級智慧擴展框架完成評估。

官方指出，模型在最嚴重風險類別的量測中具備防護能力，且達到框架所要求的發布門檻；詳細結果載於模型卡，完整評估報告將於稍後公布。

這次發布對開放權重模型競賽代表什麼？

它把前沿規模的權重與桌面本地運行直接掛鈎，令開放權重陣營首次在同級能力與消費級硬件之間建立連結，或改變企業比較自建與託管的成本基準。

過去一年，開放權重陣營的競爭多集中在基準分數與價格，硬件門檻則少有突破。這次把焦點放在「能否在自有設備上完整運行」，等於把競爭維度由分數延伸到取得成本與資料主權。

對企業而言，權重可自建意味資料無須離開自有環境，對合規要求較高的行業尤其具吸引力。然而自建需要相當的硬件投入，加上授權條款帶有商業限制，實際採用仍取決於成本與法務評估。

對 Meta 本身而言，開放權重一方面是搶占開發者生態的手段，另一方面也與其代理產品線互相拉動，讓模型能力透過社群使用回饋到產品迭代。

常見問題有哪些？

常見疑問集中在權重是否真正開放、能否在自行購買的硬件運行，以及商業使用是否受限。官方表示權重可下載，商用須依授權條款辦理。

Muse Spark Open 是開放權重模型嗎？ 是。權重已於 Hugging Face 等平台釋出，惟授權屬自訂條款，並非通用開源授權。

一般個人電腦可以運行嗎？ 難以完整運行。官方示範的配置為兩部 Apple M5 Ultra Mac Studio，屬高階硬件。

是否可以商用？ 需視用途而定，條款允許許多開發者免費使用，但附帶商業限制。

有沒有中文支援？ 模型為多模態設計，官方公告未逐項列出語言覆蓋範圍，實際表現有待社群測試。

總結：Muse Spark Open 適合什麼團隊？

適合重視資料留在本地、具備高階 Apple 晶片或自建 GPU 資源，且以代理與編程任務為主的團隊；資源有限的團隊宜先以 API 服務驗證效益。

這次發布的意義，在於把前沿規模的模型推向自有硬件，而非再一次堆高基準分數。對有能力投資硬件的團隊，它提供了一條資料不出門的推論路徑；對多數開發者，託管 API 仍是更現實的起點。

評估順序建議由任務開始：先確認代理與長程編程是否為主要需求，再比較自建與 API 的長期成本，最後才核對授權條款是否容許預定用途。在完整評估報告與第三方實測出爐之前，小規模試用是較穩健的做法。
