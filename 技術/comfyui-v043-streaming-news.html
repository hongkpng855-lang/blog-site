ComfyUI v0.43：4GB 顯存跑最大開源模型

2026年11月02日 04:00 • 閱讀時間 2 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/Comfy-Org/ComfyUI

ComfyUI 於二零二六年十月二十七日發布 v0.43.0，這個累積 144,376 顆星標的節點式擴散模型引擎，以非同步權重串流把最大開源模型的門檻壓到 4GB 顯示記憶體加 8GB 系統記憶體，本次更新補上 MOSS-Image 完整支援、FLUX 3 Max 與 Kling 4.0 合作節點。

ComfyUI 是什麼？

ComfyUI 是以節點圖形式運作的擴散模型推論引擎，以 Python 與 PyTorch 撰寫，可離線在本機產生圖像、影片、音訊與三維內容。

依照專案自述，ComfyUI 定位為內容創作的 AI 引擎，服務對象是需要控制每一個模型、每一個參數與每一份輸出的視覺專業工作者。它本身不是模型，而是模型之上的執行層，把檢查點載入、條件控制、採樣、解碼與輸出串成可視化流程，讓同一套流程能重複執行與版本化。

專案建立於二零二三年一月十七日，主要語言為 Python，採用 GPL-3.0 授權，累積 842 位訂閱者與超過三萬四千位貢獻者。早期由個人開發者主導，現由 Comfy-Org 組織維護，並拆分成核心、桌面版與前端三個互相關聯的儲存庫。

v0.43 版本加入了哪些新功能？

本次更新加入 MOSS-Image 完整支援、FLUX 3 Max 與 Kling 4.0 合作節點、分支節點、鏡像填充節點，以及 Qwen 3.x 的自適應樹多詞元預測加速。

模型支援是這個版本的主軸。MOSS-Image 由局部支援升級為完整支援，加入長寬比縮放、色深控制、編輯用低秩適配器載入與專用合併節點，同時降低峰值記憶體佔用。影片與圖像側則補上 FLUX 3 系列的兩千與四千解析度選項、Krea 3 的延伸思考模式、Kling 4.0、PixVerse V6-Max、Meshy T2.5 拓撲節點與 Ideogram 的向量輸出節點。

節點層面出現兩項結構性補充。分支節點讓同一張流程圖可以按條件走向不同後段，減少為了單一分支而複製整張圖的情況；鏡像填充則處理需要邊緣延續的圖像擴展場景。色彩管理同時加入 ACEScg 轉換，讓輸出可以直接進入影視後期流程。

效能部分集中在推論排程。Qwen 3.x 的自適應樹多詞元預測完成第三階段優化，動態顯示記憶體鍵值快取進入第一階段實作，AMD 顯示卡的注意力運算亦改為啟用 PyTorch 原生路徑。

為何 4GB 顯存可以執行大型模型？

關鍵在於非同步權重串流與分層卸載，模型權重留在系統記憶體或磁碟，按執行順序分批送入顯示記憶體，峰值佔用因此大幅下降。

擴散模型的記憶體壓力來自兩處。一是權重本身，參數量以十億計的模型即使以半精度儲存，也遠超消費級顯示卡的容量；二是中間激活值，在解析度提高時呈平方增長。傳統做法要求兩者同時放進顯示記憶體，於是形成硬性門檻。

ComfyUI 的處理方式是把權重視為可串流的資料。專案說明採用非同步權重串流後，最大的開源模型可以在 4GB 顯示記憶體搭配 8GB 系統記憶體上相對快速地執行，並且仍能飽和顯示卡的運算能力。代價落在頻寬上，每次前向傳播都要從系統記憶體搬運權重，實際速度取決於記憶體通道與模型大小。

版本節奏亦反映這種工程取向。專案維持每週一次的發布週期，主穩定版大約每兩週推進一次，修補版則回填到當前穩定分支。

合作節點模式代表什麼商業方向？

合作節點把關閉來源的商業模型接進同一張節點圖，使用者以帳號與點數付費，開源核心仍保留本地執行與完全離線能力。

合作節點是這個專案最值得注意的商業嘗試。它讓 Nano Banana、Seedance、Hunyuan3D 一類未公開權重的模型，以節點形式出現在同一張流程圖中，使用者付費後即可呼叫，無需自行部署。

授權安排把兩條路線分開。核心程式以 GPL-3.0 發布，保持可修改與可自架；商業模型則透過官方帳號與點數計價，收入回流到專案與模型供應方。專案同時提供 --offline 參數，強制停用所有合作節點與付費介面，讓合規要求嚴格的環境仍可完全離線運行。

這種設計的意義在於，開源工具不必靠限制功能來變現，而是把外部模型當成可插拔的資源。對使用者而言，同一套工作流可以先用本地開源模型驗證，再切換到商業模型輸出最終版本。

ComfyUI 與其他擴散模型工具的分別在哪裡？

差異在於節點圖的可組合性與推論排程的精細度，工作流以 JSON 儲存、可版本化與重用，而非固定表單式的參數面板。

表單式介面把可用參數固定下來，使用者只能調整作者預留的欄位。節點圖則把執行順序本身變成資料，使用者可以插入條件判斷、批次處理、遮罩合成與自訂節點，把多個模型串成單一流程。

這種彈性的代價是學習曲線。專案以 App Mode 與工作流範本降低門檻，把複雜流程包裝成簡單表單對外呈現，同時保留返回節點圖的入口。對需要量產的團隊，真正價值在於流程可以存成 JSON 納入版本控制，配合本機 API 直接接入既有生產線。

如何安裝並開始使用 ComfyUI 0.43？

最簡路徑是下載桌面應用程式；需要完整控制則以可攜版或手動安裝，並依顯示卡類型選擇對應的 PyTorch 版本。

桌面應用程式支援 Windows 與 macOS，安裝後即可載入官方工作流範本。手動安裝覆蓋所有作業系統與顯示卡類型，包括 NVIDIA、AMD、Intel、Apple Silicon 與 Ascend NPU，步驟是先建立虛擬環境，再依硬體安裝對應的 PyTorch，最後啟動主程式。

python -m venv comfyenv
source comfyenv/bin/activate
pip install torch torchvision torchaudio
git clone https://github.com/Comfy-Org/ComfyUI
cd ComfyUI && pip install -r requirements.txt
python main.py

啟動後瀏覽器開啟本機位址即可進入節點畫布。模型檔案放入對應的檢查點目錄，若模型分散在多個磁碟，可透過 extra_model_paths.yaml 指定額外路徑，避免重複搬移大型檔案。

ComfyUI 的專案數據與發布節奏如何？

截至二零二六年十一月，專案累積 144,376 顆星標、17,173 次分叉、842 位訂閱者，最新版本 v0.43.0 於十月二十七日發布。

版本密度相當高。九月二十一日發布 v0.37.0，九月二十九日 v0.38.0，十月五日 v0.39.0，十月十三日 v0.40.0，十月十五日 v0.41.0，十月十八日 v0.42.0，十月十九日 v0.42.1，十月二十七日 v0.43.0，六週內推出八個版本。

待處理議題數目維持在五千以上，與每週合併大量外部貢獻的模式相符。對自架使用者而言，這個數字同時提醒升級前應先備份工作流與檢查自訂節點的相容性，因為非穩定標籤的提交可能破壞第三方節點。

出處連結有哪些？

原始碼與版本說明位於 GitHub 的 Comfy-Org/ComfyUI 儲存庫，官方網站提供下載、工作流庫與線上文件。

專案的原始碼、版本說明與問題追蹤集中於 GitHub 儲存庫，每一版都附有完整的合併請求清單與新貢獻者名單。官方網站提供桌面版下載、雲端方案與工作流範本庫，文件站點則整理安裝、節點說明與合作節點的計價方式。

出處：https://github.com/Comfy-Org/ComfyUI

總結：ComfyUI 適合什麼使用者？

適合需要精細控制流程、願意投入時間學習節點邏輯的視覺創作者與量產團隊；追求開箱即用的一般使用者，桌面版是較輕鬆的起點。

ComfyUI 的價值在於把推論流程從黑盒變成可檢視、可修改、可版本化的結構。v0.43.0 的意義則在於兩條路線同時推進，一邊用串流技術壓低硬體門檻，一邊用合作節點接入關閉來源的商業模型。

對已有明確產出流程、需要批次生成與可重現結果的團隊，這個專案目前仍是開源選項中最完整的一套。對只想快速產圖的個人使用者，先從桌面版與官方範本開始，再決定是否投入節點圖的學習成本，會是較務實的路徑。
