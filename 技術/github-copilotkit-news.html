37,741 星開源項目：CopilotKit 的生成式 UI 平台

Eric Chan

IT 顧問・實測主義者

2026年10月05日 10:00 • 閱讀時間 3 分鐘

來源：GitHub

內容創作者： https://github.com/CopilotKit/CopilotKit

CopilotKit 是一套以 TypeScript 撰寫的開源代理應用框架，截至二零二六年十月在 GitHub 累積 37,741 顆星標與 4,693 次複製，採用 MIT 授權，最新正式版本為 v1.77.0，於二零二六年十月二日發布。它將自身定位為「代理與使用者之間的橫向層」，讓同一套代理後端能同時驅動網頁、行動應用與 Slack、Microsoft Teams 等通訊渠道。該專案同時是 AG-UI 協議的主要發起者，該協議已被 Google、LangChain、AWS、Microsoft 等廠商採用，使其從單純的前端元件庫，演進為代理應用領域的介面標準之一。

CopilotKit 是累積 37,741 顆星標的開源代理應用框架，以 TypeScript 撰寫、MIT 授權，提供生成式 UI，讓同一套代理可跨網頁與通訊渠道運作。

CopilotKit 是什麼？

CopilotKit 是一套用於建構代理原生應用的前端框架，提供聊天介面、生成式 UI、共享狀態與人機協作功能，並支援多種前端框架與通訊渠道。

根據專案自述，CopilotKit 是建構全端代理應用、生成式 UI 與聊天應用的軟體開發套件。它最初是一套 React 元件庫，如今已擴展為代理與使用者之間的橫向介面層，讓開發者不必為每個平台重寫應用，就能把既有的代理接入不同前端。

它的核心價值在於補上代理落地的最後一段路。模型與代理框架負責推理與工具調用，但使用者實際接觸的是按鈕、表單與對話框。CopilotKit 提供的正是這一層：一個能與代理雙向同步的介面層，讓代理可以讀寫畫面狀態、在需要時暫停等待使用者確認，並依情境動態渲染元件。

CopilotKit 的開發背景與 AG-UI 協議有何關聯？

專案於二零二三年六月建立，由 CopilotKit 團隊維護；團隊同時發起 AG-UI 協議，將代理與前端的通訊標準化，並獲 Google 與 Microsoft 等採用。

專案於二零二三年六月十九日建立，由 CopilotKit 團隊開發與維護，主要語言為 TypeScript，採用 MIT 授權。它並非單一產品，而是一組套件與協議的組合，涵蓋前端元件、後端執行環境與跨渠道轉接層。

關鍵的轉折在於 AG-UI 協議。這是一套定義代理與使用者介面之間通訊方式的開放協議，把訊息串流、工具調用、狀態同步與人機協作等互動，收斂成前後端都能理解的共同語言。由於協議獨立於特定代理框架，LangChain、CrewAI、Mastra 與 PydanticAI 等生態都能接入，這使 CopilotKit 的影響力超出單一專案的星標數字，成為整個代理工具鏈的接口之一。

CopilotKit 有哪些核心技術亮點？

核心亮點包括生成式 UI、代理與畫面的共享狀態、可暫停等待確認的人機協作流程，以及富執行緒與自動學習機制，讓代理能跨對話保存情境並持續改進。

第一項是生成式 UI。代理不再只能回傳文字，而是能依使用者意圖與自身狀態，在執行期間動態產生或更新畫面元件，例如把查詢結果直接渲染成表格、卡片或表單。開發者可選擇以協議驅動的靜態元件、宣告式描述，或結合 MCP 應用的開放式做法來實作。

第二項是共享狀態。框架提供一個代理與前端元件都能即時讀寫的同步狀態層，代理的推理結果可立即反映在畫面上，使用者在介面上的操作也能被代理感知，形成單一的互動迴圈，而非各自維護一份資料。

第三項是人機協作與富執行緒。代理可在執行過程中暫停，請求使用者輸入、確認或修改後再繼續；對話則可跨重新載入、跨裝置與跨工作階段保存，連同生成式 UI 一併還原。團隊另在其商業版加入自動學習機制，讓已完成的對話轉化為可審閱、可重用的技能，無須另建微調流程。

CopilotKit 的生成式 UI 如何運作？

生成式 UI 讓代理在執行期間依意圖與狀態動態產生介面元件，開發者可透過協議驅動、宣告式描述或 MCP 應用三種方式接入，畫面與代理狀態保持同步。

運作邏輯是把「代理想做什麼」與「使用者看到什麼」綁在同一條迴圈上。代理在推理過程中輸出的結構化指令，經由協議傳到前端，由前端對應的元件渲染出來；使用者與畫面互動後，狀態再回寫給代理，成為下一輪推理的輸入。

專案把生成式 UI 分成三種型態。靜態型以 AG-UI 協議描述代理可調用的介面元件；宣告式型以 A2UI 描述畫面結構，交由前端呈現；開放式型則結合 MCP 應用與開放 JSON，讓代理產生更自由的介面組合。三者的差異在於控制權與彈性之間的取捨，開發者可依產品需求選用。

CopilotKit 支援哪些框架與應用渠道？

前端支援 React、Next.js、Angular 與 Vue；渠道可接入 Slack、Microsoft Teams 與 Telegram 等，並持續擴充。

在前端層，React 與 Next.js 已達正式版本，Angular、Vue 與 React Native 亦在支援之列，開發者可沿用原有的元件與狀態管理方式，由框架處理與代理之間的連線。

在渠道層，專案推出 Channels SDK，讓同一套代理直接進駐使用者日常使用的通訊軟體。Slack 與 Microsoft Teams 被視為第一級整合，具備執行緒、工具調用與人機協作核准；Discord、WhatsApp 與 Telegram 則透過渠道轉接層支援，Google Chat、iMessage 與簡訊仍在規劃中。官方說法是代理邏輯維持不變，由 AG-UI 負責傳輸協議，CopilotKit 負責各框架與渠道的介面層。

截至二零二六年十月，專案累積 37,741 顆星標、4,693 次複製與逾二百六十位貢獻者，主要語言為 TypeScript，最新版本 v1.77.0 於十月二日發布。

  • 263+貢獻者
  • 17,995累積提交
  • TypeScript主要語言

這些數字反映的是一套高速迭代的框架。專案自二零二三年建立以來累積逾一萬七千九百次提交，貢獻者超過二百六十位，程式庫由多個套件組成，以單一儲存庫方式管理。官方核心套件的 npm 版本紀錄已超過一千一百個公開發布，平均每週皆有新版本推出。

CopilotKit 與同類方案相比有何差異？

與偏重後端編排的代理框架相比，CopilotKit 專注前端介面層與跨渠道整合，並以開放協議串接多種代理後端，而非綁定單一框架。

市面上多數代理框架的重心在後端，負責規劃、工具調用與記憶管理，前端多半需要自行搭建。CopilotKit 的差異在於把前端與渠道視為一等公民，直接提供聊天介面、生成式 UI 與狀態同步等元件，讓開發者省去從零實作互動層的工作。

另一項差異是協議中立。由於 AG-UI 獨立於特定代理框架，LangChain、CrewAI、Mastra 與 PydanticAI 等後端都能接入，開發者不必因為選用 CopilotKit 而更換既有的推理層。這種設計降低了替換成本，也是它能在不同生態間取得採用基礎的原因。

CopilotKit 的商業模式與生態影響為何？

核心框架以 MIT 授權免費開源，商業收入來自付費的 Intelligence 平台，提供富執行緒、使用者記憶、產品分析與自動學習，並支援自架部署。

專案採取開源核心加商業平台的模式。框架本身以 MIT 授權免費提供，可自由用於商業專案；團隊另推出 CopilotKit Intelligence，將跨裝置保存的富執行緒、使用者記憶、產品分析與自動學習納入付費層，並允許企業部署於自有的 Kubernetes 叢集或虛擬私有雲。

生態影響力則來自協議本身。AG-UI 已被多家廠商採用，涵蓋模型供應商、代理框架與雲端平台，使 CopilotKit 的定位從單純的元件庫，轉向代理與使用者之間的介面標準制定者。對於需要把代理推向實際使用者的團隊而言，這種標準化降低了跨平台整合的門檻。

如何快速開始使用 CopilotKit？

官方提供命令列工具，可在既有專案中安裝並引導整合，或以指令建立全新專案；亦可為編碼代理安裝專屬技能，協助產生功能與排查問題。

最直接的方式是透過官方命令列工具。在專案根目錄執行安裝指令後，工具會檢視專案結構並引導完成整合；若需要全新專案，則可使用建立指令在獨立目錄中產生範本，不會更動既有應用。

# 在既有專案中引導整合
npx --yes copilotkit@latest onboard start

# 建立全新專案
npx copilotkit@latest create

此外，官方亦提供代理技能，讓編碼代理能依 CopilotKit 的慣例產生功能與除錯。文件網站另附各框架的快速入門與範例，使用者可依 React、Angular、Vue 或 React Native 選擇對應指引。

為什麼 CopilotKit 的模式值得開發者關注？

它把代理落地的最後一哩路產品化，並以開放協議連結多種後端與渠道，使開發者能以較低成本把代理帶進使用者既有的工作介面。

代理技術的瓶頸正逐漸從模型能力轉向使用體驗。模型能完成任務，但若使用者必須離開日常工具才能使用，採用率便難以提升。CopilotKit 把這一段落差視為主要戰場，試圖讓代理直接住進網頁、行動應用與通訊軟體之中。

這種取向也回應了企業的實務需求。多數組織已在使用 Slack 或 Microsoft Teams，若能讓代理在既有渠道中完成工作，導入成本與教育成本都會下降。當介面層被標準化之後，代理的價值取決於後端能力，而前端不必重複造輪。

常見問題有哪些？

CopilotKit 的常見疑問集中在授權、後端綁定、渠道支援與商業收費四方面；核心框架免費開源、不綁定單一代理後端，付費部分為其雲端平台。

CopilotKit 是免費的嗎？

核心框架以 MIT 授權發布，可自由用於個人與商業專案；團隊另提供付費的 Intelligence 平台，加入富執行緒、使用者記憶與自動學習等功能。

使用 CopilotKit 是否必須更換現有代理後端？

不需要。它主導的 AG-UI 協議獨立於特定框架，LangChain、CrewAI、Mastra 與 PydanticAI 等後端皆可接入。

CopilotKit 支援哪些前端框架？

React 與 Next.js 已達正式版本，Angular、Vue 與 React Native 亦在支援之列，各框架另附對應的快速入門文件。

CopilotKit 可以接入哪些通訊渠道？

Slack 與 Microsoft Teams 為第一級整合，Discord、WhatsApp 與 Telegram 透過渠道轉接層支援，Google Chat 與 iMessage 仍在規劃。

什麼是生成式 UI？

指代理在執行期間依使用者意圖與自身狀態，動態產生或更新介面元件，而非只回傳純文字，讓互動結果直接呈現在畫面上。

總結：CopilotKit 適合什麼團隊？

CopilotKit 適合需要把代理快速帶進網頁、行動應用與通訊渠道的產品與企業團隊；若只需後端編排、不涉及前端整合，則未必是首選。

CopilotKit 的意義在於把代理與使用者之間的介面層產品化。專案擁有 37,741 顆星標、逾二百六十位貢獻者與逾一萬七千次提交，核心框架以 MIT 授權開放，並以 AG-UI 協議串接多種代理後端與前端框架。對於希望讓代理在既有產品與工作渠道中發揮作用、又不願為每個平台重寫應用的團隊，它提供了成熟且低門檻的起點；至於只需後端編排、不處理前端互動的情境，則可評估更專注於推理層的方案。
