last30days 開源：70,175 星的 AI 社群搜尋引擎

2026年11月19日 20:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/mvanhorn/last30days-skill

last30days 是一個開源的 AI 代理研究技能，以 70,175 顆星標成為 GitHub 當日熱門榜首。它把 Reddit 讚數、X 喜歡數、YouTube 逐字稿與 Polymarket 賠率並行檢索，再由代理模型彙整成一份附來源的簡報，補上搜尋引擎無法觸及的社群訊號。

專案於二零二六年一月二十三日建立，以 Python 撰寫，採用 MIT 授權，目前累積 6,254 個分支與二千二百餘位關注者。最新版本 v4.3.2 於十一月十七日發布，距離 v4.0 上線不足三週，版本節奏相當密集。本站在八月曾介紹其 v3 架構，當時的星標為五萬八千餘顆，三個月內增加約一萬二千顆。

last30days 是什麼？

一個開源的 AI 代理研究技能，把十餘個社群平台並行檢索，按讚數、喜歡數與賠率排序，再由代理模型彙整成一份附來源的簡報。

專案的自我定位寫得直接：以讚數、喜歡數與真實金錢計分的代理搜尋引擎。使用者輸入一個人物、公司、產品或技術名稱，代理會先解析出相關的社群帳號、GitHub 儲存庫、子版塊與頻道，再向各平台發出多輪查詢。

檢索結果經過互動量、相關性與新鮮度三項加權，同一個事件在不同平台的碎片會被合併成單一叢集。最終輸出一份簡報，每一段結論都標明來源與數字，而不是一串待讀的連結。

它同時支援五十多個代理宿主，包括 Claude Code、Codex、Cursor、Gemini CLI、Copilot、Windsurf 與 OpenClaw。安裝方式依宿主而異，但共用同一份引擎原始碼與命令介面。

它與 Google 或 ChatGPT 搜尋有何分別？

Google 彙整網頁與編輯內容，此工具直接抓取消費者的讚數與留言。它把各自封閉的平台併入同一輪檢索，再按真實互動量排序。

差別來自平台圍牆。Google 搜尋不觸及 Reddit 留言與 X 貼文，ChatGPT 與 Reddit 有授權協議但無法搜尋 X，Gemini 有 YouTube 卻沒有 Reddit。每個平台各有 API 與憑證體系，過去只能逐一登入翻查。

last30days 的做法是把使用者自備的憑證與瀏覽器工作階段接上同一條管道。代理因此可以同時取得 Reddit 的千讚討論、X 的即時爭論與 YouTube 的四十五分鐘逐字稿，並在同一個評分尺度下比較。

這個設計取向帶來明顯偏向。README 舉例說明，一篇一千五百讚的 Reddit 討論比一篇無人閱讀的部落格文章更具訊號價值，而具備六萬六千美元成交量的預測市場賠率，比評論員的猜測更難反駁。代價是熱門等於重要，冷門但關鍵的官方文件容易被壓下去。

資料來源如何評分與排序？

Reddit 讚數、X 喜歡數、YouTube 觀看、TikTok 互動與 Polymarket 賠率構成主要權重，配合相關性與新鮮度計分，跨平台碎片合併為單一事件。

評分不是把各平台的數字直接相加。引擎先按互動量對每個項目做平台內標準化，再乘上相關性與新鮮度加權，避免 TikTok 的百萬觀看直接壓過 Reddit 的千讚長文。時間窗口固定為三十日，超出範圍的舊資料不進入排序。

排序之後是合併。同一則消息在 Reddit 首次披露、在 X 引起爭論、在 TikTok 出現價格討論，會被歸為一個叢集並附上三處來源，而不是三條獨立結果。代理接下來的工作是判斷哪一項細節值得寫進簡報。

Hacker News 的分數與留言數是開發者社群的獨立訊號。README 引用「825 分、899 則留言」的例子說明，技術圈的共識往往在留言區成形，而標題本身只提供入口。這類結構化資訊比全文抓取更省 token，也更容易被引用。

v4 版本加入了哪些新信號？

美國專利檔案與企業招聘頁成為兩種新信號，只在內容與公司既定路線不符時標記。另加入引言行、賠率變動行與股價對照行。

專利信號在處理公司主題時自動啟用，毋須任何金鑰。引擎讀取該公司當月的美國專利申請，只在申請內容與公司已公布產品明顯不符，或描述尚未發布的功能時，才列為值得注意的訊號。

招聘頁信號讀取公司自家的職位頁面，涵蓋 Workday、Apple、Amazon、Google、Microsoft、Netflix 與 Oracle 等系統。新設立的團隊與職位描述往往先於產品公告出現，README 舉例指出 Apple 一個與交易流程相關的總監職位，讀起來像在為助理完成購物做品質驗證。

第三類新增內容是可引用行。Reddit、X、YouTube、TikTok 與 Instagram 的最佳留言會獨立成行放在對應事件之下，必要時附上翻譯，影片中的口頭評論亦在引用範圍。另有一行 Polymarket 賠率與變動幅度，以及一行上市公司三十日股價對照標普五百的表現。

如何安裝並開始使用？

Claude Code 以外掛市集安裝，其他代理宿主用 npx skills 全域安裝，OpenClaw 則以 clawhub 安裝官方技能包。首次執行後向導解鎖額外來源。

Claude Code 是作者建議的路徑，外掛快取具版本管理，發布新版本後會自動刷新。其餘宿主共用 Agent Skills 命令列工具，加上全域參數後安裝到使用者目錄，跨專案可用。

# Claude Code（建議）
/plugin marketplace add mvanhorn/last30days-skill
/plugin install last30days

# 其他宿主（Codex / Cursor / Copilot / Gemini CLI 等）
npx skills add mvanhorn/last30days-skill -g

呼叫方式是一個斜線命令加主題。輸入 /last30days 某個人物 後，代理會解析實體、展開多輪查詢、評分並彙整，最後把簡報寫入本機的存檔目錄。若只想確認會讀寫什麼而不啟動研究，可先執行預檢模式，它會列出設定來源、瀏覽器憑證計畫與預計寫入的檔案。

網頁版需要下載技能檔並在設定頁上傳，桌面版則以單鍵安裝的套件形式掛載為 MCP 伺服器，要求系統具備 Python 3.12 以上。Windows 平台的桌面套件仍在處理各平台入口清單，目前未提供。

免費可用到什麼程度？需要哪些金鑰？

Reddit、Hacker News、Polymarket 與 GitHub 毋須金鑰；arXiv、Techmeme 與 Yahoo Finance 由免費工具提供。

零設定的來源足以完成一份基本簡報。Reddit 含留言、Hacker News 分數、Polymarket 賠率、GitHub 提交與發布紀錄、StockTwits 情緒，以及公司主題下的專利與招聘頁，全部不收取費用。

X 的官方 API 只回溯約一週的貼文，除非開發者專案具備全檔案權限。因此 README 建議以瀏覽器工作階段補足三十日窗口，這個做法依賴使用者自行登入，憑證留在本機。

TikTok、Instagram 與 Threads 共用同一組 ScrapeCreators 憑證。小紅書需要本機已登入的服務在指定連接埠運行，並在每次執行時明確指定，不會自動啟用。

資料會離開本機嗎？

預設全部在本機執行，只有查詢各平台 API 時對外連線。若設定推理提供者金鑰，主題與檢索片段會送往該提供者做相關性重排。

專案宣告不做追蹤、不做分析，研究結果留在使用者電腦。資料離開本機的唯一預設路徑，是向各平台 API 發出查詢本身，這與任何抓取工具的性質相同。

重排是另一個可選出口。設定 OpenAI、xAI、OpenRouter、Google 或 Gemini 的推理金鑰後，主題與檢索片段會送往該提供者做相關性評分。若不設定任何推理金鑰，引擎退回本機計分模型，不會發出外部重排請求。

長期保存需要明確開啟。加上儲存旗標後，結果寫入存檔目錄內的 SQLite 資料庫，供跨次執行的趨勢監控與簡報累積使用，資料庫不會上傳。這項設計適合定期追蹤同一主題的團隊，但需要自行處理保留期與清理。

議題比例值得單獨看。二十三個未結議題對照七萬顆星標，比例遠低於同級專案，反映維護節奏跟得上回報量。提交歷史顯示一千五百餘次提交，主要來自維護者本人與自動化發布流程，另有約一百個具名貢獻者參與翻譯與來源整合。

成長曲線集中在十月下旬。使用者引用的社群貼文提到，當日 GitHub 熱門榜前十名有五個是 Claude 相關工具，而榜首正是此專案。這種熱度與代理宿主生態的擴張直接相關，宿主數量從少數幾個增至五十餘個。

last30days 適合哪些使用者？

需要在會議或銷售前掌握對象近三十日動態的業務與研究人員，以及追蹤工具聲量的內容工作者。只查官方文件的使用者收益有限。

README 列出的使用場景相當具體。會議前查一個人，得到的是本月加入哪個團隊、正在推進哪個專案、在哪些討論中被批評；銷售電話前查一間公司，得到的是近期招聘方向與可能的預算訊號。另有發現模式，用於找出正在上升但尚未到達頂點的主題。

限制同樣明確。窗口固定三十日，適合追蹤動態而非建立背景知識。排序以互動量為主，爭議性內容天然佔優，需要讀者自行校正。憑證數量決定覆蓋範圍，只裝零設定來源的簡報會偏向英文技術社群。

對已經在用瀏覽器代理或抓取框架的團隊，此專案可視為上游的選源與評分層。Crawl4AI 的抓取與反封鎖設計 處理單頁內容深度，Chrome DevTools MCP 的瀏覽器控制 處理互動式頁面，兩者與社群訊號檢索屬於不同層次。

出處連結有哪些？

原始碼位於 GitHub 的 mvanhorn/last30days-skill 儲存庫，另有多語言說明、設定文件與 JSON 輸出規格可查。

專案位址為 https://github.com/mvanhorn/last30days-skill，另有一份涵蓋各來源憑證矩陣與推理提供者優先序的設定文件，以及供代理與工作流使用的版本化 JSON 輸出規格。多語言說明包含繁簡中文、日文、法文、德文、西班牙文、葡萄牙文、阿拉伯文、波斯文與土耳其文。

本文數據取自儲存庫公開統計、v4.3.0 至 v4.3.2 發布說明與 README 內容，時間為二零二六年十一月十九日。來源數量、金鑰需求與免費額度以文件所列為準，實際可用性取決於各平台的現行政策與使用者憑證狀態。
