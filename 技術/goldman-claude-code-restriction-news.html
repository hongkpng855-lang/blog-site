高盛收回 Claude Code：交易員失去 AI 編碼權

2026年11月10日 00:00 • 閱讀時間 2 分鐘 • Eric Chan • 來源：State of AI

高盛於十月更新內部指引，把 Anthropic 的 Claude Code 與 Microsoft 的 GitHub 編碼代理限制給約一萬二千名工程師，交易員與投資銀行家原則上失去使用權。此變動源於生產力與風險審查，時間點落在 Anthropic 上市前數週，而高盛正是該次發行的主承銷商之一。

指引的判準並非職級，而是職能。策略分析師橫跨交易、量化研究與軟件工程，仍被列為可使用群組。其餘以業務為主的職位，改用銀行自家的 AI 助理，該助理整合多家廠商的模型，但不具備自行撰寫與執行程式碼的能力。

這項調整與七月的公開說法形成明顯落差。當時資訊總監形容非技術員工以對話方式建構工具是有效率的做法，並提到交易員與銀行家把初版工具交給工程團隊改良，令最接近問題的人不必等待排隊。三個月後，同一批工具被重新界定為需要治理的對象。

高盛這項限制的具體範圍是什麼？

限制針對能自行讀取檔案、撰寫並執行程式碼的第三方代理。Claude Code 與 GitHub 編碼代理只開放給工程師與策略分析師，其餘員工改用銀行自建助理。

受影響人數約三萬五千人。高盛全行約四萬七千名員工，工程師約一萬二千人，佔比約四分之一，其餘職能集中在交易、投資銀行、資產管理與支援部門。

限制方式是按角色分層，而非按地點或裝置。銀行內部平台仍然開放，員工可以查詢資料、撰寫文件、整理會議紀錄，差別在於能否讓代理直接產生可執行的程式。

消息由彭博引述兩名知情人士披露，高盛發言人回應時僅表示銀行會提供特定 AI 工具，以確認各部門最適用的場景，未直接評論限制的範圍。

為什麼交易桌上的編碼代理比工程團隊更高風險？

工程程式碼經審查、測試與部署控制才接觸重要系統，交易員自建的腳本往往直接進入日常使用。銀行另須維持部門資訊屏障，而代理產出的工具未必內建這些控制。

風險的核心是權限繼承。Claude Code 讀取檔案、撰寫程式與執行指令時，通常沿用使用者本人的存取權限。工程師的權限被限制在開發環境，交易員的權限則可能觸及客戶資金流向與部位資料。

第二層風險是生命週期。工程團隊的產出有版本控制、同儕審查與回滾機制，一個交易員為監控客戶資金流而寫的腳本，可能從第一天起就每日運行，卻從未經過任何一道關卡。系統一旦出錯，事後追查也缺乏紀錄。

第三層風險是可理解性。金融機構依法須在部門之間維持資訊屏障，例如負責併購的銀行家與可從中獲利的交易員之間。代理產出的工具並非按這些規則設計，工程師只有在工具被送過來時才有機會檢查。

高盛與 Anthropic 的關係有沒有因此改變？

沒有公開跡象顯示合作生變。Anthropic 工程師曾進駐高盛半年，協助建立後台交易會計與開戶代理。高盛同時是 Anthropic 上市的主承銷商之一。

雙方最深的合作在後台流程。今年早前，Anthropic 的工程人員在高盛駐場半年，協助把交易會計與客戶開立帳戶的部分流程改由代理處理。這些代理部署在營運部門，由工程團隊操作與維護，與前線員工自行拼裝的工具屬於不同層級。

資本市場的關係更為直接。高盛與摩根士丹利同為 Anthropic 上市案的主承銷商，該公司預計在納斯達克以 ANT 代碼掛牌。未來數週，高盛的銀行家將要向投資人推銷一家公司，而該公司的旗艦編碼工具，他們大多數人已無權使用。

這種並存並非矛盾。銀行的採購決策與使用決策分屬不同層級，前者看的是整體技術路線與關係維護，後者看的是單一工具在特定職位上的風險敞口。兩者可以同時成立。

其他金融機構的做法有何不同？

同業方向分歧。摩根大通六月把 Claude 從香港核准清單移除；巴克萊則計劃年底前讓半數開發者使用 Claude Code，三週後把開發職位列為五千人裁減。

摩根大通的調整屬於地區性子集。其香港辦公室把 Claude 從內部核准工具清單移除，原因與合約條款的解讀有關，ChatGPT 與 Gemini 在當地仍然可用。高盛在四月已對香港銀行家作出類似限制，兩者時間相近。

巴克萊走相反方向。該行十月表示預期年底前半數開發者會使用 Claude Code，三週後公布五千人裁減計劃，開發職位也在其中。同一項工具，在一家銀行是風險來源，在另一家則是效率來源，同時也是編制調整的工具。

差異的來源是使用位置。給工程師使用，工具進入既有審查流程；給業務人員使用，工具繞過流程。多數銀行最終選擇同一個答案，只是動作先後不同。

成本因素在這次決定中佔多少比重？

成本是次要但真實的壓力。代理按代幣計費，全員開放後支出容易失控。埃森哲改為每名員工每月補助二十九美元的 Claude 額度，把無限使用變成有限配額。

按用量計費的模式令授權範圍直接對應帳單。當工具開放給數萬名員工，實際消耗取決於個人習慣而非預算編列，財務部門難以在事前估算。

已有企業把額度當作治理手段。埃森哲改為每名員工每月固定補助，超出部分由部門自行吸收，把無限使用變成有限配額。這種做法同時解決成本與濫用兩個問題。

高盛的說法把生產力與風險並列，未公開兩者權重。從結果看，限制的界線劃在「能否自行執行程式碼」，而非「是否產生費用」，顯示治理邏輯優先於成本控制。

企業導入編碼代理時應注意什麼？

先分清使用位置。讓代理進入既有審查流程的職能可以放寬，繞過流程的職能須收緊。同時建立可執行紀錄，並為非技術使用者設定額度與檢查點。

第一項是權限對齊。代理繼承使用者的存取範圍，因此部署前應確認該職位原本能看到哪些資料，而不是假設工具會自行限縮。權限過寬的帳號，不適合直接接上可執行的代理。

第二項是紀錄。可執行的程式若無版本控制與執行日誌，事故發生後無法重建當時狀態。企業可要求代理產出必須落在受管理的儲存庫，即使產出者並非工程人員。

第三項是分階段。把工具先開放給已有審查流程的團隊，觀察三個月至半年，再評估是否延伸到其他職能。這種節奏比一次性全員開放更容易在事後調整。

常見問題有哪些？

以下四題涵蓋受影響職位、仍可使用的工具、策略分析師的例外原因，以及這項限制是否代表企業對編碼代理降溫，依公開報導整理。

哪些職位失去 Claude Code 使用權？

以交易與投資銀行業務為主的職位，包括交易員、投資銀行家與部分支援角色。策略分析師因為工作橫跨量化研究與軟件工程，被歸入可使用群組。實際名單由各部門依職能認定。

受影響員工仍可以使用哪些 AI 工具？

銀行自家的 AI 助理仍然全面開放，該助理整合多家廠商的模型，可用於查詢、摘要與文件撰寫。差別在於它不能自行撰寫並執行程式碼，也不具備代理式的多步操作能力。

策略分析師為何被排除在限制之外？

其工作本質接近工程職能。策略分析師橫跨交易、量化研究與軟件開發，產出的程式通常會進入既有的測試與部署流程，因此不構成繞過審查的風險。

這是否代表企業對編碼代理開始降溫？

不是降溫，而是分工。同一時期巴克萊擴大開發者的使用比例，顯示需求仍在。企業調整的是使用位置，把工具集中在已有治理流程的職能，而非全面撤回。

總結：這件事對企業 AI 採用意味什麼？

編碼代理的門檻不在能力，而在治理。當工具能自行執行程式碼，授權範圍就等同風險範圍。企業的實際做法是把使用位置對齊審查流程。

高盛的決定提供一個可觀察的樣本。同一套工具在三個月內由推廣對象變成管制對象，轉折點不是模型能力，而是使用位置離開審查流程之後，風險無法被量化。

對其他企業而言，可操作的結論是把「誰能用」與「產出如何被檢查」一起設計。只決定授權範圍而不設計事後檢查，等於把治理成本延後到事故發生時才支付。

工具能力的曲線仍在上升，治理的難度也會同步上升。願意在早期建立紀錄與流程的組織，後續擴張時會比同業更快，因為它們已經知道界線在哪裡。
