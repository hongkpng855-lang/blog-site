Cherry Studio 2.2.1：技能市集與遠端任務

2026年11月14日 00:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/CherryHQ/cherry-studio

Cherry Studio 於 2026 年 11 月 12 日發佈 v2.2.1，距 2.2.0 僅兩日。此版本把 2.2.0 建立的技能市集補上遠端任務查詢能力，新增 SerpKite 與 StepFun 兩個搜尋供應商，並修復代理與排程任務的多項缺陷。專案累積 53,485 顆星標，以 AGPL-3.0 釋出。

Cherry Studio 2.2.1 於 2026 年 11 月 12 日發佈，屬修補版本。主體功能仍來自 2.2.0 的技能市集，本版集中處理遠端任務查詢與缺陷修正。

Cherry Studio 2.2.1 是什麼？

Cherry Studio 是跨平台開源 AI 桌面工作站，支援 Windows、macOS 與 Linux，統一接入多間模型供應商，以 AGPL-3.0 釋出。

Cherry Studio 是一個跨平台的 AI 桌面工作站，2024 年 5 月 24 日建立於 GitHub。專案以 TypeScript 撰寫，採 GNU AGPL-3.0 授權，累積 53,485 顆星標、5,218 個分叉與 417 頁貢獻者名單。它的定位並非單純的聊天介面，而是把模型接入、代理執行、知識庫與排程任務放進同一個應用程式。

版本節奏值得留意。2.1.10 於 10 月 31 日發佈，2.2.0 於 11 月 10 日推出，2.2.1 於 11 月 12 日跟上，三個版本間隔不足兩週。這種密度說明 2.2 系列仍在穩定化階段，功能擴張與缺陷修補同時進行。

技能市集解決了什麼問題？

技能市集把技能目錄、外部來源、代理範本與 MCP 資源集中於單一介面，安裝附有引導，使用者不必再逐項進入設定頁面配置。

2.2.0 最受注目的改動是市集。它把原本分散在設定頁的技能、代理範本與 MCP 資源集中，並提供引導式安裝。對長期使用 MCP 的使用者而言，這件事的意義在於降低配置成本：過去每一台伺服器都要手動填寫指令與環境變數，如今可從目錄挑選後直接落地。

市集同時處理外部技能來源。專案允許把受管理的技能匯出至 ~/.agents/skills，供其他代理工具讀取。這個設計意味著 Cherry Studio 願意把技能視為可攜資產，而非綁定於單一應用程式的私有格式。專案的 GitHub topics 中列有 agent-skills 與 mcp-client，與此方向一致。

技能市集把散落的設定變成可挑選的目錄，但目錄本身不會判斷內容是否安全。近期對代理技能的實測顯示，掃描一批公開技能後有相當比例存在權限或腳本風險，因此在市集內一鍵安裝之前，仍值得先看清技能要求的存取範圍。若關注技能品質如何量測，把技能文件當作可訓練參數的做法提供了另一個切入角度。

遠端任務與通知中心帶來哪些改變？

遠端客戶端可發現排程任務的結果對話，並查詢任務排程、執行歷史與範圍受限的摘要。即使執行紀錄被清理，任務對話仍可被找到，補上行動端與桌面端之間的斷層。

2.2.0 為排程任務建立獨立側欄頁面，把任務對話、分頁的執行歷史與已完成或錯過任務的管理集中。2.2.1 進一步開放遠端查詢：外部客戶端能發現任務結果對話，並讀取排程、歷史與摘要。

通知中心是配套設計。側欄新增的通知抽屜把任務結果與官方公告集中，附未讀指示、回覆預覽與本地化公告。對同時跑多個長時間任務的使用者，這種集中入口比逐一翻查對話實用。

2.2.1 另外強化了代理的檔案與權限處理。系統與全域套件安裝改為在一般模式下請求批准、在完全存取模式下直接執行，而非一律封鎖。代理與助手可使用上傳圖片作為頭像，工作區與代理群組可釘選至頂部。子代理呼叫可同時指定供應商與模型，子任務列會顯示所請求的模型。

搜尋供應商與本地模型有什麼新選擇？

遠端客戶端可發現排程任務的結果對話，並查詢排程、執行歷史與範圍受限的摘要。即使執行紀錄被清理，任務對話仍可被找到。

搜尋層的擴充反映實際需求。使用者接入多間供應商後，搜尋品質與計費方式差異明顯，可替換的供應商清單因此成為關鍵。2.2.1 加入 SerpKite 與 StepFun，並讓 Exa 透過 Contents API 取得指定網址的內容，減少自行抓取網頁的工夫。

本地模型接入亦有進展。Rapid-MLX 以內建且免金鑰的形式加入，安裝後即可選用。既有路徑仍包括 Ollama 與 LM Studio，README 亦列出 Qwen、LongCat 2.5 與 Hunyuan 4 等模型的圖像輸入支援。對不想把資料送出本機的使用者，這條路線是主要選項。

執行期的選擇會直接影響速度與記憶體佔用。Ollama 在新版本把 Apple 平台全面轉向 MLX，是本地推理路線近期較明顯的變化。桌面客戶端與執行期分屬兩層，前者負責介面與任務編排，後者決定模型跑得多快。

2.2.1 修復了哪些代理與排程問題？

2.2.1 新增 SerpKite 與 StepFun 兩個搜尋供應商，Exa 可透過 Contents API 抓取網址內容。Rapid-MLX 成為免金鑰的本地供應商。

缺陷清單集中在代理執行時期。嵌套的 shell、檔案與產物工具結果在 Pi 與 Pi Durable 的 codemode 下重新顯示，包括重開對話後；未指定逾時的 Pi shell 指令不再無限期等待；關閉工作階段時先中斷 Claude 的工作，被中斷的回覆不再留下佔位文字。

排程任務的修正同樣具體。Cron 逾時在 Gemini 相容執行時期下可正常運作，刪除超過約三萬二千個工作階段的任務不再失敗，執行歷史載入時錨點導覽保持對齊。這些項目單獨看細碎，合起來卻決定長時間執行的可靠度。

Cherry Studio 的技術架構與生態定位如何？

2.2.1 修正嵌套工具結果顯示、Pi 指令無限期等待、關閉工作階段的中斷順序，以及 Cron 逾時對 Gemini 相容執行時期的支援。

架構上，Cherry Studio 以 TypeScript 撰寫，桌面端採 Electron 打包，同時提供 Windows、macOS 與 Linux 三平台安裝檔。代理層分為 Pi 與 Pi Durable 兩種執行時期，後者為新建代理的預設，原生保存工作階段並獨立串流背景子代理。

生態已超出單一應用程式。行動版另有獨立倉庫，企業版提供集中模型管理、共享知識庫與私有部署，社群亦維護多個主題倉庫。商業模式採雙軌：社群版依 AGPL-3.0 釋出，需要豁免條款者可另談商業授權。這種安排在開源專案中常見，但會影響企業採用的評估流程。

如何開始使用 Cherry Studio 2.2.1？

專案以 TypeScript 與 Electron 建構桌面應用，代理執行時期分為 Pi 與 Pi Durable。生態另含行動版、企業版與社群主題。

安裝路徑清楚。Windows 使用者可選 x64 或 arm64 的安裝版與可攜版，macOS 分 Apple silicon 與 Intel 兩種封裝，Linux 則有 AppImage、DEB 與 RPM 三種格式，並涵蓋 arm64。首次啟動後於供應商設定填入金鑰，或改用 Ollama、LM Studio 等本地路徑。

功能可用性取決於供應商、作業系統與設定。官方文件明言部分功能需要 API 憑證、已下載模型、額外依賴或系統權限。文件另提醒社群主題若為 v1 時期撰寫，需先適配 v2 介面方可使用。

出處連結有哪些？

可從官方網站或 GitHub Releases 下載安裝檔：Windows 有安裝版與可攜版，macOS 有 DMG，Linux 有 AppImage、DEB 與 RPM。

原始碼與版本紀錄位於 github.com/CherryHQ/cherry-studio，2.2.1 的完整變更清單可在該倉庫的 Releases 頁面查閱。使用說明與快速入門見官方文件站，行動版與企業版各自有獨立入口。

總結：Cherry Studio 適合什麼團隊？

主要出處為 GitHub 倉庫 CherryHQ/cherry-studio，版本紀錄見 Releases 頁，使用說明見官方文件站，企業版與商業授權另有獨立入口。

2.2 系列的方向明確：把技能、代理與排程收進同一個工作站，並讓這些資產可被外部工具讀取。53,485 顆星標與 417 頁貢獻者說明社群基礎穩固，但 2,701 個未結議題與兩日內連發兩版，也反映維護壓力真實存在。對正在評估桌面 AI 工作站的團隊，這個專案值得實測，惟應先確認授權條款與資料留存邊界。
