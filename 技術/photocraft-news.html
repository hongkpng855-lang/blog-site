PhotoCraft 開源：純 Rust 重寫的 Photoshop 替代方案

Eric Chan

IT 顧問・實測主義者

2026年10月11日 14:00 • 閱讀時間 3 分鐘

來源：GitHub

內容創作者： https://github.com/storytold/photocraft

PhotoCraft 是一套以純 Rust 從零重寫的開源圖像編輯器，在 GitHub 累積 42,085 顆星標與 6,315 次複製，由 ArtCraft 團隊開發並採 Apache-2.0 與 MIT 雙授權。專案於 2026 年 9 月 30 日建立，目標是重現 Photoshop 的分層編輯工作流，涵蓋圖層、遮色片、調整圖層、圖層樣式、文字、向量與原生 PSD 檔案處理。截至本文撰寫時，儲存庫仍在每日更新，最新提交時間為 2026 年 10 月 11 日。

PhotoCraft 是什麼？

PhotoCraft 是以純 Rust 重寫的開源圖像編輯器，重現 Photoshop 分層工作流，支援原生 PSD 讀寫。

專案的官方定位是「圖像編輯；以純 Rust 重建的 Adobe Photoshop 潔淨室實作」。潔淨室一詞在軟體工程中指僅依據公開規格與可觀察行為進行實作，不接觸專有原始碼、著色器或素材，這種做法讓專案在合規層面與原產品保持距離，同時避免直接複製受保護的實作細節。開發團隊在說明文件中強調，專案與 Adobe 並無隸屬或背書關係。

PhotoCraft 屬於 ArtCraft 團隊的 Crafting Apps 系列，同系列還包括向量繪圖、影片剪輯、相片庫與 RAW 顯影、PDF 處理、動態圖形與版面編輯等工具。這些工具共用相同技術前提：以 Rust 撰寫、在 macOS、Windows 與 Linux 提供原生版本、透過 WebAssembly 在瀏覽器執行，並且全部可被程式或 AI 代理驅動。

專案目前處於早期 Alpha 階段。開發團隊在 README 中以相當直接的方式說明現況：Photoshop 的功能介面多數已有對應實作，但距離可取代專業日常作業仍有落差，主要缺口集中在生成式 AI 功能、15 項尚未實作的工具、排版深度與外掛相容性。官方提供逐項對照文件，並在路線圖中列出後續方向。

PhotoCraft 具備哪些核心功能？

PhotoCraft 內建 55 項工具、16 種調整圖層、27 種 Photoshop 混合模式與完整筆刷引擎，並支援向量圖層、智慧型物件與即時濾鏡預覽。

工具列數量是 55 項，涵蓋選取、修補、繪製與變形等類別。選取工具從矩形、套索、魔術棒等傳統作法，延伸到快速選取、物件選取與主體選取，後者由本機模型執行，不需連線雲端或登入帳號；修補類包含污點修復筆刷、修補工具與內容感知移動；繪製類則提供筆刷、鉛筆、混合器筆刷、仿製印章與歷史記錄筆刷。

調整圖層共 16 種，包括支援逐通道編輯的曲線、具即時直方圖的色階、黑白、色版混合器、漸層對應、相片濾鏡與選色，另可讀取 .cube、.3dl 與 .look 等色彩查閱表。這些調整以非破壞方式疊加，可套用遮色片、調整順序或暫時關閉，原始像素不會被改寫；圖層樣式則涵蓋陰影、內陰影、內外光暈、斜角浮雕、緞面、筆畫與顏色、漸層、圖樣覆蓋，並可套用於文字圖層。

文件模型支援 RGB、灰階、CMYK 與 Lab，位元深度涵蓋每通道 8、16 與 32 位元，色彩管理以純 Rust 實作 ICC 描述檔，支援指定與轉換描述檔、四種渲染意圖、黑點補償與軟式打樣。格式方面除 PSD 與 PSB 外，另支援分層 TIFF、Paint.NET PDN3 讀取、OpenRaster 讀寫、SVG 匯入為向量圖層，以及 PNG、JPEG、WebP、GIF、OpenEXR、Radiance HDR 與原生 .pcraft 等平面格式。

PhotoCraft 的 PSD 相容性與架構有何特點？

PSD 支援為獨立 Rust 模組，依 Adobe 公開規格實作；官方語料 309 個檔案中 307 個重新儲存後渲染一致，無法解析的區塊會原樣保留。

PSD 處理是專案的技術重點。這部分被拆成獨立模組，依 Adobe 公開規格撰寫，並以真實檔案語料進行驗證；開發團隊指出，開啟後重新儲存的檔案在 309 個官方測試檔案中有 307 個渲染結果一致，在另一組混合語料中則為 170 個檔案中的 169 個。未建模的原始區塊、描述子與附加資料不會被丟棄，而是原樣帶到新檔案中，避免往返過程造成資訊損失。

架構採引擎優先的分層設計。核心是一套純資料的文件模型加上指令引擎，圖形介面僅是薄層，專案透過建置期檢查強制 24 個模組之間的分層關係。合成器有兩套，一套 CPU 版本作為參考標準，另一套以 wgpu 將畫布送上 GPU，兩者互相對照測試，後端涵蓋 Metal、Vulkan、DX12 與 WebGPU。

效能設計圍繞區塊與寫入時複製。畫布以 256 平方像素的稀疏區塊管理，讓復原操作成本低廉、大型畫布佔用較少記憶體，效果圖則依圖層狀態快取。濾鏡實作亦有針對性優化，例如大半径模糊以跨核心的執行總和箱型處理，官方量測顯示 360 萬像素影像上半径 180 的高斯模糊可在一秒內完成。整份引擎與介面均可編譯為 WebAssembly，直接在瀏覽器執行。

PhotoCraft 如何讓 AI 代理直接操作圖像編輯？

專案把選單、工具與對話框統一註冊為 500 多個指令，介面、命令列、JSON 控制通道與 MCP 伺服器共用同一套指令，代理可執行相同操作。

代理驅動能力來自指令註冊表的設計。專案把每一個選單項目、工具與對話框都對應到單一指令，總數超過 500 個，圖形介面、命令列工具、JSON 控制通道與 MCP 伺服器都呼叫同一份註冊表。這種安排意味著使用者在介面上能完成的動作，理論上腳本或 AI 代理也能完成，而不需要額外維護一套自動化介面。

實務使用上，命令列工具支援單次執行與批次處理。使用者可載入 PSD 檔案、依序套用智慧型銳化與曲線調整圖層、再輸出為 PNG，也能把同一份動作清單套用到整個資料夾的影像；代理則可透過 MCP 連線操作，桌面版本另提供僅限本機回環、需驗證的控制通道，用於檢視介面狀態、以指標事件驅動工具，以及產生離屏截圖。專案的 README 圖片即是以此通道渲染產出。

這項設計的意義在於把圖像編輯納入自動化流程。傳統影像處理腳本受限於函式庫提供的能力，難以操作圖層樣式或遮色片等編輯器專屬概念，而指令化引擎把這些操作暴露為結構化參數，讓批次修圖、範本套用與代理工作流得以共用同一條執行路徑。

PhotoCraft 與 Adobe Photoshop 有何差異？

PhotoCraft 以免費開源、原生執行與可程式化控制為訴求，Photoshop 則在生成式 AI、外掛生態與排版深度上仍具優勢，官方亦承認尚未能完全取代。

定位差異首先反映在授權與成本結構。PhotoCraft 採 Apache-2.0 與 MIT 雙授權，可自由使用、修改與再散布，也能整合進商業產品；Photoshop 屬訂閱制商業軟體。對於需要把編輯能力嵌入內部系統或產品流程的團隊，前者的授權條件明顯寬鬆。

功能取捨則呈現不對稱。PhotoCraft 在檔案格式廣度、指令化控制與跨平台原生執行上具備特色，但在生成式填充、專業排版深度與外掛相容性上仍有明顯缺口；開發團隊在狀態說明中明言，目前尚不適合作為專業日常作業的完整替代品，並以逐項對照文件呈現各面向的完成度，而非僅以選單項目是否接線來衡量。

生態位置的差異同樣關鍵。Photoshop 的護城河除了功能本身，還包括多年累積的外掛與教學資源；PhotoCraft 目前以一組共用技術前提的應用家族形式推進，價值更接近為需要自動化與自主部署的場景提供另一條路徑，而非正面取代既有商業產品。專案採用公開規格實作，也讓後續維護與擴充不必依賴原廠授權。

如何快速開始使用 PhotoCraft？

可由官方網站下載安裝檔，或從原始碼以 cargo 建置；支援 Windows、macOS、Linux、FreeBSD 與瀏覽器版本。

取得途徑分為三類。最直接的方式是從官方網站下載對應平台的安裝檔；也可在 GitHub 發布頁面選取特定版本，Windows 提供安裝檔與免安裝壓縮檔，macOS 提供已簽章與公證的通用版本，Linux 涵蓋 AppImage、Flatpak、Debian、RPM 與壓縮檔，FreeBSD 則提供 x86_64 版本。

自行編譯則以 Rust 工具鏈執行。以下指令可取得原始碼、啟動桌面版本並執行測試套件：

git clone https://github.com/storytold/photocraft
cd photocraft
cargo run --release -p photocraft -- image.psd   # 桌面版本
cargo test --workspace                           # 測試套件

實際使用前有幾項條件值得留意。專案處於早期 Alpha，介面變動與粗糙邊緣屬預期範圍；Wayland 環境下的檔案拖放尚未支援，需改用選單開啟或貼上，或改以 XWayland 執行。若需要完整中日韓字型，可另建置官方提供的字型輸入專案，或依賴系統既有字型。遇到問題時，官方建議在回報中附上作業系統、文件尺寸、圖層數量與截圖。

授權條款屬寬鬆類型。專案採 Apache-2.0 與 MIT 雙授權，使用者可擇一遵循，兩種授權都允許商業使用、修改與再散布，其中 Apache-2.0 另含專利授權條款。需注意的是，ArtCraft 的名稱、字標與標誌不在授權範圍內，僅可在不修改的前提下、作為本專案與 PhotoCraft 的一部分使用，衍生版本必須移除這些商標素材。內附字型、圖示與影像素材各自維持原有開放授權，並在署名文件中逐項列出作者、來源與授權。

專案活躍度反映在開發節奏上。儲存庫建立於 2026 年 9 月 30 日，截至目前累積 859 個未結議題，最新推送時間為 2026 年 10 月 11 日。測試規模超過 1,700 項，涵蓋 PSD 往返、合成器對照、多深度檢查與合成資料產生；官方另提供獨立語料儲存庫，以雜湊值固定版本後供測試取用，付費與企業使用者可據此評估專案的驗證嚴謹度。

總結：PhotoCraft 適合什麼團隊？

PhotoCraft 適合需要檔案掌控、批次自動化與可嵌入編輯能力的技術團隊；若高度依賴生成式 AI 與外掛，宜搭配 Photoshop。

PhotoCraft 的價值在於把圖像編輯重新拉回可檢查、可程式化的層次。以純 Rust 重寫、24 個模組分層、雙合成器互測與 1,700 多項測試，構成一套可驗證的工程基礎；原生 PSD 讀寫與 500 多個指令註冊在同一套引擎，則讓檔案掌控與自動化不再互斥。這些特性回應的正是長年被訂閱制與封閉格式所限制的使用情境。

採用前仍須衡量現實條件。專案處於早期 Alpha，生成式功能、外掛相容性與排版深度尚待補齊，不適合直接承擔專業產線的關鍵流程；在 Wayland 環境、中日韓字型與部分格式支援上也有已知限制，需要先行驗證。適合與否，取決於團隊在自主部署、授權成本與功能完整度之間的取捨——若核心需求是掌控檔案與流程，這套引擎已提供可行的起點；若核心需求是最完整的專業功能集，商業方案仍是更穩妥的選擇。
