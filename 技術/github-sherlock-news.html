93,217 星開源項目：Sherlock 以用戶名追蹤社交帳號

Eric Chan

IT 顧問・實測主義者

2026年10月05日 02:00 • 閱讀時間 3 分鐘

來源：GitHub

內容創作者： https://github.com/sherlock-project/sherlock

Sherlock 是一套以 Python 撰寫的開源用戶名追蹤工具，截至二零二六年十月在 GitHub 累積 93,217 顆星標與 11,009 次複製，採用 MIT 授權，最新正式版本為 v0.16.2，於二零二六年九月八日發布。該專案自二零一八年十二月建立後持續維護至今，目前收錄四百八十二個社交平台網站，使用者只需在命令列輸入一個用戶名，便會逐一查詢各平台是否存在對應帳號。在開源情報工具領域，它是星標數最高、使用基數最廣的用戶名查詢方案之一。

Sherlock 是累積 93,217 顆星標的開源用戶名追蹤工具，以 Python 撰寫、MIT 授權，可在命令列一次查詢四百多個社交平台是否存在對應帳號。

Sherlock 是什麼？

Sherlock 是一套命令列工具，輸入單一用戶名即可查詢數百個社交平台是否存在對應帳號，並將結果輸出為文字、CSV 或 Excel 檔。

Sherlock 的官方定位，是讓使用者在一個指令內完成跨平台的用戶名核對。它的輸入是人們早已熟悉的使用者代號，輸出則是一份列出各平台帳號狀態的清單，必要時還可加上瀏覽器直接開啟結果頁面的選項。

這類需求過去多半以手動方式處理，使用者逐一開啟社群網站、貼上用戶名、判斷帳號是否屬於同一人，過程繁瑣且容易遺漏。Sherlock 把重複的查詢動作收斂成單一命令，將結果集中輸出，因而成為數位足跡盤點、品牌帳號清查與資安演練中最常被引用的開源工具。它的價值不在於破解任何私密資料，而在於把公開頁面的比對工作自動化。

Sherlock 的開發背景與社群規模如何？

Sherlock 於二零一八年十二月建立，由 Siddharth Dushantha 發起，現由 sherlock-project 組織維護，累積逾二百七十位貢獻者。

專案最早的版本發布於二零一八年十二月，由開發者 Siddharth Dushantha 以 Python 實作，起初只是一支用來解決個人痛點的小型腳本。隨著使用者增加，專案成立獨立的 sherlock-project 組織負責維護，並將網站定義抽離程式碼、集中管理，讓社群能自行提交新平台。

經過近八年迭代，Sherlock 已成為同類工具中社群規模最大的專案之一。官方提供 pipx、pip、Docker 與 dnf 等安裝方式，Debian、Ubuntu、Homebrew、Kali 與 BlackArch 另有社群維護的套件。專案文件涵蓋安裝、使用與貢獻指引，README 亦提供多語言版本，降低非英語使用者的進入門檻。

Sherlock 的核心技術特色有哪些？

核心特色包括以單一命令查詢多個平台、可擴充的網站資料檔、支援文字與 CSV 等多種輸出格式、可調整的代理與逾時設定，以及內建的 NSFW 站點排除清單。

第一項特色是以資料驅動的網站清單。Sherlock 不把每個平台的查詢邏輯寫死在程式碼中，而是集中描述於一份 JSON 資料檔，每筆記錄包含網站位址、用戶名的嵌入位置、判定帳號存在的正規表達式與回應狀態碼。當新平台出現或既有平台改版，維護者只需更新資料檔，不必更動核心程式，這也是專案能長期跟上平台變化的主因。

第二項特色是輸出格式的彈性。工具預設為每個用戶名寫入獨立文字檔，也可透過參數輸出為 CSV 或 XLSX 格式，方便後續以試算表整理。--json 選項更允許載入自訂或線上的網站清單，甚至支援以 Pull Request 編號直接載入已合併的新站點定義，讓查詢範圍能隨社群更新即時擴充。

第三項特色是可控制的查詢行為。使用者可指定單一或多個用戶名、限制只查特定網站、設定代理伺服器與逾時秒數，或選擇只輸出命中結果。工具亦內建 NSFW 站點的分類與排除清單，讓使用者在合規前提下自行決定查詢範圍。

Sherlock 如何安裝與執行？

安裝後在命令列輸入 sherlock 與用戶名即可執行，工具會查詢資料檔中的網站並輸出結果；使用者可用參數調整代理、逾時、指定站點與輸出格式。

安裝方式依作業環境而異。多數使用者可透過 pipx 或 pip 安裝 PyPI 上的 sherlock-project 套件，也能以一行 Docker 指令直接執行，Fedora 使用者則可經 dnf 安裝官方套件。專案提醒，ParrotOS 與 Ubuntu 24.04 的第三方套件目前處於損壞狀態，這些系統的使用者應改用 uv、pipx 或 Docker。

執行方式相當直接。在命令列輸入 sherlock 後接一個或多個用戶名，工具便會查詢資料檔中的所有網站，命中結果預設存入以用戶名命名的文字檔。若需要檢查相似用戶名，可在參數中以問號作為佔位符，讓工具自動替換底線、連字號與句點等常見變體。

# 以 pipx 安裝後查詢單一用戶名
pipx install sherlock-project
sherlock user123

# 以 Docker 執行並查詢多個用戶名
docker run -it --rm sherlock/sherlock user1 user2 user3

最新正式版本 v0.16.2 發布於二零二六年九月八日，與前一個版本 v0.16.0 相隔約一年，期間更新以網站資料檔維護與錯誤修正為主。儲存庫最近一次提交則在九月二十六日，內容為修正專案標誌的連結。

截至二零二六年十月，Sherlock 擁有 93,217 顆星標、11,009 次複製與逾二百七十位貢獻者，收錄四百八十二個網站，最新版本 v0.16.2 於九月發布。

上述數字反映的是一套成熟且仍在演進的工具。專案自二零一八年建立至今累積逾二千九百次提交，參與者超過二百七十位；儲存庫仍維持穩定更新，網站清單則隨社群提交持續增減，以因應平台改版與新服務上線。

Sherlock 與同類工具相比有何差異？

與 Maigret 等同類方案相比，Sherlock 的使用基數最大、安裝最簡單；取捨在於報告與視覺化能力較弱，覆蓋站點數也不及 Maigret。

Maigret 是 Sherlock 生態衍生的分支，同樣以用戶名查詢多平台，但將覆蓋範圍擴大到數千個網站，並能產生 PDF 與 HTML 報告、建立帳號關聯圖，適合需要完整調查紀錄的使用者。相對地，Maigret 的依賴較多、執行時間較長，對只想快速核對幾組用戶名的情境而言未必划算。

WhatsMyName 走的是另一條路，它以社群維護的 JSON 清單搭配網頁介面，使用者無須安裝即可在瀏覽器中查詢，彈性較低但門檻最低。Sherlock 則處在中間位置：安裝簡單、命令列操作直覺、結果輸出結構化，同時具備可自訂的清單與路徑，兼顧輕量與擴充性。

三者的選擇最終取決於用途。若目的是快速核對與批次輸出，Sherlock 的普及度與穩定性具優勢；若需要完整報告與更大覆蓋面，則可評估 Maigret；若只想在瀏覽器臨時查詢，WhatsMyName 更為輕便。

Sherlock 有哪些法律與倫理邊界？

Sherlock 僅查詢公開的帳號頁面，不進行登入或繞過驗證；使用者仍須遵守平台條款與當地法律，避免將查詢結果用於騷擾、跟蹤或未經同意的身分揭露。

工具本身只發送一般 HTTP 請求，檢查特定網站的用戶名頁面是否存在，不涉及漏洞利用、登入繞過或資料竊取，MIT 授權亦允許自由使用與修改。就技術面而言，它自動化的動作與使用者手動開啟網頁核對並無本質差別。

然而判定結果存在誤判空間。不同平台上的相同用戶名未必屬於同一人，工具回報的命中僅代表該頁面存在，不能直接推論身分關聯。將查詢結果用於跟蹤、騷擾、人肉搜索或未經同意的身分揭露，在多數地區可能觸犯跟蹤騷擾或個人資料保護法規。專案的 README 並未提供合規指引，使用者須自行判斷用途是否正當，並承擔相應責任。

常見問題有哪些？

Sherlock 的常見疑問集中在授權、支援站點數、判定準確度與合法性四方面；它為免費開源工具，查詢範圍與判定規則皆公開可查。

Sherlock 是免費的嗎？

是。專案以 MIT 授權發布，可自由用於個人與商業用途，包含修改與再散布，只需保留原始授權聲明。

Sherlock 支援多少個網站？

目前資料檔收錄四百八十二個網站，涵蓋主流社交、論壇、創作與約會平台，並隨社群提交持續增減。

Sherlock 的查詢結果準確嗎？

工具以回應狀態與頁面特徵判斷帳號是否存在，可能出現誤判；相同用戶名不代表同一人，結果需人工複核。

使用 Sherlock 是否合法？

工具僅查詢公開頁面，但使用方式受當地法律與平台條款約束，用於騷擾或身分揭露可能違法。

在 Windows 上可以執行嗎？

可以。透過 pipx、pip 或 Docker 皆可在 Windows 環境安裝使用，官方網站列出完整的安裝方式。

總結：Sherlock 適合什麼團隊？

Sherlock 適合需要以用戶名快速核對多平台帳號的資安研究、品牌保護與數位足跡盤點團隊；若需完整報告與更大覆蓋面，可再評估 Maigret 等衍生工具。

Sherlock 的價值在於把跨平台的用戶名核對，從逐一手動開啟網站的流程，收斂成一行命令與一份結構化清單。專案擁有 93,217 顆星標、逾二百七十位貢獻者與近八年的維護歷史，網站清單由社群持續更新，使它成為開源情報領域最普及的起點工具之一。對於需要盤點品牌帳號、演練身分暴露風險或核對公開足跡的團隊，它提供了成熟且易上手的方案；而任何使用情境之下，查詢結果的解讀與用途正當性，仍須由使用者自行負責。
