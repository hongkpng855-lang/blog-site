1.6 萬星 Google 開源：MCP Toolbox 打通資料庫

2026年10月26日 04:04 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/googleapis/mcp-toolbox

MCP Toolbox for Databases 是 Google 開源的模型上下文協定伺服器，把 AI 代理與企業資料庫直接接通。專案累積 16,721 顆星標與 1,779 個分支，採 Apache-2.0 授權，以 Go 開發。最新版 v1.15.0 於二零二六年十月二十三日發布，加入 MCP Apps 介面與對話式分析工具。

MCP Toolbox 是什麼？

MCP Toolbox 是 Google 開源的資料庫 MCP 伺服器，讓 AI 代理以自然語言查詢企業資料庫。它同時提供預配置工具集與自訂框架，內建連線池、認證與可觀測性。

專案在二零二四年六月建立，初名為 Gen AI Toolbox for Databases，倉庫路徑為 googleapis/genai-toolbox。命名在模型上下文協定普及後調整，官方在 README 明確說明改名原因：初版開發早於協定出現，改名是為了對齊相容性。

這項歷史細節值得留意。它說明此工具並非跟隨熱潮臨時拼湊，而是在協定成形之前就已處理資料庫連線、認證與工具描述的問題，只是後來找到了共通的介面語言。

目前的定位由兩部分組成。第一部分是立即可用的 MCP 伺服器，開發者在 IDE 或命令列就能列出資料表、執行 SQL、探索結構。第二部分是生產環境的工具框架，團隊以設定檔定義結構化查詢、語意搜尋與自然語言轉 SQL 的能力。

Google 為何在此刻主推資料庫 MCP？

資料庫是代理最需要存取、企業最不願開放的資產。Google 以開源中介層處理認證、連線池與稽核，把風險集中在一層可控的伺服器上，而非散落在每個代理。

企業導入代理時最常卡住的環節並非模型能力，而是資料邊界。直接把資料庫帳號交給代理意味著權限失控，把資料匯出成檔案則失去即時性。中介層的價值在於把兩者折衷。

官方把安全機制寫進設計：整合各雲端的身分驗證、限制存取範圍、以結構化查詢取代任意拼接的 SQL。這些做法在資料庫工具領域並不新穎，但套用在代理場景時，參數由模型產生的情況讓驗證變得更關鍵。

Google Cloud 同時提供受管的 MCP 伺服器，官方文件明確比較兩者差異。開源版本適合需要自建、需要跨雲、需要放進內部網路的團隊；受管版本則減少維運負擔。這種雙軌安排在雲端廠商中相當常見。

預配置工具與自訂工具框架有何分別？

預配置工具以一行參數啟動，即取得列出資料表與執行 SQL 等通用能力。自訂框架以 tools.yaml 定義來源、工具與工具組，把權限與查詢範圍寫死。

預配置路線的操作成本極低。在客戶端的 MCP 設定檔加入 npx 啟動指令與資料庫類型參數，即可取得該資料庫的標準工具集。官方支援以斜線指定子集，例如只載入 SQL 相關工具，避免一次暴露過多功能。

這條路線的對象是開發階段的探索。讓 IDE 直接讀取結構、產生與資料表相符的程式碼，省去來回切換視窗的動作。Google 亦把預配置工具上架到自家 Antigravity 的 MCP 商店，以點擊安裝的方式降低門檻。

自訂框架的對象則是上線後的服務。設定檔分為來源、工具、工具組、提示與資源五類區塊，每個工具要指定類型、來源、參數與查詢語句。這種宣告式寫法讓查詢內容可被審查，也讓權限邊界落在檔案而非模型輸出。

v1.15.0 更新了哪些重點？

v1.15.0 加入對話式分析代理的新增、修改與刪除工具，讓 Looker 以查詢編號執行已存查詢，並把 MCP Apps 支援回溯至多個協定版本。

版本於二零二六年十月二十三日發布，距上一版 v1.14.0 相隔十五日。這種節奏在專案歷史中屬常態，五十五個正式版本與近三十日五十三次提交說明維護密度穩定。

功能層面有三處值得注意。對話式分析模組補上資料代理的建立、更新與刪除工具，意味代理不只查詢資料，也能管理分析資產；Looker 支援以查詢編號執行已存查詢，把企業既有報表變成代理可呼叫的能力。伺服器端亦把 MCP Apps 介面支援回溯到多個協定版本，減少客戶端版本落差造成的相容問題。

修補項目同樣關鍵。授權模組補上簽發者聲明的驗證，檔案資源工具在讀取錯誤訊息中遮蔽伺服器路徑，工具介面移除各自實作的授權檢查以統一到單一入口。這三項都屬於縱深防禦的範疇，而非功能增強。

支援哪些資料庫與開發語言？

官方支援二十餘種資料庫，包括 BigQuery、Spanner、Firestore 與 PostgreSQL、MySQL、MongoDB 等主流系統。

覆蓋範圍是此專案最實際的賣點。多數資料庫廠商推出的 MCP 伺服器只服務自家產品，團隊若同時使用雲端資料倉儲與自架關聯式資料庫，就得維護多套連線設定。單一伺服器支援多來源，等於把設定集中到一份檔案。

客戶端適配同樣齊備。官方文件點名 Gemini CLI、Google Antigravity、Claude Code 與 Codex，並提供 Python、JavaScript 與 TypeScript、Go、Java 四套語言的 SDK。Python 版本再細分為核心、LangChain 與 LlamaIndex 三種封裝，Go 版本另附 LangChain Go 的整合範例。

載入工具所需的程式碼極短。以 Python 為例，建立客戶端後呼叫載入工具組的方法，即可取得可傳入應用程式的工具清單。這種設計讓框架整合的成本落在數行程式碼之內，也讓既有專案不必改寫架構。

可觀測性與技能封裝解決什麼問題？

伺服器內建 OpenTelemetry 追蹤與指標，可用單一參數匯出至任意相容後端。另有 skills-generate 指令，把工具組轉成代理技能套件。

代理呼叫工具的失敗往往難以重現。模型產生的參數、資料庫回應的錯誤、連線池的等待時間，三者分散在不同日誌中。以 OpenTelemetry 統一輸出，能把整條呼叫鏈串成單一追蹤。

這項能力對生產環境的意義大於開發環境。當代理在夜間批次任務中出錯，團隊需要的是可回溯的軌跡，而非重跑一次碰運氣。官方亦提醒可在匯出器上關閉自我追蹤，避免監控系統反覆觀察自身。

技能封裝則是較新的嘗試。指令可把既有工具組轉換為代理技能套件，並附帶名稱、工具組與描述參數，產出物符合公開的技能規格，可直接安裝到命令列代理。倉庫本身亦附上維護流程用的技能範例。

企業採用前需要評估什麼風險？

主要風險在權限設計與稽核能力。工具一旦暴露任意 SQL 執行，模型可讀取的範圍就等於帳號權限。團隊需要以結構化查詢限制語句，並保留查詢日誌與審批流程。

預配置工具提供執行任意 SQL 的能力，這在探索階段方便，在生產環境則過於寬鬆。官方文件把結構化查詢列為自訂框架的核心價值，正是針對此點。團隊若跳過這一步，等於把資料庫權限交給模型判斷。

第二項風險是版本迭代速度。十五日一版、五十五個正式版本的節奏，代表行為可能隨更新變動。設定檔格式、預配置工具的組成與 SDK 介面都屬公開 API 範圍，官方以語意化版本管理，但實際升級仍需回歸測試。

第三項是專案治理。倉庫現有四百零六個待處理議題，由 Google 團隊主導維護，貢獻者達一百六十八人。開源授權為 Apache-2.0，商業使用無授權障礙，但長期的路線圖仍取決於單一廠商的優先順序。

香港與亞洲團隊可以如何使用？

可先以 Docker 或單一二進位檔在內網部署，接上既有的 PostgreSQL 或 MySQL，再以工具組限制可查詢的資料表。這種做法避免資料外傳，也符合資料落地要求。

部署門檻不高。官方提供 Linux、macOS、Windows 各架構的二進位檔、容器映像與 Homebrew 套件，亦可從原始碼編譯。單一服務埠即可同時服務多個客戶端，適合放在內部網路的既有伺服器上。

對本地團隊而言，價值主要落在資料主權。金融、醫療與公營機構的資料庫無法上傳至外部服務，把中介層留在內網，代理與資料之間的流量就不必離開機房。這點比模型效能更常成為採購的決定因素。

需要注意的是模型本身仍可能位於境外。中介層解決的是資料庫連線與權限問題，不改變模型推論的位置。若法規要求整條鏈路留在本地，仍須搭配本地部署的模型，這一點在規劃時容易被忽略。

出處連結有哪些？

主要來源為 GitHub 倉庫 googleapis/mcp-toolbox，版本資訊取自 v1.15.0 發布說明，功能細節引用官方 README 與文件站。

倉庫網址為 https://github.com/googleapis/mcp-toolbox，README 載明雙用途定位、支援資料庫清單、安裝方式與 SDK 用法。版本說明列出 v1.15.0 的功能與修補項目，日期為二零二六年十月二十二日提交，於二十三日晚間發布。

官方文件站位於 https://mcp-toolbox.dev/，涵蓋來源設定、工具定義、預配置參考、部署指南與版本政策。Skill 產生與 MCP 技能服務的說明亦在該站，屬倉庫之外的補充資料。

總結：MCP Toolbox 適合什麼團隊？

適合已有多種資料庫、需要自建代理工具層的工程團隊。若只需單一雲端資料庫的臨時探索，受管服務更省事；若資料必須留在內網，開源版本是現階段少數完整選項。

此專案解決的是代理落地的中間層問題。模型能力已足夠產生查詢，缺的是可控的執行通道。把連線池、認證、權限與追蹤收進單一伺服器，能讓代理從示範走入生產。

限制同樣明確。它不提供模型，不負責資料治理政策，也不替代資料庫本身的權限系統。這些界線在文件中寫得清楚，採用者若不願自己補上，工具本身無法填補。

對正在評估代理架構的團隊，最實際的動作是先以預配置工具在測試環境接上一個資料庫，觀察模型產生的查詢品質，再決定是否投入自訂工具組的建置。這條路徑的成本低，資訊量卻足夠支撐後續決策。
