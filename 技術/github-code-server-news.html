code-server 4.140.0：瀏覽器內的 VS Code

2026年10月06日 20:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/coder/code-server

code-server 是 Coder 維護的開源專案，讓使用者在遠端伺服器上執行 VS Code，並透過瀏覽器存取同一套開發環境，在 GitHub 累積 79,551 顆星標與 6,881 次複製。專案於 2026 年 10 月 1 日發布 v4.140.0，內容跟隨上游 VS Code 1.140.0 的更新。自 2019 年問世以來，該專案已成為遠端開發與瀏覽器 IDE 領域的重要開源選項。

code-server 是可在瀏覽器運行的 VS Code 開源版本，安裝於遠端伺服器後以網頁存取，採 MIT 授權、以 TypeScript 撰寫，最低需求為 1 GB 記憶體。

code-server 是什麼？

code-server 讓使用者把 VS Code 安裝在遠端伺服器，再透過瀏覽器存取完整編輯器，包含終端機與擴充功能，適用於任何可連網的裝置。

依照官方說明，code-server 的核心用途是「在任何機器上執行 VS Code，並在瀏覽器中存取」。這意味著開發環境不再綁定於單一裝置，使用者可在平板、舊筆電或他人電腦上接續同一份專案，而所有編譯、測試與下載等高負載工作都在伺服器端完成。

專案列出的主要價值有三項：在任何裝置上維持一致的開發環境、利用雲端伺服器加速測試與編譯、以及在行動時節省電池續航。官方公布的最低需求相當親民，只要一台啟用 WebSocket 的 Linux 機器、1 GB 記憶體與 2 個 vCPU 即可運行，因此也能部署在小型虛擬主機或自架伺服器上。

在授權與技術組成方面，code-server 採用 MIT 授權，主要語言為 TypeScript，並以 VS Code 的開源核心為基礎。由於該核心與微軟市集、部分官方擴充功能分屬不同授權，專案在擴充生態上採用 Open-VSX 市集作為替代來源。

code-server 4.140.0 帶來哪些更新？

v4.140.0 於 2026 年 10 月 1 日發布，主要跟隨上游 VS Code 1.140.0；前一版 v4.139.1 修正了閒置逾時參數的驗證漏洞。

本次發布的 v4.140.0 內容精簡，變更項目為「Update to Code 1.140.0」，即把底層的 VS Code 核心升級至對應版本。這種跟版節奏是 code-server 的常態，專案必須持續吸收上游改動，才能讓瀏覽器版與桌面版在功能與行為上保持一致。

鄰近版本則包含較具體的修正。v4.139.1 修復了閒置逾時參數的驗證問題：過去以空白分隔方式傳入的 --idle-timeout-seconds 數值若為 60 或更小，會被默默接受而未生效，只有等號寫法才會正確驗證。v4.138.0 則修正連接埠代理在改寫 localhost 網址時，會遺失原始路徑、查詢參數與片段資訊的問題。

從發布紀錄觀察，專案維持密集而穩定的節奏，最新版本於 10 月 1 日推出，前一版在 9 月 26 日發布，再前一版為 9 月 19 日，大致以每週一版的速度跟進。官方提供的版本標籤同時標示 VS Code 對應版號，方便使用者判斷相容性。

code-server 的架構與運作原理是什麼？

code-server 以 Node.js 伺服器包裝 VS Code 開源核心，藉 WebSocket 串接瀏覽器前端，設定集中於 config.yaml，每個鍵對應一個旗標。

在運作層面，code-server 是一個在遠端主機執行的 Node.js 服務，它載入 VS Code 的開源核心，並透過 WebSocket 與瀏覽器端保持連線，因此伺服器必須允許 WebSocket 通訊。使用者在瀏覽器看到的介面、終端機與檔案總管，實際都由遠端主機執行。

設定管理集中於單一檔案。首次啟動時，程式會在 ~/.config/code-server/config.yaml 建立預設設定，內容包含綁定位址、驗證方式、密碼與 TLS 開關。設定檔中的每個鍵都直接對應一個命令列旗標，且命令列傳入的參數優先於設定檔；使用者也可透過 --config 旗標或環境變數改變設定檔位置。

擴充功能與網路存取是兩個常見的架構要點。由於微軟條款限制非官方 VS Code 存取其市集，code-server 改用 Open-VSX 擴充庫，並可透過環境變數指向自建市集。網路方面，code-server 只代理伺服器端請求，使用者可藉 HTTP_PROXY 等環境變數讓這些請求改走特定代理。

code-server 與其他遠端開發方案有何差異？

code-server 為自架的瀏覽器版 VS Code；Coder 為團隊開發平台，Theia 與 OpenVSCode-Server 屬其他分支。

官方常見問題中，把 code-server 與數個相近方案並列比較。與 Coder 的差異在於產品定位：code-server 是單一的瀏覽器編輯器服務，Coder 則是面向團隊的雲端開發環境平台，可集中管理多個工作區；專案由同一團隊維護，但服務對象不同。

在 VS Code 分支之間，Theia 與 OpenVSCode-Server 同樣提供瀏覽器版編輯器，差別在於實作基礎與整合程度；code-server 強調完整沿用 VS Code 開源核心並維持跟版。至於託管式服務，GitHub Codespaces 由 GitHub 代管環境並整合其平台，VS Code web（vscode.dev）則為微軟官方瀏覽器版本，兩者都不需要使用者自行架設伺服器。

由此可見，code-server 的定位落在「自架、可控、與上游同步」這一側。對於需要把程式碼與執行環境留在自有網路、或想在既有伺服器上直接開啟瀏覽器 IDE 的團隊，它提供的是不需導入完整平台的最小方案；反之，若追求開箱即用的託管體驗，代管服務更為直接。

如何安裝與開始使用 code-server？

官方提供安裝腳本，先以 dry-run 預覽再執行即可完成安裝；也可手動安裝或以 devcontainer 導入，並以指令安裝擴充功能。

官方文件列出五種入門途徑，其中最直接的是使用安裝腳本，它會盡量透過系統套件管理器完成大部分流程。使用者可先執行加上 --dry-run 的版本預覽安裝過程，確認無誤後再真正安裝；安裝完成後，腳本會印出執行與啟動的相關指示。

若不使用腳本，也可依官方文件手動安裝、部署到雲端服務供應商，或在已採用 devcontainer 的專案中透過對應功能導入。團隊若要集中管理，官方建議改用 Coder 平台，而非逐台維護 code-server 執行個體。

在擴充功能方面，使用者可在側邊欄的擴充市集安裝，或從命令列以擴充識別碼安裝，也能直接指定本地端下載的 VSIX 檔案。若專案所需的擴充未收錄於 Open-VSX，官方建議向其發布管道提交，或從該擴充的 GitHub 發布頁下載後手動安裝。

常見問題有哪些？

code-server 的常見疑問集中在安全性、擴充市集限制、與其他方案的差異及設定方式，多數可從官方文件與常見問題找到解答。

code-server 是免費的嗎？

是。專案以 MIT 授權開源，可免費用於個人與商業用途。團隊若需集中管理與商業支援，官方建議評估 Coder 平台。

為什麼無法使用微軟的擴充市集？

微軟市集條款限制非官方 VS Code 存取，因此專案改用 Open-VSX 擴充庫，並允許透過環境變數指向自建市集。

執行 code-server 需要什麼硬件？

官方最低需求為啟用 WebSocket 的 Linux 機器、1 GB 記憶體與 2 個 vCPU，實際需求依專案規模與同時連線人數而定。

如何變更連接埠與密碼？

可在設定檔或命令列旗標中調整。設定檔每個鍵對應一個旗標，命令列參數優先於設定檔，密碼亦支援以雜湊形式儲存。

iPad 或其他平板可以使用嗎？

可以。code-server 以瀏覽器為前端，官方文件另提供 iPad 使用說明，並建議將介面安裝為漸進式網頁應用以改善快捷鍵支援。

可以沿用原本的 VS Code 設定嗎？

可以。使用者可透過 Settings Sync 擴充同步，或指定既有的使用者資料目錄，以沿用原有設定與擴充功能。

總結：code-server 適合什麼樣的團隊？

code-server 適合希望在自有伺服器上提供瀏覽器版 VS Code、並把程式碼留在內部網路的團隊，也適合需要跨裝置接續開發的個人。

以本次 v4.140.0 為觀察點，code-server 的價值不在於單一版本的新功能，而在於長期維持與上游同步的能力。專案以每週左右的節奏跟進 VS Code，讓瀏覽器版在功能上不至於落後桌面版太多；同時以 MIT 授權與自架模式運作，把環境控制權交回使用者手中。

在方案選擇上，判斷點相對清楚。若核心需求是把程式碼與執行環境保留在自有網路、或在不更換硬體的前提下統一開發環境，code-server 的安裝成本低且依賴單純；若需要集中治理多個工作區或開箱即用的代管體驗，則應評估 Coder 平台或託管式服務。以 79,551 顆星標、6,881 次複製與七年持續維護來看，該專案已具備作為長期開發基礎設施的成熟度。
