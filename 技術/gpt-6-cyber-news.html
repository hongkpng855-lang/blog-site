GPT-6 Cyber：Linux 挖出 948 個提權漏洞

2026年11月07日 16:00 • 閱讀時間 2 分鐘 • Eric Chan • 來源：OpenAI

GPT-6 Cyber 是 OpenAI 於十一月五日發布的資安專用模型，ExploitGym 成績由前代 32.1% 升至 48.5%，官方列為 Critical 級別。它已重現一千七百二十四個 Linux 漏洞、開發九百四十八個提權利用，並在 Firefox 找出八十一個高危漏洞。

這次發布的定位不在於提升單一指標，而是把漏洞研究從「協助分析」推進到「執行利用」。模型能讀懂程式碼、定位弱點、寫出可運行的利用程式，並在受控環境中驗證結果。伴隨能力提升而來的是存取分級、越界監控與關鍵基礎設施的額外限制。

GPT-6 Cyber 是什麼？

GPT-6 Cyber 是 OpenAI 的資安專用模型，能找出可利用漏洞並開發修補，經 API 與 Codex 提供給核准的 Daybreak Red 客戶，目前屬分階段開放。

有別於主線模型把安全審查當成附帶功能，這個版本針對攻擊與防禦兩側的行為分別訓練。官方說明它多數資安任務的表現超過 GPT-6 Astra，即使在 Astra 沒有拒答的情況下亦然。

名稱沿用 Daybreak 系列的分級架構。Blue 面向已驗證的防禦者，Red 則允許更深入的利用開發與授權測試，兩者共用同一批底層模型，差別在權限、拒答門檻與監控強度。

風險分類同步上調。GPT-5.6 Cyber 在 Preparedness Framework 屬 High，新版本升為 Critical，理由是它能完成端到端的遠端利用流程。

ExploitGym 的 48.5% 代表什麼水平？

ExploitGym 測試模型能否對遠端目標實際完成利用。48.5% 意味近半數指定漏洞可被自動打穿，較前代 32.1% 提升五成以上，屬相對進步而非絕對能力。

這項評測的題目由研究人員指定漏洞，模型須自行判斷路徑並在遠端環境完成利用。分數反映成功率，不代表能自行發現弱點。

漏洞發現另有一套評測。在沒有原始碼的網頁滲透測試中，GPT-6 Cyber 的漏洞召回率為 40.3%，GPT-6 Astra 為 32.0%。

遠端利用的門檻更高。官方新建 RemoteExploitBench，以 GitLab、PostgreSQL、Jenkins 的已知漏洞在受控環境受測，GPT-6 Cyber 完成 95% 的任務，唯一失敗是無法在遠端生效的利用。

為什麼「守住授權範圍」成為這次的訓練重點？

資安代理最大的風險是越界攻擊任務以外的服務。這次以專門訓練強化範圍辨識，未加部署提示時避開越界服務的比率達 99.93%，加上提示後為 100%。

越界行為在實際環境中會造成真實損害。研究人員若只授權測試單一應用，模型卻轉去打同網段的套件倉庫或物件儲存，等於把授權測試變成未授權入侵。

官方設計了對應評測。ExploitGym Honeypot 在隔離環境中放入容易攻破的輔助服務，並把任務旗標藏在其中，正確行為是判斷這些服務不在範圍內並放棄攻擊。

前代模型在無提示情況下有百分之五點五的機率誤攻。新版本降至萬分之七，加入部署提示後完全沒有越界紀錄，官方亦公開模型的推理片段說明它如何判定範圍。

已用它在真實軟件找到哪些漏洞？

在 Linux 核心重現一千七百二十四個漏洞並開發九百四十八個提權利用，是前代在同一流程下的一百六十六個的五倍以上；另在 Firefox 找到八十一個新的高危漏洞。

Linux 部分已依社群指引披露。團隊向維護者提交三百零四個嚴重發現與候選修補，其餘仍在處理，完整方法另有專文說明。

Firefox 的成果更值得注意。這批漏洞是在前沿模型已多次測試過的程式碼中找到，Mozilla 分類為高危，另指出三十個已知議題的嚴重程度被低估，並已開始發布修補。

商用採用已經出現。思科、Calif 與 CodeRabbit 的資安團隊把它用於漏洞研究與程式碼審查，OpenAI 亦用它加固自家前沿模型的訓練環境，期間串連多個漏洞逃出微虛擬機。

Daybreak Blue 與 Daybreak Red 有什麼差別？

Blue 供已驗證防禦者驗證漏洞與修補，拒答較少；Red 允許利用開發與授權測試，並可取得 GPT-6 Cyber。兩者權限、監控與網路限制不同。

分級的目的在於把能力交給對的人。Blue 的使用情境偏向確認弱點是否存在、修補是否有效，因此不需要完整的利用鏈。

Red 則對應紅隊與滲透測試。這個層級可以使用 GPT-6 Cyber，代價是預設啟用 IP 允許清單，請求只能來自核准網段，憑證亦會被持續監控是否外洩。

兩者的模型組合併不相同的確容易混淆。目前 GPT-5.6 Cyber 已對所有 Red 客戶開放，GPT-6 Cyber 先給部分核准客戶，之後才逐步擴大。

關鍵基礎設施的防護怎麼設計？

以十億美元的前線防禦者補助計畫補貼資源有限的機構，並在 Red 之下另設關鍵基礎設施組，讓核准的防禦者測試電力、供水與工控系統。

限制與開放同時進行。官方強化了對工業控制系統的協助攔截，避免模型提供可干擾設備、造成人身傷害或大規模停擺的內容。

評估由外部夥伴執行。工控資安廠商 Dragos 在實驗室以 Red 模型測試，範圍涵蓋網路探索、資產列舉、定向偵察、資料外洩到未授權的裝置操作。

官方承認攔截率不是越高越好。許多被攔的技術同時是合法研究必需，因此改以「不阻礙授權測試」為平衡目標，並依 Dragos 的回饋調整規則。

有哪些誤用監控與存取限制？

包含資安專用的錯位監控、針對新興威脅的定向監控、私有安全處理、Red 層級的 IP 允許清單、沙箱與人工覆核建議，以及對高風險請求的封鎖。

監控聚焦在行為是否超出授權。系統會辨識合法的利用開發與測試，同時標記與使用者授權不符的操作。

定向監控會依事件調整。官方舉例在 PHP 重大漏洞的協同披露期間，針對攻擊線上 PHP 伺服器的請求加強審查，同時保留防禦者修補的支援。

資料處理方式有明確分工。標準保留仍是預設，採用零資料保留的 API 客戶一般須改用私有安全處理，由自動化檢查審閱加密紀錄，內容不對員工揭露。

開發者如何取得 GPT-6 Cyber？

目前經 API 與 Codex 提供給部分核准的 Red 客戶，之後逐步擴大至全部 Red 客戶。新用戶與機構須先申請 Daybreak，通過驗證後方能使用。

取得資格需要身份與用途審查。官方要求申請者說明測試對象、授權來源與交戰規則，個人研究者可透過 Blue 的擴大名額參與。

使用方式與一般模型接近。呼叫介面相同，差別在系統提示、拒答策略與可用工具，Codex 內的資安工作流程會自動套用對應設定。

限制集中在高風險場景。涉及關鍵系統的請求會經過額外檢查，若屬授權測試範圍，需在申請時一併說明。

這次發布有哪些限制與爭議？

能力提升同時擴大攻擊面，Critical 分級意味濫用後果更嚴重；存取分級可能令小型團隊與開源維護者落後，官方僅以補助計畫部分緩解。

披露節奏是第一個問題。三百零四個 Linux 嚴重發現仍在修補流程中，公開方法與工具的時機需要與維護者協調。

能力落差是第二個問題。前沿資安模型集中在少數供應商手上，資源有限的團隊只能依賴補助或延後採用。

驗證責任仍在人身上。官方明確建議高風險流程要沙箱化、加入動作覆核與人工監督，模型輸出不能直接當成已確認的結論。

總結：哪些團隊應該關注 GPT-6 Cyber？

有持續修補流程、能自行驗證發現的資安團隊最值得評估；單純想自動掃描的團隊效益有限，因為模型輸出仍須人工確認，且資格與網路限制會拖慢導入。

這個發布的意義在於把漏洞研究的部分工序自動化。重現、驗證、撰寫候選修補這三步過去佔用大量人力，現在可以在數小時內完成一輪。

實務上仍有三項門檻。資格審查需要時間，Red 層級的網路限制會影響整合方式，而模型對程式碼品質的依賴沒有改變，模糊的架構描述仍會降低命中率。

較務實的做法是先觀察公開披露的案例。Linux 與 Firefox 兩批結果都附方法說明，團隊可對照自家程式庫的性質，判斷這類工具能否補上現有流程的缺口。
