Claude Duet 發布：主動式代理接手日常雜務

2026年10月23日 00:00 • 閱讀時間 2 分鐘 • Eric Chan • 來源：Anthropic

Anthropic 於二零二六年十月二十一日開放 Claude Duet 研究預覽，這是一款以 Claude Opus 5.5 為核心的主動式代理應用，會在每天早上主動送上簡報，代為處理日程、帳務與文件草稿，並在發送訊息、付款或簽署之前等待使用者批准。它擁有獨立的雲端虛擬機器與瀏覽器，即使個人電腦關機仍可繼續執行任務。首階段僅供美國地區的 Pro 與 Max 訂閱者排隊申請，Team 與 Enterprise 方案暫未納入。

Claude Duet 是什麼？

Claude Duet 是 Anthropic 推出的主動式代理應用，以 Opus 5.5 驅動，在雲端虛擬機器上代為處理事務，於需要決定時才主動聯絡使用者。

產品的定位寫得相當清楚：它不是等待使用者開啟對話的聊天介面，而是一個會主動找上門的助理。官方描述的使用情境，是專業人士與小型企業主手上同時有多條線索，難以逐項追蹤；Claude Duet 的職責是判斷哪一件事需要當事人親自處理，哪一件事可以先行推進，並在必要時才發出通知。

與市場上大量「代理框架」相比，差別在於交付形態。多數開源方案要求使用者自行架設執行環境、串接工具權限與設計重試邏輯；Claude Duet 把這些工作收進產品內部，使用者只需要在單一對話串中輸入一句需求，其餘的環境準備、工具選擇與流程編排由系統完成。

Claude Duet 與 Claude 應用有何分別？

Claude 應用等待使用者開啟對話，Claude Duet 則主動聯繫使用者。兩者共用記憶、技能與連接器，但 Duet 以獨立應用形式運作，並具備背景執行能力。

官方在問答段落中把差異講得直接：Claude 應用需要使用者主動開啟聊天，並肩完成工作；Claude Duet 則是反過來先接觸使用者。它每天早上輸出一份簡報，列出跨應用程式的重要事項，其餘時間只在有新情況需要處理時才發送訊息。

第二個差異是持續執行。Claude Duet 在雲端擁有一台附帶瀏覽器的虛擬機器，任務可以在使用者離開之後繼續推進，完成或需要覆核時再發出通知。官方同時說明，它每隔數小時檢查一次已連接的帳戶，而非不間斷輪詢，理由是持續檢查會急速消耗方案的用量額度。

第三個差異體現在帳號延續性。使用者的記憶、技能與已連接應用會從既有 Claude 帳號帶入，第一則訊息即具備完整背景，不需要重新設定。這種設計讓既有使用者幾乎沒有遷移成本，也讓代理的判斷建立在長期累積的偏好之上。

Claude Duet 如何處理權限與敏感資料？

所有發送訊息、付款、簽署與刪除動作均需事前批准，憑證由系統代管，代理不會直接看到密碼。證券交易與帳戶間轉帳屬永久禁區。

權限模型採用「先展示、後執行」原則。代理在發送訊息、完成付款、簽署文件或刪除任何內容之前，會先顯示即將執行的具體動作，並等待使用者確認。部分操作即使獲得批准亦不會執行，例如買賣證券或在帳戶之間轉移資金，官方把這類動作列為硬性禁區。

憑證處理沿用 Claude Managed Agents 的設計，代理本身不會直接接觸密碼或登入權杖，應用授權與工作階段由系統代管。動作審批則交由自動模式分類器判斷，這套機制同時用於 Claude 與 Claude Code，目的是攔截使用者未曾要求的操作。

針對提示注入，官方表示防禦措施來自瀏覽器使用研究，並在模型層面同步加固。Claude Duet 另設專用的分類器與安全系統提示，逐則訊息檢查是否涉及敏感資料外洩；信用卡號與政府身分證件屬最高保護層級，一律拒絕傳送，健康與個人財務資料則只在使用者明確指示時才放行。安全驗證方面，官方提到紅隊測試、外部機構滲透測試與公開漏洞獎勵計劃三層安排。

Claude Duet 可以接上哪些工具？

Claude Duet 可使用 Claude Marketplace 內超過六千個連接器，涵蓋郵件、通訊、會計與電商等常見服務。

連接器數量是這次發布最具體的規模指標。官方指出，Claude Duet 可以使用 Claude Marketplace 內超過六千個連接器與外掛，並列出一批實際操作示例，包括在 Gmail 與 Slack 中找出漏讀訊息並協助回覆、在 QuickBooks 或 Stripe 檢查未收款項並起草催款信、在 Gusto 準備薪酬資料，以及在 LinkedIn 發布經人工修改的招聘帖文。

商業流程的覆蓋面同樣值得注意。代理可以透過 Docusign 送出合約供簽署，依 HubSpot 的聯絡人與交易記錄起草跟進郵件，把產品發布轉成 Canva 的社群活動素材，並在 Shopify 建立與管理商店。官方預告將推出更完整的視覺編輯器，讓使用者在內容上線前先行預覽店面。

採購環節補上了付款路徑。使用者可透過 Stripe 的數位錢包 Link 購買商業用品，代理先確認品項，再由 Link 要求批准支出，最終以虛擬卡付款，真實卡號不會外流；Shopify 的 Shop Pay 亦在支援之列。官方表示下一步將在取得授權的前提下，使用 1Password 內已儲存的登入資訊完成網站登入。

Claude Duet 的定價與使用限制如何？

研究預覽期間，Claude Duet 包含在 Pro 與 Max 方案內，不另收費，但與其他 Claude 功能共用同一用量額度，背景檢查亦計入其中。

收費結構相對簡單：預覽階段不設獨立訂閱，Pro 與 Max 訂閱者可直接使用，Team 與 Enterprise 方案暫未包括在內。真正的限制出現在用量層面。官方說明，Claude Duet 與其餘 Claude 功能共用同一份方案額度，但消耗方式與一般對話不同，背景檢查會計入額度，建立財務模型或簡報等大型任務則需要更多模型回合與背景工作。

這項設計意味著重度使用者可能較早觸及上限。對於每天需要多次背景巡檢的使用情境，額度消耗速度會明顯高於單純的對話式使用。官方目前未公布獨立的用量換算表，只表示會在預覽期間持續觀察並調整。

Claude Duet 目前有哪些限制？

官方承認代理可能誤讀對話脈絡或錯判急迫程度，亦可能漏掉兩次檢查之間傳入的訊息，個人瑣事處理能力較弱。

官方在公布頁面中用一整段說明不足之處，態度相對坦白。Claude Duet 屬於研究預覽，可能誤讀某個對話串的脈絡，或錯判事項的急迫程度；在兩次檢查之間傳入的訊息，也有機會被漏掉。

能力邊界同樣明確。產品核心圍繞工作場景建構，代訂機票等個人雜務的表現較弱；代理目前無法展示自己的瀏覽器畫面，使用者只能透過動作記錄理解它做了什麼。此外，Claude Duet 暫時以獨立應用形式存在，與主 Claude 應用分離，兩者日後的整合方式仍在觀察使用者回饋。

這些限制對導入決策有實際影響。對於需要完整可追溯性的合規場景，無法即時看到瀏覽器畫面意味著覆核只能依賴事後記錄；對於需要即時反應的營運場景，數小時一次的檢查頻率亦未必足夠。

常見問題有哪些？

**Claude Duet 目前可以在哪些地區使用？** 首階段僅開放美國地區的 Claude Pro 與 Max 訂閱者，需先加入候補名單，官方會在開通時以電子郵件通知。其他地區與企業方案的時程尚未公布。 **Claude Duet 會不會自行動用使用者的金錢？** 不會。任何付款動作都需要使用者先行批准，代理只負責確認品項與準備流程；涉及證券交易或帳戶之間轉帳的操作，即使在取得批准的情況下亦不會執行。 **Claude Duet 與 Claude Code 屬於同一類產品嗎？** 兩者定位不同。Claude Code 面向程式開發流程，以終端與編輯器為主要介面；Claude Duet 面向日常工作事務，以訊息往來與背景執行為核心，並以獨立應用形式提供。 **使用 Claude Duet 需要保持電腦開機嗎？** 不需要。代理在雲端的虛擬機器上執行，具備獨立瀏覽器環境，任務可以在個人裝置關閉之後繼續推進，完成後再以通知回報。 **Claude Duet 的資料會不會用於訓練模型？** 官方公告未就訓練資料另作說明，僅強調憑證由系統代管、敏感資料受專用分類器保護。企業導入前宜先查閱最新資料處理條款。

總結：Claude Duet 適合哪些使用者？

Claude Duet 適合工作事項繁多、需要有人代為追蹤與起草的專業人士與小型企業主；對需要完整審計軌跡或即時反應的場景，現階段仍需謹慎評估。

這次發布的意義，在於把代理產品從「工具」推向「同事」的位置。過去一年多數代理方案聚焦於單次任務的完成度，Claude Duet 則把重點放在判斷力：決定什麼需要打擾使用者、什麼可以等待、什麼必須先取得同意。這種設計讓自動化的邊界變得更清楚，也讓使用者較容易建立信任。

實際導入時，值得先確認三件事。第一是工作流程中有多少環節屬於「讀取、起草、準備」而非「送出、付款、簽署」，前者可以大幅自動化，後者仍然需要人工把關。第二是團隊能否接受數小時一次的檢查頻率，這直接影響代理的即時性。第三是方案額度是否足以支撐背景巡檢的消耗，重度使用者的成本可能高於預期。

對於正在評估代理工具的中小企業，Claude Duet 提供了一個相對完整的參考樣本：權限分層、憑證隔離、動作記錄與硬性禁區四個層次同時到位。即使最終不採用這個產品，這套設計思路仍值得在內部自動化規畫中對照。
