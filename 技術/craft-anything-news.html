32K 星純 Rust 逆向引擎：Craft Anything 重建任何軟件

2026年11月15日 04:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/storytold/craft-anything

Craft Anything 由 storytold 團隊於 2026 年 10 月 31 日開源，兩週內累積 32,313 顆星標與 6,583 個分支。這套純 Rust 引擎內建 320 項工具，可拆解網站、桌面程式與遊戲結構，再由 AI 編碼代理依樣重建新專案並逐項比對，採 MIT 或 Apache 2.0 雙授權。

專案的定位寫在 README 第一段：指向一個目標，說明想要什麼，它會用真實的檢視工具研究原件，讓編碼代理建立新專案，再把成品與原件對照並反覆修正。整個流程分為四個階段，依序是研究、建置、比對與交付。

這條流水線的背景值得注意。市場上多數工具只做單向工作，反編譯器只回答程式如何運作，編碼代理只負責從零產生程式碼。Craft Anything 把兩端接在同一份專案資料夾裡，讓檢視結果成為生成階段的輸入，也讓生成結果重新接受檢驗。

Craft Anything 是什麼？

Craft Anything 是純 Rust 撰寫的開源逆向與重建引擎，內建 320 項工具，可拆解網站、應用與遊戲，並交由 AI 編碼代理重建同類專案。

專案由 ArtCraft 團隊維護，該團隊同時經營一個以藝術創作者為對象的社群，並陸續推出 PhotoCraft、FilmCraft、PdfCraft、WordCraft 等以純 Rust 重寫的創作工具。Craft Anything 在產品線中扮演底層引擎的角色，既驅動同名桌面應用，也單獨提供命令列與 MCP 服務。

目標受眾的界線相當清楚。README 明列的使用場景包括研究競爭對手的網站結構、理解一個沒有原始碼的舊系統、把一款遊戲的玩法移植到另一個引擎，以及在接手遺留專案前先摸清其組成。這些工作過去需要多名工程師配合不同工具完成。

Craft Anything 的星標成長速度有多快？

專案於 2026 年 10 月 31 日建立，十四日內累積 32,313 顆星標、6,583 個分支與 382 個未結議題，並在十一月的六日內連續發布三個版本。

星標與分支的比例是觀察重點。6,583 個分支對應 32,313 顆星標，約每五顆星標就產生一個分支，這個比例高於一般教學型倉庫。分支數量偏高通常意味使用者打算實際執行或改造，而非單純蒐藏。

版本節奏同樣密集。十一月六日發布 0.5.0，九日推進至 0.6.0，十二日再給出 0.6.1。0.6.1 的版本說明列出數十項合併請求，內容集中在 Mach-O、ELF、PE 與 Unity 資源解析的邊界處理，顯示團隊正逐項補強引擎的解碼覆蓋範圍。

貢獻者規模也超出單人專案的常態。儲存庫的分頁資料顯示貢獻者接近百人，其中反編譯與格式解析的修補多由不同帳號分頭處理。這種分工方式讓引擎可以在短期內覆蓋大量冷門檔案格式。

Clean room 模式與 Deep 模式有何分別？

Clean room 為預設模式，只讀訪客可見的畫面、文字與版面量測，拒絕進入原始碼的工具。Deep 模式則開放檔案讀取與反編譯，供私人用途完整檢視。

模式切換在標題列或設定頁完成，也可以在命令列加上參數單次指定。Clean room 下的工具若嘗試進入原件內部，會直接拒絕並提示開啟 Deep 模式，這種設計讓使用者在預設狀態下不會意外讀到不該讀的部分。

兩種模式對應不同的法律與倫理邊界。Clean room 的邏輯接近傳統的淨室設計，只依外部可觀察行為重建，避免直接複製實作。Deep 模式則回到傳統逆向工程的範疇，適合分析自有系統或已獲授權的目標。

README 對這一點有明確的自我限制說明。文件寫明 clean room 是一套工具層面的規則，並非作業系統層級的沙箱，不會隔離使用者的電腦。被呼叫的編碼代理仍以自己的權限運作，能讀寫什麼取決於該代理本身的設定。

Craft Anything 的技術架構有什麼特點？

引擎以純 Rust 實作，內建解碼器、反彙編器與反編譯器，覆蓋原生程式、.NET、Android、網站、固件與遊戲檔，無須外部程式即可運作。

自帶解碼鏈是此專案與多數逆向工具的分水嶺。傳統流程往往需要先安裝反編譯器、再補上格式解析腳本，工具鏈一旦缺件就無法繼續。Craft Anything 把這些環節收進同一份二進位，Deep 模式僅在需要更深分析時才選用外部的 Ghidra。

同一套引擎同時供應三種介面。桌面應用使用 egui 繪製，命令列提供批次操作，MCP 服務則把工具暴露給外部代理。官方說明指出，部分模組已編譯為 WebAssembly，可直接在瀏覽器內辨識檔案類型，檔案不會離開本機。

輸出形式也經過設計。每項檢視結果都是一筆證據記錄，附帶信心值、覆蓋範圍與已知限制，較大的結果先回傳摘要，再透過分頁工具逐段取用。這種結構讓後續的比對階段可以引用具體依據，而不是依賴模型的印象。

Craft Anything 如何與 AI 編碼代理協作？

建置階段需本機已登入的編碼代理，首選 Claude Code，直接執行原版 claude 並沿用其登入。另可經 ACP 接入 Gemini CLI 等代理。

憑證處理方式是同類工具中較保守的做法。Craft Anything 不代為保管帳號，也不介入登入流程，使用者的 claude 程式以自身憑證連線，額度與條款仍歸使用者與供應商之間的協議。文件同時註明，Codex 轉接層雖已寫好，尚未在真實安裝上驗證。

其他代理的接入依賴 ACP 協定。GitHub Copilot 與 Grok Build 需要各自先完成登入，其餘支援 ACP 的代理可在每個後端單獨切換。若只想做問答與分析而不建置，Anthropic、OpenAI、OpenRouter、xAI 與本地相容伺服器都能作為分析後端。

代理端的選擇會直接影響可用額度與流程長度。Codex CLI 0.169 的終端工作區擴充便是一個例子，同一個帳號可在編輯器、桌面與命令列之間切換，額度與訂閱方案綁定。

代理的權限界線被反覆強調。文件指出，編碼代理執行時仍以使用者身分行動，Craft Anything 能拒絕哪些代理自帶工具，取決於各家代理的介面設計，Claude Code 的部分另有一份專頁說明。

320 項工具如何被外部代理呼叫？

每項工具同時是命令列子命令與 MCP 工具，代理可列出全部工具、啟動 MCP 服務，或以單一 rebuild 指令完成掃描、建置與比對，無須開啟圖形介面。

命令列入口的設計偏向可組合。列出工具、啟動 MCP 服務與執行重建各有獨立子命令，重建時可指定輪數、指定既有資料夾續作，或把目標換成一句純文字需求，直接產出一個全新專案。

同樣走 MCP 路線的還有瀏覽器自動化領域，Playwright MCP 把 72 項操作包成工具，讓代理以結構化指令操控頁面，兩者的差別在於一者瞄準取證與重建，一者專注日常網頁操作。

專案資料夾的結構固定，包含記錄請求與狀態的設定檔、擷取自原件的素材、生成出來的應用、每輪比對的結果、證據資料與待答問題。這種配置讓重建過程可以中斷後接手，也讓比對紀錄具備可追溯性。

專案也能從使用者指定的資料夾開始。若該資料夾已有檔案，系統會要求使用者說明這些檔案是應用本體或起始素材，兩種情況的生成位置不同，避免覆寫既有工作。

Craft Anything 與同類工具有何差異？

多數工具只做分析或只做生成，此專案把檢視、重建與比對串成單一流程，並以 clean room 規則限制取證範圍，比對階段會以三種畫面寬度檢驗網站成品。

比對階段的具體做法值得單獨說明。網站專案會在三種畫面寬度下逐頁比對，並計算相似程度；遊戲專案改以遊戲自帶的測試流程驗證玩法；桌面應用則以實際執行狀況判斷。這種按類型調整的檢驗方式，比單純的畫面截圖對照更接近真實可用性。

與傳統反編譯工具相比，差異在於它不停在理解階段。Ghidra 一類工具能把二進位還原成可讀的虛擬碼，但不會替使用者產生替代實作。Craft Anything 把理解結果直接餵給編碼代理，讓下一步的產出有依據。

同類思路此前已出現在較輕量的專案上，REA 以單一命令反推任意應用，但範圍限於結構理解；這次把重建與比對補上，流程才算閉環。

與編碼代理相比，差異在於它有參照物。純生成流程只能依提示詞建構，成品是否貼近原件無從判斷。此專案在生成後保留一份可量化的對照紀錄，使用者能看到還差多少，而不是只看模型自稱完成。

Craft Anything 有哪些已知限制？

專案標示 early alpha，以 API Key 及其他編碼代理建置尚未實機跑通，應用與遊戲的行為檢查僅部分完成，少量引擎工具只對照替代樣本測試，穩定性仍需驗證。

環境門檻不低。建置需要 Rust 1.97 或以上版本，桌面端在 Debian 與 Ubuntu 上還需安裝一組圖形與輸入相關的開發函式庫。發行檔雖已覆蓋 Windows、macOS、Linux、FreeBSD 與瀏覽器，全部仍屬 alpha 階段。

套件格式存在實質取捨。Flatpak 版本因為沙箱限制無法啟動本機瀏覽器，而研究網站正需要瀏覽器，官方因此建議改用其他封裝。這意味在部分 Linux 發行版上，功能會隨封裝方式而縮減。

安裝依賴的風險已被寫進文件。建置過程會執行 npm、cargo 等安裝指令，這些指令可能在安裝階段執行第三方程式碼。Craft Anything 會在首次遇到某類指令時請求確認，但一旦選擇永遠允許，後續同類指令就不再提示。授權層面另有一項限制，ArtCraft 的名稱與標誌屬商標，分支版本必須移除。

如何開始使用 Craft Anything？

先在電腦安裝 Rust 1.97 或以上版本並登入一個編碼代理，再從 Releases 取得對應平台的安裝檔，或自行編譯桌面版與命令列，最後執行 doctor 檢查環境。

從發行檔安裝是最短路徑。Windows 提供安裝檔與免安裝壓縮檔，macOS 提供已簽章與公證的映像檔，Linux 提供 AppImage、Flatpak、deb、rpm 與壓縮檔，FreeBSD 與 RISC-V 則只有壓縮檔。所有檔案在版本頁附有校驗碼清單。

自行編譯需要多一步環境準備。在 Debian 或 Ubuntu 上，桌面版需要 xkbcommon、wayland、gtk 等開發套件，安裝後即可從原始碼執行。命令列則可透過 cargo 安裝，完成後以 doctor 子命令檢查安裝狀態、編碼代理與引擎是否齊備。

git clone https://github.com/storytold/craft-anything && cd craft-anything
cargo run --release -p craft-anything
cargo install --path apps/craft-anything-cli
craft-anything-cli doctor

命令列的第一次重建建議從簡單目標開始。官方示範以一個公開網站為對象，指定重新製作該網站，或直接以一句需求生成小遊戲，並可限制輪數以控制執行時間。新專案預設落在文件資料夾下的專用目錄，位置可在設定頁更改。

出處連結有哪些？

原始碼與發行檔位於 GitHub 的 storytold/craft-anything，官方網站為 getartcraft.com，社群討論集中在 Discord。

儲存庫位址為 https://github.com/storytold/craft-anything ，版本頁列出各平台的安裝檔、校驗碼與逐版變更說明。官方網站 getartcraft.com 提供同一產品線其他工具的介紹，文件目錄另收錄工具清單、狀態表與路線圖。

總結：Craft Anything 適合什麼團隊？

適合需要理解遺留系統、移植遊戲或研究競品結構，且已有編碼代理可用的小型團隊。若目標只是單純生成程式碼，現有代理已足夠，額外安裝此引擎的必要性有限。

專案的價值集中在理解與重建之間的那段空白。單純分析工具能回答系統如何運作，單純生成工具能產出可執行程式，兩者之間的落差過去靠工程師的經驗填補。Craft Anything 把這段過程拆成可記錄的步驟，並保留每輪比對的證據。

風險與限制同樣清楚。early alpha 的標示意味著介面與行為仍可能變動，部分代理整合尚未實機驗證，套件格式的功能也有差異。對於需要穩定產線的團隊，現階段適合用於探索與評估，不宜放進正式流程。

三萬顆星標在兩週內累積，反映開發者社群對「可驗證的重建」確實存在需求。專案能否把這股關注轉為長期維護，取決於引擎覆蓋率能否持續補齊，以及商業化路徑能否在不封閉核心的前提下成立。
