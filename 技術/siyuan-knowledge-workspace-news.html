SiYuan 思源筆記：4.6 萬星的本機優先知識庫

2026年10月13日 04:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/siyuan-note/siyuan

SiYuan（中文名思源筆記）是一款由開發者 88250 於 2020 年 8 月開源的本機優先知識管理系統，GitHub 星標數累積至 46,733 顆、複製數 3,058 次，最新版本為 2026 年 9 月發佈的 v3.8.6。它以區塊作為最小管理單位，支援雙向連結、SQL 查詢嵌入與 Markdown 所見即所得編輯，內建 AI 對話、OCR 與間隔重複卡片，資料以純文字與 JSON 格式儲存在本機工作空間，可完全離線使用或透過 Docker 自行架設。

本文依據官方儲存庫的 README、版本紀錄與架構說明整理，先說明專案定位，再逐項分析功能結構、技術架構、維護狀況與實際採用前提，供評估知識管理工具的團隊與個人參考。

SiYuan 是什麼？

SiYuan 是 2020 年開源的本機優先知識管理系統，以區塊為最小單位，支援雙向連結、Markdown 所見即所得編輯與 SQL 查詢嵌入，資料留在本機。

專案定位為「人與 AI 代理共同工作的知識工作空間」，由中國開發者社群 b3log 維護。其核心主張是資料主權：所有筆記以純文字與 JSON 檔案存放在使用者指定的工作空間資料夾，不強制上傳雲端，因此可以離線編輯，也能透過第三方同步工具或自架服務在多台裝置之間傳遞。

與多數雲端筆記服務不同，SiYuan 把「區塊」視為可尋址的基本單位。段落、清單、標題、程式碼區塊都擁有獨立識別碼，可被引用、嵌入與查詢，這使跨文件組裝內容與建立知識關聯成為系統的原生能力，而非外掛功能。

專案同時明確支援 AI 工作流程。儲存庫標籤涵蓋 ai-agent、agentic-ai 與 mcp，官方說明提到可透過 OpenAI 相容 API 進行寫作與問答，並提供插件介面讓外部代理讀寫筆記資料，反映其從純筆記工具向知識基礎設施演進的方向。

SiYuan 有哪些核心功能？

功能涵蓋區塊級引用與雙向連結、SQL 查詢嵌入、大型文件編輯、數學公式與圖表、網頁擷取、多格式匯出、間隔重複卡片與 AI 寫作問答。

內容組織採區塊式設計。每個區塊可被引用與嵌入，支援反向連結與自訂屬性，並允許以 SQL 查詢語法直接查詢整個工作空間的資料，把筆記當成可查詢的資料庫。編輯器同時提供大綱、區塊放大與百萬字級長文件編輯，適合撰寫長篇技術文件或書籍草稿。

輸入與輸出能力相對完整。系統可匯入網頁內容並保留來源連結，支援數學公式、流程圖、甘特圖、時序圖與五線譜等區塊類型；匯出方面提供標準 Markdown 含附件、PDF、Word 與 HTML，並可直接複製到微信公眾號、知乎與語雀等平台。

學習與 AI 功能屬於差異化項目。內建間隔重複卡片與獨立的複習模組，可用於語言或考試記憶；OCR 採用 Tesseract 引擎處理圖片文字；AI 寫作與問答則透過相容 OpenAI 的 API 介面執行，讓使用者以自有金鑰串接模型。

SiYuan 的技術架構如何運作？

前端以 TypeScript 搭配 Electron 與 Go 內核組成，資料存放於本機工作空間的 JSON 檔案，並以 lute 編輯引擎與 dejavu 資料倉庫串成生態。

桌面端採 Electron 外殼搭配 Go 編寫的內核，前後端以本機介面通訊；行動端則對應 Android、iOS 與 HarmonyOS 三個獨立儲存庫。語言組成以 TypeScript 約 1,365 萬位元組與 Go 約 1,243 萬位元組為主，兩者比重接近，反映其將資料處理與介面渲染分離的設計取向。

資料層由獨立專案負責。編輯引擎為 lute，資料倉庫與版本機制為 dejavu，社群市集為 bazaar，插件介面為 petal，間隔重複模組為 riff。這些元件各自開源，使用者可理解資料流向，也讓第三方開發者能針對單一環節擴充。

部署方式兼顧個人與團隊情境。官方提供應用商店與安裝套件、多種套件管理器版本、Docker 映像 b3log/siyuan，以及 Kubernetes、Unraid 與 TrueNAS 的部署說明。自 v3.7.0 起 Docker 需明確帶上 serve 子命令，並以 --workspace 指定工作空間路徑、以 --accessAuthCode 設定存取密碼，適合架設在自有伺服器保存資料。

版本發布呈穩定週期。最新標籤 v3.8.6 於 2026 年 9 月 29 日發佈，各平台安裝檔同步提供，涵蓋 Linux、Windows 與 macOS 的套件與映像格式。專案並維護公開的開發計畫看板與更新日誌，讓使用者可追蹤功能排程。

SiYuan 與其他筆記軟體有何差異？

差異在於資料以本機純文字檔案儲存、區塊可被引用與 SQL 查詢、內建 AI 與間隔重複功能，且主要功能免費並允許商業使用。

資料存放方式是最根本的分野。多數主流筆記服務將內容保存在廠商雲端資料庫，匯出格式與欄位對應由平台決定；SiYuan 把資料留在本機工作空間，使用者可直接以檔案系統備份或版本控管，長期可讀性不依賴廠商存續。

內容模型亦不相同。部分工具以整頁文件為單位，連結只能在頁面層級建立；SiYuan 以區塊為單位，同一段文字可被多處引用並自動同步，配合 SQL 查詢可以組裝儀表板式的筆記視圖，適合建立個人知識圖譜而非單純的分類目錄。

授權與成本結構值得留意。專案採 AGPL-3.0，官方說明強調多數功能免費且允許商業使用，只有部分雲端同步與會員功能需要付費；對比以訂閱制為主、免費版限制同步裝置數量的服務，自架路線在長期成本上更具彈性。

如何開始使用 SiYuan？

從官方應用商店或安裝套件取得桌面與行動版本，指定本機工作空間資料夾即可開始，團隊可用 Docker 映像自架並設定存取密碼。

取得方式以官方管道為主。桌面端建議經微軟商店或其他應用商店安裝，便於一鍵升級；行動端在 App Store、Google Play 與 F-Droid 皆可取得；進階使用者則可透過套件管理器或 GitHub Releases 下載安裝檔。首次啟動只需指定一個本機資料夾作為工作空間，不需要註冊帳號。

自架部署適合需要多裝置同步的團隊。以 Docker 執行官方映像 b3log/siyuan，掛載工作空間目錄並設定 --accessAuthCode 密碼，即可透過瀏覽器存取；官方亦提供 Kubernetes、Unraid 與 TrueNAS 的部署範例，資料仍在自己的伺服器上。

導入策略建議先以個人工作空間試用。熟悉區塊引用與雙向連結後，再評估資料庫視圖、SQL 查詢與 AI 寫作等功能是否符合既有流程；若團隊需要多人協作與權限控管，則應先確認自架方案的備份與還原演練是否完備。

SiYuan 有哪些限制與採用考量？

限制包括同步須自行架設或設定第三方服務、部分進階功能需付費、介面以中文社群為主，以及 AGPL 授權對閉源整合設有條件。

同步與備份需要自行規劃。由於資料儲存在本機，跨裝置同步必須依賴第三方同步磁碟、WebDAV、相容 S3 的物件儲存或自行架設伺服器；若資料倉庫金鑰遺失，官方說明需透過備份還原，因此備份策略屬於必要前置工作。

成本與功能分層需先釐清。官方定價顯示部分功能僅提供付費會員，例如部分雲端同步與進階服務；一般使用與商業使用不需付費，但企業若計畫整合進內部平台，仍應先確認所需功能落在哪一層。

授權條件對軟體廠商影響較大。AGPL-3.0 要求以網路提供服務的衍生作品同樣開源，若打算將 SiYuan 的程式碼嵌入閉源產品或 SaaS，需先諮詢法務；純粹作為終端使用者的個人與團隊則不受此限制。介面與文件以中文社群為主要來源，英文資源相對有限，非中文使用者需要自行適應。

總結：SiYuan 適合什麼使用者？

適合重視資料主權、需要區塊級知識關聯與內建 AI 功能的個人與小型團隊，願意自行處理同步與備份者尤其合適。

專案的長期價值在於把筆記還原成可攜的檔案。區塊級引用、雙向連結與 SQL 查詢讓知識得以組裝與檢索，本機純文字儲存則降低了對單一廠商的依賴，46,733 顆星標與 3,058 次複製反映這條路線在開源社群獲得穩定支持。

採用前仍需衡量現實條件。跨裝置同步與備份須自行規劃，進階功能存在付費分層，AGPL-3.0 對閉源整合設有條件，介面與文件亦以中文社群為主。對於重視資料主權、願意投入設定成本的個人與小型團隊，SiYuan 提供了功能完整且可長期維護的知識工作空間選項。
