Selenium 4.53 開源：官方 MCP 伺服器登場

2026年11月20日 20:00 • 閱讀時間 4 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/SeleniumHQ/selenium

Selenium 4.53.0 於 2026 年 11 月 17 日發佈，上一版為 10 月 29 日。此版在 Java、Python、Ruby、JavaScript 與 .NET 五種綁定同步加入無障礙快照，並把官方 MCP 伺服器推進至 v1。專案累積 34,599 顆星標、8,733 個分支，採 Apache-2.0 授權。

這個專案自 2004 年開始運作，GitHub 倉庫於 2013 年 1 月上線。它的核心產出並非單一工具，而是 W3C WebDriver 規範的實作基礎：一套與平台和語言無關的程式介面，對接所有主流瀏覽器。

維護模式值得注意。專案由志願貢獻者長期推進，提交次數超過 35,000 次，標籤數達 268 個，分支數 122 個。版本節奏約每三週一次小版，改動分散在五條語言綁定與 Grid 元件上。

Selenium 4.53 是什麼？

Selenium 4.53 於 2026 年 11 月 17 日發佈。五種語言綁定同步加入無障礙快照，官方 MCP 伺服器推進至 v1，AI 代理可透過元素引用操作真實瀏覽器。

版本說明把 4.53 定位為能力對齊版本。無障礙快照的原子實作先前只存在於部分綁定，此次統一補齊，並移除 Java、Ruby 與 .NET 的舊有客戶端實作，避免兩套邏輯並存。

同一版本內亦包含兩項相容性調整。Python 綁定的 driver.webextension 進入棄用程序，改用新的腳本介面；Select 元件改以 XPath 依 value 屬性定位選項，處理結尾雙引號的轉義問題。

官方 MCP 伺服器解決什麼問題？

官方 MCP 伺服器讓編碼代理以無障礙樹讀取頁面，靠元素引用執行動作，不必推測選擇器。工具命名對齊 Playwright MCP，技能檔與習慣可直接沿用。

過去由代理驅動瀏覽器，常見做法是讓模型讀取 HTML 後自行生成 CSS 選擇器。這條路徑的失敗率高，頁面結構一改動，選擇器即失效，除錯成本落在使用者身上。

無障礙快照改變了輸入形式。頁面被轉換成帶引用的語意樹，代理看到的是「登入按鈕」這類角色與名稱，動作直接指向引用編號。引用在同一頁面內保持穩定，導航後才重新編號。

工具集覆蓋完整操作鏈。快照、導航、點擊、輸入、表單填寫、下拉選擇、按鍵、懸停、拖放、檔案上傳、等待、對話框處理、截圖、主控台訊息、網路請求、視窗調整與分頁管理皆為內建。

無障礙快照為什麼重要？

快照在頁面沙箱內依 WAI-ARIA 與 HTML 無障礙 API 計算角色與名稱，頁面腳本無法干擾。開放式 Shadow DOM 亦納入，密碼值一律不顯示。

這套計算在頁面內獨立沙箱完成，不依賴外部服務。角色、名稱與狀態依規範推導，iframe 內容以框架自身的引用為前綴，例如 f5e1，工具可直接對其操作。

輸出範圍有明確界線。預設只列出可互動元素、標題、即時區域與框架，加上 all: true 參數才會納入其餘可見內容。這個設計控制了單次快照的體積，也降低模型的判讀負擔。

各語言綁定有哪些同步更新？

五種綁定同步加入無障礙快照原子與方法。Python 另補相對定位器支援 WebElement 與 ShadowRoot，Grid 恢復把新工作階段分散至各節點。

Python 綁定的改動數量最多。除相對定位器外，另加入 WebDriver cookie 型別註解，並提供與協定無關的 driver.script 介面，同時棄用舊有的擴充套件載入方式。

其餘綁定亦各有進展。Java 端加速 JSON 序列化與解析，並修正非 CSS 識別碼的框架編號轉義；Ruby 允許在啟動瀏覽器時設定環境變數，JavaScript 端把雙向協定的數值限制在宣告範圍內。

安裝與使用門檻在哪裡？

需 Node.js 22.23.4 以上版本與本機 Chrome。伺服器走 stdio，預設無介面、單一瀏覽器。Edge 與 Firefox 可啟動但未完成測試。

安裝指令按代理而異。Claude Code 與 Codex 使用各自的 mcp add 子命令，Cursor 與 VS Code 需在設定檔加入 npx @selenium/mcp@latest，其餘客戶端直接以 stdio 伺服器啟動。

目前的實務障礙在套件供應狀態。截至撰稿時，公開 npm registry 對 @selenium/mcp 回傳 404，倉庫的開發說明指出相依的 getAccessibilitySnapshot() 隨 selenium-webdriver 4.53.0 首次提供，未上架前需以具 read:packages 權限的 GitHub token 安裝 nightly 版本。selenium-webdriver 4.53.0 本身已於 npm 正常提供。

安全預設偏向保守。未加 --allow-evaluate 參數時，不提供執行代理自撰 JavaScript 的工具；file:// 網址與工作目錄外的檔案上傳預設封鎖；導航僅允許 http、https、about:blank 與 data 四種協定。

與 Playwright MCP 相比有何差異？

兩者工具命名與參數對齊，遷移成本低。Selenium 版走 WebDriver 與雙向協定，可接既有 Grid 叢集；Playwright 版功能覆蓋較完整。

Selenium 版本的優勢在既有基礎設施。企業若已建置 Grid 叢集，可用 --grid 參數把瀏覽器導向遠端節點，不必在每台機器安裝瀏覽器，這是 Playwright 版本目前未提供的部署路徑。

成熟度仍有差距。倉庫明確標示 v1 進行中，請求攔截、HTTP 傳輸與多工作階段皆未支援，selenium_* 系列工具亦待後續版本補上。Playwright MCP 已在功能廣度上領先一段時間。瀏覽器端的代理介面競爭不止於此，Chrome DevTools MCP 直接接上瀏覽器除錯協定；若目標是抓取網頁內容而非操作頁面，Crawl4AI 提供另一條路徑。

總結：誰適合現在試用？

已用 Selenium Grid 的團隊最適合評估，可沿用既有節點取得代理操作能力。純前端測試團隊宜等套件上架 npm。需請求攔截者短期應選替代方案。

4.53 的價值在於把瀏覽器自動化與代理操作接上同一條軌道。無障礙快照原本是測試輔助功能，如今成為模型讀取頁面的主要通道，這個轉向降低了代理對頁面結構的依賴。

評估時應聚焦三件事。套件供應狀態決定導入時程，安全預設決定可開放的操作範圍，Grid 相容性決定是否值得切換。三者確認後，再進入小規模試用較為穩妥。

常見問題有哪些？

以下五題說明套件供應現況、與 Playwright MCP 的取捨、可用瀏覽器範圍、無障礙快照運作方式，以及 Grid 接入條件。

現在可以直接用 npx 安裝嗎？

視套件上架進度而定。撰稿時公開 npm registry 尚未收錄該套件，直接執行 npx 會失敗。替代做法是依倉庫說明設定具 read:packages 權限的 GitHub token，從 GitHub Packages 取得 nightly 版本。

應該選 Selenium MCP 還是 Playwright MCP？

已有 Grid 叢集或既有 Selenium 測試資產的團隊，選前者可沿用基礎設施。追求功能完整度與請求攔截能力的團隊，選後者較務實。兩者工具命名一致，日後遷移成本不高。

Firefox 與 Edge 支援到什麼程度？

兩者可以啟動，但官方標明尚未測試。穩定路徑為 Chrome，預設以無介面模式運行。需要顯示視窗時加上 headed 參數，除錯時較易觀察。

無障礙快照會不會讀到密碼欄位？

不會。快照計算時密碼值一律不輸出，只保留欄位角色與名稱。若需讀取儲存內容，須另加 storage 工具群組，該群組會回傳 cookie 與 Web Storage 值，可能包含工作階段權杖。

既有 Grid 環境如何接入？

啟動伺服器時加上 grid 參數並指定 Hub 位址，瀏覽器即在遠端節點執行。此模式下本機不需安裝 Chrome，適合多機器或容器化環境，惟節點版本需與 4.53.0 對齊。
