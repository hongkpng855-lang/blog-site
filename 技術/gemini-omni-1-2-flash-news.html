Gemini Omni 1.2 Flash：15 秒影片降價三成

2026年11月06日 20:00 • 閱讀時間 2 分鐘 • Eric Chan • 來源：Google DeepMind

Google DeepMind 於二零二六年十一月五日推出 Gemini Omni 1.2 Flash，把原生影片生成長度由十秒延長至十五秒，並將 720p 定價下調三成至每秒零點零七美元。新版本同步開放多輪對話剪輯、更強的參考圖遵循與更自然的多語者對白，已在 Gemini API 與 Google Cloud 全面可用。

這次更新的定位相當明確：把生成式影片從「一次出片」的實驗工具，推向可反覆修改的生產流程。官方把價格、長度、一致性三項並列為主要賣點，背後對應的是廣告、電商與教學內容的實際工作方式。開發者可先在低解析度快速試錯，再針對單一細節追加指令，最後把定稿升頻輸出。

Gemini Omni 1.2 Flash 是什麼？

Gemini Omni 1.2 Flash 是 Google DeepMind 的生成式影片模型，主打原生十五秒片段與多輪對話剪輯，經 API 及 Google Cloud 提供。

此模型屬於 Gemini Omni 系列的第三個版本，前一代 1.1 於八月底發布，當時的長度上限為十秒，並以場景延伸與 4K 升頻作主打。1.2 Flash 延續同一條產品線，把重心由「能不能生成」轉向「能不能穩定修改」。

命名中的 Flash 對應延遲與成本取捨。官方把此版本定位為大量產出的工作層，適合批量生成廣告變體、商品展示與社群短片，而非單次製作的旗艦模型。企業用戶可透過預留輸送量方案取得較穩定的排隊優先級。

影片長度增至十五秒有什麼實際用途？

十五秒足以容納一段完整敘事或一則社群廣告，並可按一秒為單位指定三至十五秒的長度。單次生成即可完成過往需要拼接的多鏡頭短片。

長度是這輪最直接的變化。上一代的十秒限制令多數題材必須靠剪接拼接，接縫處的色溫與運鏡經常出現落差。放寬到十五秒之後，產品說明、開箱流程與情境短劇可以在一次生成內完成。

長度亦可精細指定。請求可把時長設為三至十五秒之間的任何整數，官方形容這是為了讓創作者按平台版位調整，例如六秒的前導片與十五秒的完整版本可以由同一個提示衍生。

更長的片段同時考驗一致性。官方在示範中以單一風格影格生成四鏡頭、十五秒的科學解說，並要求畫面中的標註文字隨鏡頭移動而保持正確拼寫，這一點在過往版本中難以穩定達成。

多輪對話剪輯如何減少重做？

每次追問只改動指定元素，其餘畫面沿用上一輪結果。換背景、換光線、改比例皆可在同一片段上連續調整，不必重新簡報或整段重生成。

過去修改一段生成影片，通常要調整提示後整段重跑，運氣成分高。新版本把編輯變成對話：使用者針對既有片段提出追加指令，模型只改動被指明的部分，其餘構圖、角色與運鏡保持不變。

官方示範以一組角色在帳篷前的片段為起點，逐輪把背景換成橡木林、馬廄、市集與石堡，角色的表演、盔甲反光與鏡頭位置全程維持。這種做法讓一支素材可以快速衍生出多個投放版本。

對團隊協作而言，改動脈絡也變得可追溯。每一輪指令與對應結果構成可回看的版本鏈，審核者能指出具體哪一輪造成偏差，而不必在整段重生成之間猜測原因。

參考圖遵循提升解決了哪些問題？

模型可同時接受角色、產品與風格圖片、三秒動態片段及音訊提示，並在整個片段維持臉部、服裝、包裝字體與品牌色一致，減少角度切換時的漂移。

參考條件是這輪技術描述中最具體的一項。舊版本在鏡頭轉向或角色走動時，臉部特徵與服裝剪裁容易變形，包裝上的文字更是經常糊成無法辨識的色塊。

1.2 Flash 把這些細節的保持範圍延伸到全片。官方以一位模特兒配合三套服裝的正背面產品照，生成十五秒的虛擬試穿序列，內容包含三百六十度轉身與匹配剪接，每套服裝的剪裁、垂墜與背部細節均維持一致。

對電商而言，這意味著既有商品攝影可以轉為動態素材，而不必重新拍攝。官方列出的用例包括虛擬試穿、目錄旋轉與品牌廣告，這些過去需要實拍或逐格後製的內容，現在可以用既有圖片作條件生成。

價格下調三成後成本怎樣計算？

720p 影片定價為每秒零點零七美元，較 1.1 版本低三成。十五秒片段約一點零五美元，草稿階段可用較低解析度進一步壓低成本。

計費以輸出秒數為單位，與解析度掛鉤。官方公布的 720p 價格為每秒零點零七美元，換算一段十五秒成品約一點零五美元；上一代同規格的價格高出三成。

工作流程本身也是成本設計的一部分。草稿階段可用 360p 或 720p 快速生成，發現細節偏差時以追加指令修正，而非整段重跑；只有確定採用的版本才升頻至 1080p 或 4K。這種分層做法讓試錯成本與成片成本分開計算。

企業級採購另有預留輸送量方案，可按需求保留固定產能。對於每日需要產出數十支素材的團隊，排隊時間往往比單價更影響整體節奏，這類方案解決的是交付確定性。

對白與鏡頭控制有哪些改進？

模型可為多個角色分配不同聲音，改善唇形同步與語氣連貫，並支援連續運鏡如穿越、環繞與拉遠，跳接與比例跳動明顯減少。

語音部分過去是生成影片的弱項，多人對話時常出現聲音錯配或唇形落後。新版本加入多語者條件，可把不同取樣聲音指派給指定角色，並在十五秒片段內維持語氣與節奏。

鏡頭控制方面，官方示範以兩張建築參考照生成一段連續的穿越鏡頭：由廣場起飛、穿過銅門、沿穹頂內壁上升至天窗，全程沒有跳接。這種長鏡頭在舊版本中通常會在中途斷裂或比例失真。

運動轉移亦一併開放。同一段水流動態可以在第二輪換成舞者的裙擺，動作節奏沿用原始片段，減少了重新描述動作的需求。

開發者與企業可以從哪裡接入？

開發者可用 Gemini API 與 AI Studio 試用，企業經 Google Cloud 建置，一般用戶則可在 Flow 與 Gemini 應用直接使用。

接入路徑分三層。開發者層面提供 Gemini API 與 AI Studio，官方另備互動範例與定價文件，方便先做小規模驗證。企業層面則走 Google Cloud 控制台，可與既有雲端身分與計費體系整合。

應用層面的覆蓋範圍更廣。Flow 支援場景導演與多輪剪輯，Gemini 應用讓一般帳號免額外費用生成十五秒片段，Google Vids 為 Ultra 訂閱者提供同級能力，Google Ads 則可直接用於廣告素材量產。

輸出均帶有不可感知的 SynthID 水印。這項設計讓平台與工具能辨識內容來源，對需要標示AI生成素材的投放場景而言，屬於必須提前確認的合規細節。

目前仍有哪些限制？

官方坦言快速體育動作、頻繁腳本改動與複雜物理模擬仍待改善。十五秒以上的長篇敘事仍需拼接，參考條件過多時亦可能出現取捨。

官方在發布說明中主動列出待改進項目，包括高速運動的動作連貫、短時間內大量改稿的穩定性，以及複雜物理互動的準確度。這些限制意味著賽事精華與高動作密度題材仍需實拍或混合流程。

長度上限仍是十五秒。若成品需要三十秒或更長的敘事，仍需分段生成再拼接，接縫處的一致性雖然改善，但未達全自動程度。

參考條件亦有取捨。同時提供角色、產品、風格與音訊提示時，模型需要在多項約束之間分配注意力，條件越多，個別細節的還原度越可能下降。實務上宜先確定最關鍵的一至兩項條件。

哪些團隊值得優先評估？

需要大量短片變體的電商、廣告與教學團隊受益最明顯。以實拍為主的品牌與高動作密度題材，短期內仍宜維持原有製作流程。

最直接的受益者是素材需求量大的團隊。當一支商品影片可以從既有攝影衍生出多個背景與版位版本，製作排程會從「拍攝日」轉為「生成與審核」。

教學與解說內容同樣合適。十五秒長度足以交代一個概念或操作步驟，搭配可修改的標註與鏡頭運動，能穩定產出系列短片。

以實拍質感為核心的品牌則宜審慎。生成內容在光影細節與材質還原上仍有差距，且帶有數位水印，對於強調真實感的形象廣告未必合適。較穩妥的做法是把此類工具用於前期分鏡與提案，而非最終成品。

總結：這輪更新改變了什麼？

更新把重點由生成能力轉向可編輯性與單位成本。十五秒長度、對話式修改與三成降價組合起來，令短片量產的門檻明顯降低。

三項改動互相補足。更長的片段減少拼接需求，對話式編輯降低重做成本，價格下調則讓試錯變得可負擔。單看任何一項都只是參數調整，合起來才構成工作流程的改變。

對仍在觀望的團隊，實際的評估方式相當簡單：挑一支既有素材，用低解析度草稿跑三輪修改，比較人工剪輯所需的工時。若三輪之內能得到可用的版本，這類工具便值得納入常規流程。
