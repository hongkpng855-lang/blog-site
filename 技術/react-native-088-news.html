React Native 0.88 發布：Legacy 架構退場倒數

Eric Chan

IT 顧問・實測主義者

2026年10月17日 12:00 • 閱讀時間 3 分鐘

來源：GitHub

內容創作者： https://github.com/react/react-native

React Native 0.88 是 Meta 於 2026 年 10 月 15 日發布的跨平台應用框架版本，儲存庫累積約 12.7 萬顆星標與 4.2 萬次提交。此次屬非破壞性更新，除了同步 React 19.3.0、升級 Metro 與 Hermes 之外，最受關注的改動落在 iOS 與 CocoaPods 端新增的兩個可選開關，讓開發者能提前編譯移除舊架構的模組與元件互通層。

React Native 0.88 是什麼？

React Native 0.88 於 2026 年 10 月 15 日發布，屬非破壞性更新，同步 React 19.3.0 與新版 Hermes，並新增移除舊架構互通層的可選開關。

此版本建立在 2015 年 1 月建立的儲存庫之上，由 Meta 主導開發，並由 React Foundation 承接社群治理。框架的定位是以 React 撰寫介面，再交由原生程式碼渲染，因此元件的行為會對應各平台的原生介面，而非在網頁視圖內模擬。

版本編號雖為小幅更新，改動範圍卻橫跨 JavaScript 執行環境、建置工具與原生橋接層。變更清單涵蓋事件系統、文字樣式、型別宣告、Android 掛載流程與 iOS 生命週期支援，並在結尾明確標示 0.88 為非破壞性版本，這一點在多項被回退的改動中可以看出。

React Native 0.88 有哪些核心更新？

核心更新有四：事件目標 API 開放至原生視圖引用、文字元件支援物件語法字體設定、Android 掛載流程以旗標切換，以及 Metro 與 Hermes 版本同步。

事件系統是本次最明顯的語言層調整。開發者現在可在原生視圖引用上使用命令式的 EventTarget 介面，包括新增監聽、移除監聽與主動派發事件，目前於 canary 通道提供。同一條路徑上，網路層也修正了重複標頭依規範附加的行為，並保留緩衝與空白的 WebSocket 訊框。

文字樣式支援物件語法的字體變化設定，涵蓋文字與輸入框元件，並在 iOS 與 Android 同步實作。Android 端另新增以旗標控制的掛載協調器拉取模型，程式碼路徑預設關閉；iOS 端則加入 SceneDelegate 生命週期支援，並在影像資源上改用資產目錄管理。

回退與清理同樣構成這版的主要內容。儲存庫將 TurboModules 的陣列緩衝改動回退，恢復 Objective-C 模組方法的指標簽章，理由是 0.88 屬非破壞性版本，原改動會令已採用該功能的模組無法編譯。另有三項樣式屬性移除實驗前綴，Android 端則將輸入配件視圖標記為棄用。

Legacy 架構退場這次代表什麼？

代表舊架構移除進入可驗證階段。iOS 與 CocoaPods 端新增兩個互通層移除開關，現時預設關閉，官方明言未來會改為預設啟用。

兩個開關分別對應模組互通與元件互通，允許專案在 CocoaPods 與 Swift 套件管理器中提前選用。啟用後，原生端會編譯移除模組註冊函式，並跳過靜態模組註冊流程。官方在變更說明中指出，兩者現時預設關閉，但會於未來版本成為預設值，因此這版可視為遷移前的驗證窗口。

命名層的清理同步進行。多個核心元件，包括活動指示器、模態主機視圖、下拉刷新視圖、安全區域視圖與開關，不再於視圖設定中回報帶有舊前綴的名稱。Android 端亦將新架構旗標在片段層標記為棄用，顯示舊路徑正逐步縮減可依賴的表面積。

開發者工具與除錯體驗有什麼改進？

React Native DevTools 本次可在實驗通道擷取應用截圖，並在預覽通道檢查 WebSocket 事件；網路面板同時開放第三方網路堆疊回報事件的不穩定介面。

截圖能力同時對人與代理開放。使用者與自動化代理都可透過協定指令取得畫面，官方說明此功能先在實驗通道提供，並附帶效能截圖的實驗支援。WebSocket 事件的檢查則在預覽通道推出，補上網路面板過去只覆蓋請求與回應的缺口。

Android 端的網路觀測改為可擴充設計。第三方網路堆疊可透過不穩定介面回報事件，令自製網路層也能進入開發者工具的時間軸。同一版本另將應用名稱與版本加入預設請求標頭，與 iOS 行為對齊；建置工具則將 Metro 最低版本提高到 0.87.1，確保新舊專案解析到相同版本。

如何開始使用 React Native 0.88？

最直接的方式是執行 npx create-expo-app 建立新專案，官方視 Expo 為生產級框架；既有專案可升級套件版本，並視需要逐步開啟移除舊架構互通層的開關。

官方文件建議以框架起步，並將 Expo 列為首選，理由是其提供檔案式路由、標準原生模組函式庫與完整工具鏈。單一指令即可建立專案，適合先確認開發流程與原生模組相容性。若需在既有應用中局部導入，官方另提供與現有應用整合的指引。

升級路徑則以套件版本為主。專案可先將框架依賴指向 0.88.0，再處理 Metro 最低版本與建置工具快取的調整；採用原生依賴的專案需留意 iOS 端的標頭框架拆分成獨立套件。第三方原生模組可在官方目錄中檢索相容性，再決定是否同時啟用互通層移除開關。

React Native 與其他跨平台框架有何不同？

差異在渲染路徑。框架的原語直接對應各平台原生介面，手勢、文字縮放與無障礙行為與原生應用一致，而非以網頁視圖模擬，運算則由 JavaScript 引擎與原生模組分擔。

這條路線的取捨相當明確。介面交由平台原生元件處理，令應用在字體縮放、輔助功能與系統手勢上較貼近使用者預期；同時，開發者仍可撰寫原生模組，以同步且具型別的方式呼叫平台程式碼，兼顧跨平台重用與個別平台的深度整合。

生態規模是另一項優勢。官方維護的目錄收錄數千個社群函式庫，涵蓋導航、動畫、儲存與硬體存取；架構上則以新架構的渲染器與模組系統取代舊橋接，並保留樹外平台機制，讓其他作業系統的實作以獨立專案形式存在。

總結：React Native 0.88 適合什麼團隊？

適合以單一程式碼庫維護 Android 與 iOS 應用的團隊，也適合正評估舊架構遷移時程的專案；若應用高度依賴平台獨有介面或需極致圖形效能，仍須個別評估。

這版的重要性不在於新增單一殺手級功能，而在於把舊架構的退場排程具體化。兩個互通層開關雖預設關閉，但官方已預告未來版本將改為預設啟用，等於向仍在舊路徑上的專案發出時程信號；開發者工具在截圖與網路觀測上的補強，也降低了遷移期間的除錯成本。

採用前仍有兩項現實條件需要衡量。其一，採用原生依賴的專案必須同步處理建置設定與標頭框架的變動，升級不會只是改一行版本號；其二，框架的維護主力集中在少數貢獻者手上，社群函式庫的相容性仍需逐項驗證。把版本節奏與自身依賴盤點清楚，才能在遷移過程中保持可控。
