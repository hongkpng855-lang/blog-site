Block 發表 Dessa 語音模型：全雙工對話可本地跑

2026年10月26日 00:04 • 閱讀時間 2 分鐘 • Eric Chan • 來源：TechCrunch

Block 於二零二六年十月二十三日發表語音模型 Dessa，採全雙工架構，說話與聆聽可同時進行。模型以人類語音直接訓練，情感與停頓由模型本身產生，不經文字中介。官方稱可在 MacBook M4 Max 等消費級機器上本地運行。目前未公開發布，只邀請安全研究人員測試。

Dessa 是什麼？

Dessa 是 Block 研究院開發的全雙工語音對語音模型，以人類語音直接訓練，不依賴文字作為中介，官方稱可在消費級顯示卡上本地運行。

Block 是 Jack Dorsey 旗下的金融科技公司，主要業務包含 Square 支付與商家工具。Dessa 出自公司內部的 Sicher 研究實驗室，與支付產品線的關係並非直接，但方向清楚：把語音互動的成本與延遲壓到可以在門市與手機上大量使用。

官方的定位用詞相當強硬，稱其為「最真實的全雙工語音模型」。這類自我評價需要打折看待，但背後有一項可以查證的差異：多數語音產品的流程是先做語音辨識、再交給語言模型思考、最後用語音合成輸出，而 Dessa 把三步併成一步。

全雙工語音模型與傳統語音助手有何不同？

傳統助手依序完成聆聽、辨識、生成與朗讀，用戶必須等對方說完才能開口；全雙工模型同時處理輸入與輸出，可在對方說話時以點頭聲、短句或停頓回應。

對講機式的對話是現行語音助手最明顯的破綻。使用者講完一句，系統開始轉錄，接著等待模型生成，最後播放合成語音，整個過程有明確的空檔。真實對話不是這樣運作，人在聆聽時會以「嗯」、「對」這類短音回應，也會在對方停頓的位置接話。

全雙工把這層節奏納入模型設計。輸入與輸出不再是先後關係，而是同時進行的兩條流。技術上的難點在於模型必須判斷何時該開口、何時該閉嘴，否則會出現自己蓋過對方說話的情況，這在電話客服場景屬於致命錯誤。

OpenAI 今年較早推出的 GPT-Live 同樣採全雙工架構，兩者的差異在訓練資料與部署方式。GPT-Live 依附雲端服務，Dessa 主打本地執行，這個選擇直接影響延遲、隱私與單位成本。

Dessa 為什麼捨棄文字中介？

官方認為文字會丟失語調、節奏與情緒等大量資訊。以文字驅動語音生成，聲音聽起來會不自然；直接以語音訓練，模型可從對話資料中學習情感表現。

Block 在官方部落格的說法相當直白：現行語音人工智慧把人的聲音轉成文字，過程中丟掉了文字無法承載的大量資訊，結果是世界上最強的模型聽不出對方的情緒。這段話指向一個具體的工程選擇，而非單純的宣傳語言。

問題的核心在於文字驅動的語音合成。ElevenLabs 第四代與 Fish Audio 的 Drama 3 這類模型，會用情緒標籤去控制語音的表現，例如在輸入文字前加上標記，指示模型用疲累或興奮的語氣朗讀。標籤由誰決定、標得準不準，取決於上游的文字模型。

Dessa 把情緒寫進模型權重。訓練資料全部是人類語音，包含笑聲、嘆氣、猶豫與句中停頓，模型在這些訊號上學會對應的表現方式。官方示範的一段對話中，代理提到自己工作疲累，聲音也同步顯得疲倦。至於這種情感是否仍由某種隱含標籤操控，Block 未明確交代。

在消費級硬件運行需要什麼條件？

官方稱 MacBook M4 Max 或更高規格即可本地執行，訓練則使用單一 NVIDIA 顯示卡機櫃。具體記憶體需求與推論延遲未公布，只知屬消費級門檻。

本地執行的意義不只是省下雲端費用。語音資料包含聲紋、語氣與背景聲，這些內容一旦上傳就難以收回，對於處理醫療、金融或家庭對話的應用，資料留在裝置上是採用與否的關鍵條件。

Block 提到訓練使用單一 NVIDIA 顯示卡機櫃，這個規模在語音模型領域屬於中型。訓練成本低意味著迭代速度快，也意味著同類團隊有機會複製這條路線，這點比模型本身的表現更值得留意。

官方未公布推論所需的記憶體、每秒可處理的音訊長度與實際延遲數據。從「MacBook M4 Max 或以上」這個描述推斷，門檻落在高階筆記型電腦的統一記憶體容量區間，並非所有現役手機都能執行。真正要落地到終端裝置，還需要量化與裁剪。

情感表達如何內建在模型之中？

模型直接從人類語音學習情緒訊號，包括笑聲、嘆氣、停頓與語速變化，輸出時同步產生對應表現，不靠外部情緒標籤逐句指定。

官方示範涵蓋幾種情境。一段對話中，代理表示自己下班後很累，聲音同時變得低沉而緩慢；另一段是團隊成員與代理玩猜謎遊戲，代理在猜中時的語氣帶有明顯的興奮。這些表現若由文字標籤驅動，需要逐句標注，維護成本相當高。

研究員 Ragavan Thurairatnam 在社群平台上的說法更直接，稱這是語音領域的 GPT-3 時刻，理由是模型完全以語音訓練，且可在消費級顯示卡上執行。這類比較屬於個人判斷，但反映團隊對路線的信心。

值得保留的部分是評估方法。目前公開的示範都是精選片段，沒有客觀測試集的分數，也沒有與同類模型的盲測比較。聲音像人這件事本身難以量化，主觀感受與實際可用性之間仍有距離。

語音代理有什麼安全風險需要評估？

高度擬人的語音可被用於冒充真人詐騙。Block 因此未開放公眾使用，先邀請安全研究人員測試，蒐集語音代理能否騙過接聽者的實證。

這項安排值得肯定。過去兩年，語音克隆相關的詐騙案件在多個地區出現，手法通常是短暫取得目標親友的錄音，再合成一段求助通話。當模型能自行產生嘆氣、猶豫與情緒轉折，辨識難度會進一步上升。

Block 把測試對象限定在安全研究人員，說明團隊意識到風險與能力同時放大。官方未公布測試框架、評估指標與後續開放條件，這三項缺口令外界難以判斷安全把關的實際強度。

對企業採用者而言，這代表短期內無法在生產環境依賴此模型。即使未來開放，部署時仍需自行設計身分驗證、通話錄音與異常偵測機制，單靠模型本身無法解決冒充問題。

Block 的商業盤算為何？

Block 的主要業務是商家支付工具，Square 已用語音處理點餐。自有模型在裝置端運行，可降低每次呼叫的雲端成本，並支撐更多門市與消費者場景。

成本結構是關鍵。語音互動的單位成本高於文字，因為音訊的取樣率高、傳輸量大，而且必須維持低延遲。若每次對話都要呼叫外部供應商的模型，規模越大毛利越薄。把模型放進裝置，邊際成本轉為硬件折舊。

Square 現有的語音點餐功能說明場景已經存在。門市環境嘈雜、網路品質不穩，本地推論在這類條件下的優勢更明顯。同一套能力亦可延伸至得來速、預約與客服分流。

外部環境同時提供了壓力。Canva 在同一個月發表自家圖像模型，理由同樣是節省 API 成本並取得品質控制權；Anthropic 與 OpenAI 則持續把能力集中到少數旗艦模型。垂直整合與水平整合兩條路線正在同時發生。

香港與亞洲市場可以如何使用？

現階段無法使用，模型未公開發布。本地執行的路線對粵語與華語市場有意義，前提是訓練資料涵蓋這些語言，官方未說明多語言支援範圍。

語言覆蓋是實際落地的前提。官方強調訓練資料全部是人類語音，但未列出語言比例。若以英語為主，粵語的聲調與中英夾雜的說話習慣會是明顯挑戰。這類模型常見的失敗模式是把聲調誤判為情緒，或在中英混用時出現語序錯亂。

對本地的開發者而言，可觀察的是架構而非產品。全雙工、語音對語音、本地推論這三個設計選擇，正在成為下一代語音應用的共同基準。開源社群已有若干全雙工實驗，門檻會隨工具鏈成熟而下降。

採購與法規層面亦需留意。若企業打算把客服通話交給本地模型處理，資料保存位置、錄音同意與跨境傳輸規範仍須逐一確認，硬件在手並不自動等於合規。

出處連結有哪些？

原始報導刊於 TechCrunch，日期為二零二六年十月二十四日；Block 官方部落格與研究團隊的社群貼文提供示範音訊與技術說法。

主要來源是 TechCrunch 的報導 https://techcrunch.com/2026/10/24/blocks-new-voice-model-sounds-eerily-human/，作者為 Ivan Mehta。文中引述 Block 官方部落格、Jack Dorsey 與研究員的社群貼文，並附多段示範對話。

Block 官方部落格載有產品說明與示範音檔，內容以體驗描述為主。技術細節如模型參數規模、訓練資料時長與評測方法，目前未見公開文件。

總結：Dessa 適合什麼場景？

現階段只適合研究與概念驗證。待公開發布後，最合適的場景是需要低延遲、資料留在本地的語音互動，例如門市點餐、客服分流與輔助溝通。

Dessa 的價值在於把語音互動的兩個瓶頸同時鬆開：一是文字中介造成的情感流失，二是雲端呼叫帶來的延遲與成本。這兩個問題困擾語音產品多年，Block 提出的解法具備工程上的說服力。

需要保留的部分同樣清楚。評測數據缺席、語言覆蓋未明、公開發布時間未知，三項都是採用前必須確認的條件。對於需要即時導入語音功能的團隊，現有雲端方案仍然務實；對於研究與產品探索，Dessa 的方向值得持續追蹤。
