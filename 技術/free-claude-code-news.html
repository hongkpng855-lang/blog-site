free-claude-code 開源：1.3B 免費 Token 統一代理層

Eric Chan

IT 顧問・實測主義者

2026年10月07日 02:00 • 閱讀時間 3 分鐘

來源：GitHub

內容創作者： https://github.com/Alishahryar1/free-claude-code

在 GitHub 累積 56,795 顆星標的開源專案 free-claude-code（社群簡稱 FCC），是一套運行於開發者本機的 AI 編程代理代理層。它把 59 家模型供應商與 11 款編程代理整合到同一個入口，宣稱每月可提供超過 13 億個免費 Token，並內建配額感知的自動回退機制與終端輸出壓縮。專案以 Python 撰寫，自 2026 年 1 月建立以來已累積 1,168 次提交與 9,063 次複製，最新版本為 v6.10.2。

free-claude-code 是運行於本機的開源代理層，整合 59 家供應商與 11 款編程代理為單一入口，每月提供逾 13 億免費 Token，並內建自動回退與輸出壓縮。

AI 編程代理的成本結構在近一年出現明顯變化。模型能力持續提升，但每次調用的計費方式也從訂閱制逐步轉向按 Token 計價，開發者在選擇工具時，除了能力之外還必須考慮配額與單價。FCC 切入的正是這個縫隙：它不自行訓練模型，也不提供模型本身，而是把自己放在客戶端與供應商之間，扮演一個可切換、可回退、可壓縮的通道。

free-claude-code 是什麼？

free-claude-code 是本地代理與管理介面，讓開發者用同一組設定，在 Claude Code、Codex、Cline 等 11 款編程代理之間切換供應商與模型。

依照專案說明，FCC 的定位是「一個模型目錄，十一款編程代理」。它在本機啟動一個伺服器，並提供網頁版管理介面，開發者可在此填入各供應商的 API 金鑰、選擇模型、設定回退順序，然後透過 fcc-claude、fcc-codex、fcc-opencode 等啟動指令，讓原本的編程代理改為連向 FCC。

專案由 GitHub 帳號 Alishahryar1 主導，建立於 2026 年 1 月 28 日，主要程式語言為 Python，佔程式碼庫約 796 萬位元組，其餘為 JavaScript、PowerShell 與 Shell。安裝方式分為 macOS／Linux 的 shell 腳本與 Windows 的 PowerShell 腳本，啟動後由系統匣或選單列圖示進入管理頁面。

free-claude-code 整合了哪些供應商與代理？

FCC 支援 59 家供應商與 11 款編程代理，涵蓋 NVIDIA NIM、OpenRouter、Groq、DeepSeek、Ollama 等雲端與本機後端。

供應商清單是 FCC 最直接的賣點。文件列出 59 家可設定的後端，包含雲端推論服務如 NVIDIA NIM、Groq、Cerebras、Together AI、DeepInfra、Fireworks AI、Novita AI，區域供應商如 Alibaba Cloud、QwenCloud、Kimi API、MiniMax、Z.ai，雲端平台如 Amazon Bedrock、Google Vertex AI、Azure OpenAI、Cloudflare Workers AI，以及可在本機執行的 Ollama、LM Studio 與 llama.cpp。

客戶端一端同樣採取廣度策略。已支援的編程代理包括 Claude Code、Codex、Pi、OpenCode、Cline、Hermes、DeepSeek Harness、Grok Build、Muse Code、Aider 與 VS Code Chat，多數以獨立啟動指令的形式提供。使用者亦可在瀏覽器內開啟原生 Codex 工作階段，選擇本機資料夾後直接執行，並在同一工作階段中切換供應商與模型。

free-claude-code 的架構有什麼特別之處？

FCC 以本機代理伺服器為核心，向上對接各家編程代理，向下路由至 59 家供應商，並在通道中插入配額探測、回應快取與輸出壓縮，讓代理本身不需感知底層變化。

架構上，FCC 屬於本地反向代理的設計。編程代理原本直接呼叫模型供應商的端點，改成先呼叫本機的 FCC 伺服器，再由 FCC 依設定轉發。這種做法的好處是上層工具無須逐一適配供應商差異，包含認證方式、模型命名規則與 API 格式。

專案文件提到五項不呼叫供應商即可完成的優化，涵蓋配額探測、指令前綴偵測、標題生成、建議內容與檔案路徑處理。這類處理看似細節，實際上直接影響無效請求的數量；在按 Token 計價的模式下，任何一次多餘的往返都等於實際成本支出。

free-claude-code 如何降低 Token 消耗？

FCC 可選配 RTK 過濾終端輸出，官方稱可減少最多九成終端輸出 Token；另以配額探測、指令前綴偵測與回應快取等五項優化，在不呼叫供應商的情況下完成處理。

在編程代理的實際使用中，終端機的輸出往往是 Token 消耗的主要來源。測試失敗的堆疊追蹤、套件安裝的完整日誌、目錄遞迴的清單，都會被完整送進模型上下文。FCC 提供可選的 RTK 整合，對常見指令輸出進行過濾，官方說明最高可減少九成的終端輸出 Token。

另一項設計是供應商中斷時的續行能力。FCC 在重試耗盡之後，會自動改用清單中的下一個模型，而不需要重新啟動該次對話。文件同時提醒，一次失敗的請求可能在成功之前觸及並消耗多個供應商的配額，因此回退清單的順序設定需要謹慎。

free-claude-code 的生態與授權有什麼風險？

FCC 在 README 聲明與 Anthropic 無關聯，並以 AGPL v3 授權釋出。AGPL 對以網路服務提供修改版本設有額外義務，商用整合前需確認合規。

專案在 README 開頭即以斜體聲明，其為獨立開源專案，與 Anthropic 無關聯亦未獲其背書，並指出 Claude 與 Claude Code 為 Anthropic 的商標。這種寫法在整合第三方付費服務的專案中並不少見，主要目的是劃清品牌關係，避免使用者誤解為官方工具。

授權條款是另一個需要留意的環節。GitHub 標示 FCC 的授權狀態為 NOASSERTION，而 README 徽章與 LICENSE 檔案指向 AGPL v3。AGPL 對以網路服務形式提供修改後版本的行為設有額外義務，若企業計畫將 FCC 包裝為內部平台或對外服務，需先確認條款適用範圍。此外，專案並未提供樹狀授權明細，第三方元件的授權相容性亦需自行核對。

供應商端的使用條款同樣值得注意。FCC 文件說明其遵循各供應商條款，並在整合不再被允許時移除對應項目，但目前仍標示 OpenCode 2 的 RTK 整合暫不可用。這反映此類聚合層必須持續跟進上游政策變化。

如何快速開始使用 free-claude-code？

macOS／Linux 可執行官方 shell 安裝腳本，Windows 使用 PowerShell；安裝時選擇編程代理，啟動後在管理介面填入供應商金鑰即可。

安裝流程以單行指令為主。macOS 與 Linux 使用者可執行 curl -fsSL 取得安裝腳本後交由 sh 執行，Windows 使用者則透過 PowerShell 的 irm 指令載入腳本。安裝過程中可勾選需要的編程代理，並選擇是否一併安裝 RTK。

啟動之後，管理介面會在瀏覽器開啟。使用者需在其中建立至少一組供應商設定，例如在 NVIDIA NIM 頁面貼上 API 金鑰、選擇模型後點選套用。若需保護本機代理，可在管理介面啟用代理驗證並設定存取權杖。文件亦說明，若選擇以 ChatGPT 訂閱或 GitHub Copilot 訂閱作為來源，需改用 OAuth 連線方式，並在連線完成後重新啟動已在執行的代理。

free-claude-code 適合哪些開發者？

FCC 適合已在多個編程代理與供應商之間切換、且對 Token 成本敏感的開發者；若僅使用單一官方代理與單一供應商，額外引入代理層的效益有限。

FCC 解決的是設定碎片化與成本控制兩個問題。當開發者同時使用 Claude Code、Codex 與 Cline，並在不同供應商之間比較效果時，逐一維護設定檔與金鑰相當耗時；FCC 把這些設定集中到一處，並允許在同一介面切換模型。

對成本敏感的團隊，配額感知的自動回退與輸出壓縮具備實際價值，尤其在使用免費額度為主的配置中，能延長可用時間。相對地，若使用者只需要單一代理搭配單一付費供應商，額外一層代理會增加排查問題的環節，效益並不明顯。

常見問題有哪些？

free-claude-code 的常見疑問集中在費用、代理支援範圍、安全性與授權條款，以下整理四個問題，答案以專案 README 與公開儲存庫資訊為準。

free-claude-code 需要付費嗎？

專案本身免費且開源。使用者須自行向各供應商申請金鑰，免費額度由供應商決定；若選用付費供應商，費用直接向其結算。

支援哪些編程代理？

目前支援 Claude Code、Codex、Pi、OpenCode、Cline、Hermes、DeepSeek Harness、Grok Build、Muse Code、Aider 與 VS Code Chat 共 11 款。

API 金鑰會不會離開本機？

FCC 以本機代理伺服器形式運作，設定存放於本機並由管理介面填寫。專案另提供代理驗證選項，可為本地端點加上存取權杖。

可以商用或整合進內部平台嗎？

README 與 LICENSE 指向 AGPL v3，該授權對以網路服務形式提供修改版本設有額外義務。商用前建議先確認條款適用範圍並核對第三方元件授權。

總結：free-claude-code 對代理層的意義是什麼？

FCC 反映 AI 編程工具正走向分層：模型、代理與路由各自獨立，路由層成為控制成本與切換供應商的位置，並同時承擔上游條款變動的風險。

FCC 在短短數月內累積 56,795 顆星標與 9,063 次複製，反映開發者對「不打斷工作流程的模型切換」有明確需求。過去要在不同供應商之間比較效果，往往需要重新設定代理、重啟工具，甚至中斷當前對話；把這層差異收進本地代理之後，切換成本被壓縮到設定層級。

這種分層也帶來新的依賴。路由層必須持續跟進 59 家供應商的 API 變動與使用條款，任何一端收緊政策，都可能在短時間內影響可用清單。對使用者而言，FCC 的價值取決於維護頻率與上游關係；對整體生態而言，它則說明在模型能力逐漸趨同之後，控制成本與整合體驗會成為新的競爭位置。
