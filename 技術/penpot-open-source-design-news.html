Penpot 開源：Figma 的自架替代方案

Eric Chan

IT 顧問・實測主義者

2026年10月10日 14:00 • 閱讀時間 3 分鐘

來源：GitHub

內容創作者： https://github.com/penpot/penpot

Penpot 是一套開源設計與原型協作平台，在 GitHub 累積 60,851 顆星標與 4,192 次複製，採用 MPL-2.0 授權，主要語言為 Clojure。它以瀏覽器為主要工作環境，允許團隊部署在自有伺服器，並以 SVG、CSS、HTML 與 JSON 等開放標準交換與保存設計內容，被視為 Figma 在自架與資料自主方向上最主要的替代選項。專案最新版本 2.18.3 於 2026 年 10 月 6 日發布。

Penpot 是什麼？

Penpot 是一套開源設計與原型平台，以瀏覽器為主要工作環境，支援在自有伺服器部署，並以 SVG、CSS、HTML 與 JSON 等開放標準保存設計內容。

Penpot 的定位是面向產品團隊的開源設計平台，涵蓋介面設計、原型製作與設計系統管理。專案由西班牙軟體公司 Kaleidos 主導，於 2015 年底在 GitHub 建立，其後逐步發展為可完整自架、且與現有前端工具鏈相容的協作環境。它同時取得數位公共產品（Digital Public Good）認證，反映其開放與公益取向。

與多數設計工具不同，Penpot 把「設計基礎設施的主導權」視為核心價值。團隊可選擇使用官方雲端服務，也可將整套系統部署在自家伺服器，讓設計檔、使用者資料與協作記錄完全留在組織內部。這項安排對受合規與治理要求約束的金融、醫療與公部門團隊尤其關鍵。

目標受眾包括產品設計師、前端工程師與需要跨部門協作的產品團隊。由於設計以程式碼可讀的形式表達，工程端能直接取用樣式與結構，減少設計交付過程中反覆對齊的成本。

Penpot 有哪些核心技術亮點？

它將設計以程式碼形式表達，原生支援 Design Tokens、CSS Grid 與 Flex 版面，並提供 MCP 伺服器與外掛系統，讓設計與開發共用同一份來源。

最關鍵的設計取向是「設計即程式碼」。Penpot 以開放標準保存檔案，設計成果可對應到 SVG、CSS 與 HTML，工程師在檢視模式中能直接取得可用的樣式與結構，不必再逐項換算數值。這種做法讓設計稿與實作之間少了一層人工翻譯，也讓版本差異更容易被工具比對。

設計系統的支援是另一項重點。Penpot 原生提供 Design Tokens、元件（Components）與變體（Variants），讓顏色、間距與字級以單一來源管理，並在不同專案與平台之間保持一致。搭配 CSS Grid 與 Flex 版面，團隊在設計階段即可模擬真實的響應式行為，而非等到實作階段才發現斷點問題。

近年加入的 MCP 伺服器則把設計與 AI 工作流程接上。透過模型情境協議，外部工具可讀取設計檔的結構與資料，雙向同步設計與程式碼；官方亦提供開放 API、外掛系統與 Webhook，讓工作區具備可程式化能力，支援自動化與既有工具鏈整合。

Penpot 如何部署與開始使用？

Penpot 同時提供官方雲端服務與自架部署，自架可透過 Docker、Kubernetes 或 Elestio 等方式安裝，部署後以瀏覽器操作。

部署路徑相當彈性。官方提供可即時註冊使用的雲端版本，讓團隊在不維運伺服器的前提下先試用；若需自架，官方文件列出 Docker、Kubernetes 與 Elestio 等多種安裝方式，並整理自架環境的組態與升級指引。這意味著從個人到中大型組織，都能依自身維運能力選擇合適起點。

實際使用完全在瀏覽器內進行。使用者建立檔案後即可進行即時協作，多人同時編輯同一份設計，並透過註解在畫布上討論。對於習慣離線或需要與現有 CI 流程整合的團隊，Penpot 亦提供 API 與存取權杖，可將設計資產納入自動化流程。

需要額外治理能力的組織另有企業方案。Penpot Enterprise 提供集中式管理主控台、進階權限設定與單一身分驗證（SSO），同時支援雲端與自架環境，讓大型團隊在保留開源基礎的同時取得企業級控制。

Penpot 與 Figma 的差異在哪裡？

Penpot 以 MPL-2.0 開源並支援自架，設計檔以開放標準保存；Figma 為專有雲端服務。兩者最大差異在資料自主、授權成本與是否受供應商綁定。

最直接的差異在授權模式與資料位置。Figma 是專有的雲端服務，設計檔存放於供應商平台；Penpot 則以 MPL-2.0 釋出原始碼，可部署在自有環境，資料主導權回到團隊手上。對於必須確保設計資產不外流，或需要通過內部資安審查的組織，這項差異具有决定性。

第二項差異在檔案的互通性。Penpot 以開放標準與 JSON 結構描述設計內容，必要時可轉出為程式碼或與版本控制流程並行；Figma 生態則以自家外掛與社群資源見長，外掛數量與既有工作流程的慣性明顯領先。

成本結構亦不同。自架版本僅需負擔伺服器與維運人力，企業版則以治理與稽核能力計價；Figma 的授權以席位訂閱為主。對長期使用、人數眾多的團隊而言，兩種模式的總持有成本差距會隨規模放大，選擇時需一併評估遷移成本與團隊既有習慣。

Penpot 的開源生態與社群發展如何？

Penpot 由 Kaleidos 主導開發，社群貢獻集中於外掛、翻譯與範本，主要貢獻者包括 niwinz、Alotor 與 superalex，生態透過論壇持續擴大。

專案的開發節奏穩定。社群提交統計顯示，長期貢獻者以 niwinz、Alotor、superalex、hirunatan 與 EvaMarco 為主，程式碼橫跨 Clojure、Rust、JavaScript 與 TypeScript，兼顧後端服務、前端介面與渲染引擎。版本更新頻繁，2.18.0 於 9 月 23 日發布後，10 月初已推出 2.18.1、2.18.2 與 2.18.3 三個修正版本。

外掛與範本是社群擴充的主要方式。官方設有外掛市集 Penpot Hub，涵蓋設計輔助、資料串接與自動化工具；社群亦持續貢獻多語言翻譯、函式庫與版面範本。2.18 系列加入線與箭頭繪圖工具、工作區內註解管理，以及把繪圖工具整併為彈出選單，同時修正多項外掛 API 與 MCP 整合問題。

近期版本亦處理安全與權限細節。2.18.3 修補了匯入檔案時未淨化 SVG 內容的問題，以及已移除的團隊成員仍保留檔案存取權的缺陷。這類修正顯示專案在功能推進之外，也持續收緊自架環境的安全邊界。

Penpot 的統計數據與授權條件為何？

Penpot 累積 60,851 顆星標與 4,192 次複製，以 MPL-2.0 授權開放，程式碼以 Clojure 為主，另混用 Rust 與 TypeScript。

授權條款是採用評估的關鍵。MPL-2.0 屬寬鬆型開源授權，允許使用、修改與再散布，僅要求在衍生檔案層級保留原始碼與授權聲明，不像 AGPL 般要求整體服務開源。這讓企業可安心自架與客製，而不必擔心商業模式受到傳染性條款限制。

技術堆疊分布反映專案的工程取向。儲存庫以 Clojure 為最大宗，負責後端服務與核心邏輯；Rust 用於高效能渲染與 WASM 模組；JavaScript、TypeScript 與 SCSS 構成前端介面。專案建立於 2015 年 12 月，至今仍維持每日提交，目前累積超過 5,100 個未結議題，顯示社群參與活躍。

總結：Penpot 適合什麼團隊？

Penpot 適合重視資料自主、需要自架與合規控管的產品團隊；若偏好原生桌面效能或既有 Figma 外掛生態，轉換成本仍需評估。

Penpot 的價值在於把設計工具從訂閱服務轉為可掌握的基礎設施。開放標準讓設計檔不被單一供應商鎖定，自架部署讓資料留在組織內部，Design Tokens 與 MCP 整合則讓設計與程式開發使用同一份來源。對於需要長期累積設計系統、並同時面對合規要求的團隊，這些特性構成明確的採用理由。

選用前仍需衡量現實條件。自架意味著要自行處理部署、升級與備份，維運成本不可忽略；若團隊已深度依賴 Figma 的外掛與社群資源，或高度重視原生桌面應用的效能體驗，遷移所需的時間與培訓投入也應納入評估。適合與否，最終取決於團隊對資料主導權與維運負擔之間的取捨。
