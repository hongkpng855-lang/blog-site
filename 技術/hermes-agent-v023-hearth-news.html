Hermes Agent 0.23：桌面工作台搬進瀏覽器

2026年11月09日 08:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/NousResearch/hermes-agent

Hermes Agent 是 Nous Research 開發的開源 AI 代理，於十一月五日發布 v0.23「爐火版本」，累積 26.1 萬顆星標。此版把桌面工作台改由自家閘道以瀏覽器供應，單一閘道接管每段會話，各介面共用同一份歷史紀錄。

專案以 Python 撰寫、採 MIT 授權，自 2025 年 7 月建立以來已發布 47 頁版本記錄。自 v0.22.0 以來的這個週期合計約 10,080 次提交、1,950 個合併請求、8,720 個檔案變更與 666 位貢獻者，關閉約 850 個議題。

Hermes Agent 是什麼？

Hermes Agent 是 Nous Research 開發的開源自主代理，具備技能自動建立、跨會話記憶與多後端執行能力，採 MIT 授權，可部署於單機或雲端。

專案的定位是「會成長的代理」。它在完成複雜任務後自行建立技能，於後續使用中持續修訂，並主動提醒自己把關鍵知識寫入持久記憶。會話以全文索引儲存，配合語言模型摘要，讓數月前的對話仍可被檢索。

執行層面提供六種內建終端後端，涵蓋本機、容器、遠端主機與三種無伺服器環境，另可透過外掛接入其他沙箱方案。這個設計讓同一個代理可以由筆記型電腦搬到價格低廉的虛擬主機，或在閒置時休眠以壓低費用。

v0.23「爐火版本」帶來了哪些關鍵變化？

此版本把桌面工作台改為瀏覽器供應、以單一閘道統一會話、加入外掛自動更新與付費工具花費上限，並把內建技能由 58 項精簡至 44 項。

發布說明用了「爐火」的比喻：上一個版本 v0.22 處理的是把人送進門檻，這一個版本處理的是把火升起來。具體落點集中在四處。工作台由自家閘道以網頁形式供應；會話所有權收歸單一閘道；外掛加入自我更新機制與付費工具的成本控制；核心功能外移成外掛，內建技能同步精簡。

規模數字本身也構成新聞。自 v0.22.0 以來，這個週期累積約 10,080 次提交、1,950 個合併請求、8,720 個檔案變更，淨增約 52 萬行程式碼，關閉約 850 個議題。

為什麼要把桌面工作台搬進瀏覽器？

新的 Webapp 把完整桌面工作台由使用者自家閘道供應，任何瀏覽器均可開啟同一批會話、群組聊天、外掛與設定，出廠預設關閉。

過去桌面應用綁定在本機執行，換一台電腦就等於換一個環境。v0.23 新增的 Webapp 把同一套介面改由閘道輸出，因此在同網段的其他裝置、或加上登入驗證的公開網址，都能看到完全相同的會話清單、群組聊天、外掛與設定。Docker 映像與 Nix 套件同時附帶這項能力。

這項功能出廠時是關閉的，需在設定開啟 webapp.enabled，或在設定介面啟用 Web Access 才會生效。這個預設值值得留意：一旦對外開放，等同把具備工具執行權限的代理介面暴露在網路上，登入驗證與網路邊界必須先確認。

單一閘道接管所有會話解決了什麼問題？

過去終端、桌面、編輯器與機器人各跑一份代理，同一段對話可能被寫兩次或遺失；現在一台機器只有一個閘道持有全部會話，各介面只作為客戶端接入。

舊架構下，命令列、文字介面、桌面應用、編輯器整合、通訊機器人與排程各自啟動自己的代理副本，並對同一段對話各自寫入。結果是訊息重複出現，或在介面切換時整段消失。這類問題在單人使用時只是煩人，在多介面並行時會直接破壞對話的一致性。

新架構把會話所有權收歸單一閘道，其餘介面一律作為客戶端接入，因此同一段對話只有一個佇列與一份歷史。排隊中的提示也可以在桌面端先行編輯或改變方向，而不會在背景被執行兩次。這一輪同時修復了架構改動帶來的副作用，包括斜線命令、重試、審查與用量顯示在不同介面上的失效。

外掛目錄從 600 增至 1,050 有什麼意義？

外掛目錄由約 600 個增至逾 1,050 個，新增廠商自建驗證等級，並支援一次更新全部外掛，會破壞現有設定的更新會被暫緩套用。

數量增長之外，機制變化更值得注意。hermes plugins update 可一次更新全部外掛，另有一個需自行開啟的自動更新開關，覆蓋目錄外掛與 Git 來源外掛。系統會在更新可能破壞現有設定時暫緩套用，把「更新後開不起來」這類事故擋在前面。

目錄新增的驗證等級，用來標示由廠商自行開發的外掛，為使用者提供一層來源判別。與此同時，核心開始瘦身：瀏覽器自動化的舊外掛、MCP 伺服器模式、代理匯入工具與 Singularity 支援全部移出核心，改由外掛按需安裝；新加入的官方外掛則包括文字與圖像轉三維模型、音樂與音效生成、以及逆向工程工具。

付費工具的花費上限如何運作？

付費的 MCP 工具可自行宣告每次呼叫的價格，審批畫面會顯示單次費用與該對話累計金額，超過上限前提問，即使關閉審批亦生效。

三維生成、媒體生成這類工具按次計費，過去的做法是使用者自行留意用量。新機制讓工具在定義時聲明價格，代理在請求授權時一併顯示單次費用與該段對話的累計支出；當累計金額即將超過設定上限，系統會先提問再繼續。

值得注意的是上限在關閉審批的模式下同樣生效。這個設計針對的是自動化場景：無人值守的代理若在深夜連續呼叫付費工具，沒有人會看到授權畫面，成本控制必須寫在機制裡而非依賴使用者盯螢幕。

終端機內顯示圖片與對話回溯如何改變工作流程？

命令列與文字介面可直接在對話中繪出圖片，支援 kitty、Ghostty 與 iTerm2 等終端；按兩次 Esc 或輸入 rewind 可回溯並改寫先前訊息。

過去貼上一張圖或工具完成截圖之後，終端只會印出一行檔案路徑，使用者要另外開檢視器才能確認內容。新版在支援影像協議的終端直接以像素繪出，其餘終端以彩色區塊替代，在開啟影像支援的 VS Code 終端則以完整解析度呈現。

回溯功能處理另一個長期痛點。在文字介面按兩次 Esc 或輸入 /rewind，可挑一則較早的訊息修改後重送，或由該點分岔出新的會話，原會話保持不變。另有一項排程改動值得記錄：執行中的排程可由命令列、桌面、API 或代理本身中止，每個排程亦可設定關機期間漏跑的處理方式。

效能與成本有哪些具體改善？

同一排程的每次觸發共用提示快取，單次執行少送約 1,570 個提示權杖；開啟語言伺服器時，檔案修補從 10.1 秒降至約 0.06 秒。

長期駐留的閘道最容易顯現成本。新版讓同一個排程的每次觸發共用一組提示快取鍵，背景的單次呼叫停止支付快取寫入費用，代理目標與心跳回合亦不再重寫已快取的前綴。對每日執行數十次的排程而言，這類節省會直接反映在帳單上。

介面層面的改善同樣明顯。開啟語言伺服器後，一次乾淨的 TypeScript 編輯由 10.1 秒降至約 0.06 秒，型別錯誤仍會回報給模型；桌面側邊欄在會話累積後不再變慢，官方以一個約 35,000 次排程紀錄的儲存庫為例，刷新時間由 121 秒變為即時。

儲存庫累積 261,663 顆星標、58,138 次複製與 994 位關注者，採 MIT 授權、以 Python 為主要語言，本週期有 666 位貢獻者參與。

星標與複製的比例約為 4.5 比 1，複製比例明顯高於一般關注型專案。這個比例通常反映使用者選擇自行部署，或以其作為二次開發基礎，而不是單純按下星標。待處理議題數達 53,729 個，需要在規模脈絡下理解：以每日逾百次提交的節奏計算，議題累積速度往往高於清理速度。

版本節奏亦值得記錄。專案自 2025 年 7 月建立至今已累積 47 頁版本記錄，平均每月發布多個修補版本。這種節奏對使用者是雙面刃：修補到達得快，但每次升級都需要重新確認相容性。

升級到 0.23 前應注意哪些變更？

舊有十個瀏覽器工具已移除，僅保留 browser_exec；桌面端需 macOS 13 以上；mcp serve 更名為 mcp-serve，Office 技能合併為單一項。

第一項影響最大。內建的舊瀏覽器工具全部移除，代理的瀏覽器操作統一改走 browser_exec，過去十個以 browser_ 開頭的具名工具不再存在。若有自訂提示、技能或工具清單引用舊名稱，必須先改寫，否則會在執行時直接失敗。

第二項是平台門檻。桌面應用升級至 Electron 44，macOS 11 與 12、以及 32 位元 Windows 不再支援，最低需求為 macOS 13 及 64 位元 Windows。第三項是命令更名：hermes mcp serve 改為 hermes mcp-serve，以 Hermes 作為 MCP 伺服器啟動的客戶端需要同步更新指令，系統不會自動改寫。

第四項關於技能整理。Word、PowerPoint 與 Excel 三項技能合併為單一的 microsoft-office，舊版本會留在磁碟上直到手動移除。另有一項新機制值得採用：hermes curator lock 可鎖定手工整理的技能，阻止代理透過任何工具改寫，即使在關閉審批的模式下亦生效。

總結：哪些團隊適合升級到 0.23？

需要讓多人或多裝置共用同一個代理、且長期以排程方式運行的團隊最適合；重度依賴舊瀏覽器工具名稱或舊版桌面系統者應先完成相容性檢查。

v0.23 的價值在於把代理從「一個應用程式」推向「一個服務」。工作台改由閘道供應、會話所有權收歸單一來源、外掛可自我更新、付費工具自帶價格標示，四項改動指向同一個方向：讓代理可以在無人看管的情況下長時間運行，而使用者不必逐次介入。同類的代理執行環境比較，可延伸閱讀 T3 Code 的代理執行骨架設計 與 Browser Use 1.0 重寫後的瀏覽器操作方式。

代價同樣明確。十個瀏覽器工具的移除會讓既有自動化腳本失效，桌面端的系統門檻提高，命令更名需要手動同步。對於把代理當作團隊共用基礎設施、且需要跨裝置接續工作的組織，這輪改動的效益高於遷移成本；若目前只在本機單人使用，先觀察一個版本週期、確認外掛生態跟上再升級，亦屬合理選擇。
