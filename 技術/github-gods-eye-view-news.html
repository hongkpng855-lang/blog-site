God's Eye View 開源：57K 星的間諜衛星模擬器

Eric Chan

IT 顧問・實測主義者

2026年10月17日 06:00 • 閱讀時間 3 分鐘

來源：GitHub

內容創作者： https://github.com/bilawalsidhu/gods-eye-view

God’s Eye View 是一套在瀏覽器執行的開源地理資訊儀表板，把航班、船舶、衛星、地震、火災與公開攝影機等二十個即時資料層，疊加在同一顆可以自由探索的立體地球上，並支援以語音指令完成鏡頭調度、標註與查詢。專案由 Bilawal Sidhu 與 Sameh Khamis 在 Halfpixel 維護，於 2026 年 6 月開源，並在同年 8 月登上 GitHub 趨勢榜單日與單週首位。截至 2026 年 10 月中旬，儲存庫累積約 5.7 萬顆星標、1.1 萬次複製與 1,345 次提交，二十個資料層之中有十八個無需申請金鑰即可啟用。

God’s Eye View 是什麼？

God’s Eye View 是一套在本機瀏覽器執行的開源 3D 地球儀，把航班、船舶、衛星、地震、火災與公開攝影機等二十個公開資料層整合在同一場景，並支援語音代理操作。

專案前身為 WorldView，是 YouTube 同名影片系列的官方開源客戶端，該系列累積超過五百萬次觀看。作者在 README 中說明，開源的決定來自社群投票，多數回應要求公開程式碼。因此儲存庫被定位為「基準線」，維持開放，供後續研究者擴充資料層與場景。

與商業地理情報平台不同，這套工具採本機優先的設計。伺服器只在本機監聽，涉及私密金鑰的請求全部經由伺服器端代理轉發，瀏覽器端不會直接接觸 OpenAI、AISStream 等服務的憑證。作者同時強調，專案只呈現事件、載具、基礎設施與系統，不提供具名個人搜尋、人臉辨識或個人追蹤功能。

它整合了哪些公開資料層？

二十個資料層涵蓋航班、軍機、船舶、衛星、地震、火災、攝影機、電台、公共交通與氣象，其中十八層無需金鑰，另內建資料中心、水壩與海底電纜的靜態資料。

移動類資料層以公開訊號為主。即時航班層同時接取 OpenSky 與 adsb.lol，可顯示一萬一千架以上航空器及其航線歷史；軍機層以琥珀色標示 ADS-B 訊號，緊急廣播則以紅色呈現。船舶層來自 AISStream，衛星層採用 CelesTrak 的 838 個物件編目，並以 SGP4 模型推算軌道。

攝影與環境類資料層同樣建立在公開來源之上。攝影機層彙整約四千支公開攝影機，來源包含奧斯汀、加州、倫敦、安大略、芬蘭等十多個交通機構的開放端點，影像會被投影進三維城市之中，而非以網頁嵌入方式顯示。車牌辨識攝影機層僅取用 OpenStreetMap 上由社群標註的位置與標籤，不包含任何車牌資料或影像。氣象層則整合 NOAA 的降雨雷達、衛星雲圖、閃電密度與颱風警報路徑，全部不需金鑰。

語音與 AI 代理如何操作地球儀？

語音功能以 OpenAI Realtime API 驅動，提供三十個工具，分為鏡頭調度、空間標註、資料查詢與介面操作四類，並會先讀取場景座標與圖層狀態。

語音代理並非單純的語音遙控器。每次提問之前，客戶端會把當前視角的座標、街道名稱、已啟用圖層與縮放層級送入模型，因此可以直接詢問所在地的城市名稱，或針對已點選的航班、船舶與資料中心追問細節。在街景層級，代理會讀取視埠截圖辨識招牌與建築名稱，並被要求不得憑空生成標籤。

工具組的設計圍繞四個用途：以無人機鏡頭語彙調度視角、在真實地表上繪製邊界與路線、對已載入圖層執行計數與排序，以及免持操作整個控制台。團隊亦把專案本身實作為 MCP 伺服器，可以從 Claude Desktop、Codex 或 ChatGPT 桌面版要求顯示某個地點，地球儀會直接在對話中開啟。

它的技術架構有什麼特點？

前端不使用框架，採用原生 JavaScript、CesiumJS 與 Vite；資料每十五至三十秒更新一次，畫面以延遲一週期再插值的方式維持流暢。

面對低頻更新與高視覺要求的矛盾，專案採用幾項工程取捨。航空器與船舶圖示以逐幀的螢幕空間航向投影計算方向，無論從垂直俯視或斜角觀看，圖示都會指向真實航向；在資料尚未更新的區間，系統以航位推算補足位置，讓畫面保持連續。衛星部分則以 GMST 校準軌道環，避免長時間運行後出現漂移與閃爍。

圖層元件與資料模組分離，每個資料層都是獨立模組，並附帶各自的來源說明。專案同時設有 OpenSky 點數調節器、TomTom 每日圖磚預算與磁碟快取，以降低重複請求。所有涉及私密金鑰的呼叫都經過具備 SSRF 防護、回應大小上限與錯誤訊息清理的伺服器端代理。

它與同類地理情報工具有何不同？

差異在於無金鑰門檻與本機執行：十八個資料層免金鑰即可開啟，程式碼可自行檢視與擴充，且對推估資料明確標示，而非把模擬結果當成即時觀測。

多數同類作品停留在展示層面，以單一資料源加上預錄演示，難以自行部署。此專案把二十個來源的授權、配額與失敗處理納入設計，並在無金鑰狀態下提供可用的基準底圖與地形，把金鑰定位為能力升級而非常規前提。這種安排降低了評估成本，也讓教學與研究場景較易複製。

透明度是另一項區別。專案在文件中直接標示哪些資料屬於模擬、哪些位置屬於推估，例如交通層的車輛位置是依實際路況模擬行駛，攝影機姿態是可由使用者手動校正的先驗值，火箭軌跡則標記為重建估算。這種標示方式讓使用者能判斷資料可用於何種判斷，而不是把視覺上的精緻誤讀為資料精度。

授權條款與資料來源有什麼限制？

README 說明採用 MIT 授權，但 GitHub 介面將授權標示為其他，兩者並不一致；內建與即時資料集各自附帶條款，需查閱 DATA_SOURCES.md。

授權呈現方式值得留意。儲存庫的說明文件寫明以 MIT 授權發布，而 GitHub 的授權偵測結果顯示為其他，未識別為標準條款，兩種標示並不一致。此外，專案內附的資料集、場景素材與媒體檔各自附帶獨立條款，README 的示範動畫亦聲明不得單獨重用。

資料層的可用性也受第三方條件影響。無金鑰路徑依賴各來源的公開配額，部分提供者已開始拒絕舊版客戶端的請求，專案因此在文件中要求使用者更新版本。專案同時聲明資料可能延遲、不完整、經模型推算或存在錯誤，不得用於飛航與海事導航、緊急救援、醫療決策或投資判斷。

如何開始使用 God’s Eye View？

三種安裝路徑：Pinokio 一鍵安裝、終端機安裝 Node.js 後執行 npm ci 與 npm run dev，或以 Docker Compose 啟動，預設連接埠為 4173。

最直接的路徑是 Pinokio 一鍵安裝，需使用 8.2 或更新版本。偏好命令列的使用者可以複製儲存庫後執行 npm ci、npm run doctor 與 npm run dev，開發伺服器預設監聽本機的 4173 連接埠，官方文件建議使用 Node.js 24.14 以上或 26 版，並提醒 25 版已終止支援。容器化路徑則以 Docker Compose 啟動，資料與設定留在複製下來的目錄內，移除容器不會遺失快取。

啟動後無需帳號或金鑰即可使用航班、衛星、地震、公開攝影機、電台與氣象等圖層。若需要逼真的三維城市底圖，可加入 Cesium ion 的免費權杖；Google 地圖金鑰僅在需要直接使用 Google 三維圖磚與地點搜尋時才需要。七把金鑰之中有五把附免費額度，設定流程全部在應用內的金鑰面板完成。

總結：God’s Eye View 適合什麼團隊？

適合地理資訊、資料視覺化與空間情報教學團隊，以及需要以低成本整合多來源公開資料的研究者；若追求可直接商業部署的風險控管與授權清晰度，仍需自行補強。

這個專案的價值在於把多來源公開資料的整合工作，從示範層級推進到可自行部署的狀態。二十個資料層的授權與配額處理、無金鑰的預設體驗、以及對推估資料的明確標示，構成一條實用的起點；作者亦已表明儲存庫維持開放，並預告將推出免安裝的託管版本。

採用前應留意兩項邊界。其一是授權標示不一致，涉及商業用途時需要向維護者確認；其二是資料層可用性受第三方配額與政策影響，長期運行需自行監控請求量。把這些條件納入評估，才能判斷這套工具在自身場景中的實際可用範圍。
