Cloudflare 推 Web Search API：代理的實時搜尋層

2026年10月06日 00:00 • 閱讀時間 2 分鐘 • Eric Chan • 來源：Cloudflare

Cloudflare 於二零二六年十月二日推出 Web Search API 開放測試，讓人工智能代理與應用程式直接搜尋網絡，並以即時資訊支撐回答，不再依賴模型訓練資料的截止日期。此 API 一次整合 Ceramic.ai、Exa 與 Linkup 三家搜尋供應商，統一經由 AI Gateway 呼叫，查詢會與模型推論請求一樣進入記錄、分析與計費流程，開發者可沿用既有的 REST API 或 Worker 綁定取用。

Web Search API 是 Cloudflare 於二零二六年十月推出的開放測試服務，讓 AI 代理以單一介面搜尋網絡，回傳結構化結果並餵入模型上下文。

Cloudflare Web Search API 是什麼？

它是讓 AI 代理取得即時網絡資訊的搜尋服務，代理送出查詢後會收到結構化的標題、網址與描述，取代過去猜測連結或受限於模型訓練截止日期的做法。

Web Search API 的定位並非一般搜尋引擎介面，而是代理的資訊取得層。代理送出一個查詢字串，服務便回傳一組結構化結果，包含標題、網址與頁面描述，開發者可直接把這些結果放入模型的上下文之中。其官方文件指出，這個設計解決的核心問題，是代理過去只能依靠模型記憶或自行猜測連結，容易出現過時或錯誤的資訊。

服務的另一層價值在於可觀測性。由於查詢一律經由 AI Gateway 傳送，搜索請求會與模型推論請求並列出現在同一份記錄與分析之中，讓團隊在單一後台檢視代理的完整行為。此 API 目前以開放測試形式提供，可從任何後端以 REST 呼叫，或在 Worker 中以 AI 綁定使用。

Web Search API 支援哪些搜尋供應商？

服務支援 Ceramic.ai、Exa 與 Linkup 三家供應商，未指定時預設為 Ceramic.ai；三者格式一致，只需切換參數即可替換，不必改動程式碼。

三家供應商各有技術取向。Ceramic.ai 自建超過四百億頁的獨立索引，主打低延遲與低成本，結果附帶最多八千字的長描述，適合每次任務需要執行大量搜尋的代理；Exa 結合關鍵字與向量搜尋，回傳的是頁面中最相關的文字片段，適合把精簡且切題的摘要直接送入模型；Linkup 採用快速搜尋深度並回傳原始結果，不額外生成答案，適合需要快速且附來源引用的工具呼叫。

由於三家供應商都採用相同輸出格式，切換時只需改變 provider 參數，程式碼毋須調整。這個統一介面降低了供應商鎖定的風險，也讓團隊可依任務性質在成本與品質之間取捨。

Web Search API 的計費方式如何運作？

搜索按供應商定價以 AI Gateway 額度計費，不加價：Ceramic.ai 每千次約零點二五美元、Linkup 五美元、Exa 七美元；開發者亦可自備供應商密鑰。

計費沿用 AI Gateway 的統一額度機制。當使用者以 Gateway 額度付費時，每次搜尋按各供應商的公開定價結算，Cloudflare 不另加價；若改為自備供應商密鑰，則由供應商依既有合約直接向開發者收費。官方公布的價格顯示，Ceramic.ai 每千次請求約零點二五美元，Linkup 約五美元，Exa 約七美元，價差接近三十倍。

價格之外，資料處理條款同樣值得留意。Ceramic.ai 與 Linkup 支援零資料保留，Exa 則不提供此保證。官方強調三家供應商都遵循其驗證機械人爬取標準，並在每筆結果附上來源連結，回應外界對內容來源與爬取倫理的關注。

Web Search API 與其他搜尋工具相比有何差異？

差異在於它把搜尋視為 Gateway 的一部分，與模型推論共用記錄、分析、存取控制與額度，開發者毋須自行串接多家搜尋供應商與金流。

市場上已有 Brave Search API、Tavily 及 Exa 直連等選擇，開發者亦可自行串接搜尋服務。此服務的差異化在於整合層：搜尋與模型推論共用同一套 Gateway 記錄、分析、速率限制與存取控制，團隊毋須為搜尋另建一套觀測與計費流程。

對已採用 Cloudflare 生態的團隊而言，這種整合可減少維運負擔；對尚未使用其平台的開發者，單獨導入的誘因則相對有限。服務的真正賣點，是把代理由模型呼叫到上網找資料的整條鏈路，收攏在同一個可觀測的閘道之內。

開發者如何開始使用 Web Search API？

開發者可用 REST 向 accounts 端點發出 POST 請求，或在 Worker 中以 AI 綁定呼叫，透過 provider 與 limit 控制來源與結果數量。

取用方式有兩條路徑。其一是標準 REST 呼叫，向帳號層級的 websearch 端點送出 POST 請求，於標頭帶上權杖，並在內容中指定查詢、供應商與結果數量；其二是於 Worker 中透過 AI 綁定呼叫，把 gatewayId、查詢與 provider 傳入 websearch 方法後取回 JSON 結果。

兩種方式都支援帶入自有的 Gateway 識別碼，以便在既有專案中分流記錄。官方建議初次使用者先閱讀使用說明頁面，並從預設的 Ceramic.ai 起步，確認結果品質後再依成本與資料條款調整供應商。

這項發布對 AI 開發生態有何影響？

它把即時搜尋從可選外掛變成基礎設施的一部分，降低代理取得可信資訊的門檻，也讓搜尋成本與模型成本可以在同一處被衡量與控管。

對代理開發者而言，這項服務把上網搜尋從外掛元件提升為平台層能力。過去自行串接搜尋 API、處理金流與記錄的工程負擔，如今可由單一閘道承接；搜尋用量也能與模型用量並列檢視，使團隊更容易評估代理的整體成本結構。

更深遠的影響在於資料治理。當搜尋結果須附來源、供應商須遵循爬取標準，代理所引用資訊的可追溯性隨之提高。這對需要問責的企業應用尤為關鍵，也讓「以即時資訊支撐回答」從技術選項走向合規前提。

常見問題有哪些？

以下整理四個常見疑問，涵蓋收費、供應商選擇、與自建搜尋的差異及適用團隊，答案以 Cloudflare 官方文件為準。

使用 Web Search API 需要額外付費嗎？

需要，但 Cloudflare 不另加價。搜尋以 AI Gateway 額度按供應商公開定價結算，Ceramic.ai 每千次約零點二五美元起；開發者亦可自備供應商密鑰。

該如何選擇搜尋供應商？

若重視低成本與大量查詢，可選 Ceramic.ai；需要精簡且切題的摘要片段，可選 Exa；要求快速且附來源引用的工具呼叫，則以 Linkup 較合適。

它與自建搜尋串接有何不同？

差異在整合度。此服務讓搜尋與模型推論共用同一套記錄、分析與計費，開發者毋須自行維運多家供應商的串接與金流。

哪些團隊適合採用？

已使用 Cloudflare 生態、且代理需要頻繁取得即時資訊的團隊受益最明顯；若搜尋用量極低或已有成熟自建方案，導入誘因相對有限。

總結：Web Search API 適合哪些開發者？

它適合需要讓代理頻繁取得即時資訊、並希望在同一處掌握搜尋與模型成本的團隊，尤其對已採用 Cloudflare 生態的開發者最為順手。

Web Search API 的意義，在於把即時搜尋從零散的外掛，收攏為平台層的基礎設施。當搜尋與模型推論共用記錄、計費與存取控制，開發者能以更低成本取得可追溯的即時資訊，代理的可靠性與問責性也隨之提升。

是否採用，取決於既有技術棧與用量規模。對已落在 Cloudflare 生態、且代理需要密集上網查證的團隊而言，這項服務可實際減少維運；對用量有限或已有成熟自建管線者，則宜先比較成本與資料條款再作決定。在開放測試階段，保持觀察並從預設供應商小規模試用，是風險較低的起步方式。
