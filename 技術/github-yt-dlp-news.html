19.7 萬星 yt-dlp：千站支援的開源下載器

2026年10月15日 16:00 • 閱讀時間 2 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/yt-dlp/yt-dlp

yt-dlp 是社群維護的開源命令列影音下載工具，在 GitHub 累積 197,720 顆星標與 17,237 次複製，內建超過 1,700 個網站擷取器，可處理數千個影音平台。專案源自 2021 年後實質停止維護的 youtube-dl，於 2020 年建立，改以固定節奏發布版本，並補入格式選擇、字幕處理、SponsorBlock 與外掛機制。本文整理其功能範圍、技術架構、安裝方式，以及授權與合規層面的實際限制。

yt-dlp 是什麼？

yt-dlp 是一款以 Python 撰寫的開源命令列影音下載工具，為 youtube-dl 的活躍分支，支援數千個網站，並以 Unlicense 授權釋出原始碼。

它是一支可在 Windows、macOS 與 Linux 執行的命令列程式，使用者把網址交給它，程式便會解析頁面、挑選影音串流、下載並依需求進行轉檔。專案於 2020 年 10 月 26 日建立，定位為 youtube-dl 的後繼分支，並以 youtube-dlc 為基礎重寫部分模組。

與圖形介面工具相比，它把控制權交回使用者手上。輸出檔名、畫質排序、字幕語言與後製流程都能以參數或設定檔描述，適合需要批次處理或整合進既有自動化流程的場景。專案維持高頻更新，2026 年 10 月仍有提交紀錄，主要圍繞各平台擷取器的修正。

yt-dlp 支援多少個網站與哪些功能？

官方支援站點清單列出超過 1,700 個擷取器，涵蓋數千個影音平台；功能包含格式選擇、字幕、縮圖、SponsorBlock 與外掛擴充，並可輸出成多種容器格式。

根據官方維護的支援站點清單，目前列出的擷取器超過 1,700 個，涵蓋新聞網站、影音平台、直播服務與教學網站。清單本身提醒，未列出的站點仍可能透過內嵌擷取或通用擷取器處理，而網站改版也可能令個別支援暫時失效。

功能層面以參數組合而成。格式選擇可依畫質、編碼或檔案大小排序，並在合併音訊與視訊後輸出為指定容器；中繼資料可透過嵌入選項寫入檔案，字幕與縮圖能一併下載或轉檔。SponsorBlock 整合則可依社群標記跳過或移除贊助段落，另有外掛系統供第三方擴充擷取器與後處理流程。

yt-dlp 的技術架構有什麼特色？

架構以擷取器為單位，每個網站對應一個模組，共用下載、格式解析與後處理管線；外掛機制讓第三方在不修改主程式的前提下擴充支援範圍。

核心設計是把「網站適配」與「下載流程」拆開。每個支援的網站對應一個擷取器模組，負責解析頁面與取出影音串流資訊，之後交由共用的網路層、格式選擇與後處理管線接手。這種切分讓新增平台只需撰寫一個擷取器，不必更動主流程。

外掛機制進一步把擴充成本外部化。開發者可發布獨立套件，提供額外擷取器或後處理器，主程式在啟動時載入。專案同時支援以 Python 套件或獨立執行檔兩種方式取用，後者把直譯器與相依套件打包，方便在沒有 Python 環境的機器上執行，代價是體積較大且打包版本牽涉不同授權條款。

yt-dlp 與原始 youtube-dl 有何差異？

兩者同源，但 yt-dlp 以更高頻率更新擷取器，並加入格式排序、SponsorBlock、外掛與多項預設行為調整，同時保留大部分相容的參數介面。

分支的起點是維護節奏。youtube-dl 在 2021 年後實質停止更新，多個社群分支接手，yt-dlp 由原分支演進而來，並在 2020 年後成為主要的活躍版本。專案以固定頻率發布版本，並在說明文件列出與原專案的行為差異。

差異集中在預設值與功能補強。格式選擇加入更多排序條件，預設會挑選較高畫質的串流；中繼資料、字幕與縮圖的處理選項更完整，並新增 SponsorBlock 與外掛系統。多數原本的參數與設定檔格式仍被保留，因此既有腳本往往只需小幅調整即可轉用。

yt-dlp 如何安裝與使用？

可透過 pip、系統套件管理員或官方獨立執行檔安裝；基本用法為在命令列輸入網址，再以參數指定輸出格式、檔名模板與字幕需求，亦可寫入設定檔重複使用。

安裝路徑依作業系統而異。官方釋出頁面提供 Windows、macOS 與 Linux 的獨立執行檔，另可透過 pip 或第三方套件管理員安裝。獨立執行檔把 Python 直譯器一併打包，適合不想管理環境的機器；以 pip 安裝則便於在既有 Python 專案中呼叫。

使用方式以網址為起點。把目標網址作為參數傳入後，程式會列出可用格式，使用者再以參數指定排序規則、輸出檔名模板與字幕語言。常用選項可寫進設定檔，讓重複任務不需每次輸入完整參數。官方另提供輸出模板與格式選擇的範例章節，涵蓋批次清單與僅取音訊等情境。

yt-dlp 面臨哪些合規與法律爭議？

工具本身以 Unlicense 釋出，但下載行為仍受平台服務條款與各地著作權法規範；打包版本另含 GPL 授權元件，商用前須釐清授權與使用情境。

授權與使用是兩個層次。原始碼以 Unlicense 釋出，屬於寬鬆的公共領域授權；但官方說明指出，以 PyInstaller 打包的執行檔含有 GPLv3+ 元件，因此合併後的作品受 GPLv3+ 約束。企業若要將相關檔案納入產品，需先確認所選版本對應的條款。

使用層面的風險落在使用者身上。專案定位為通用下載工具，不內建任何繞過付費牆或數位版權管理的功能，但下載行為本身仍受各平台服務條款與當地著作權法規範。用於個人備份與用於再散布，法律評價並不相同，涉及商業或公開散布時應先完成合規評估。

yt-dlp 常見問題有哪些？

以下整理版本更新頻率、支援站點失效時的處理、獨立執行檔與 pip 安裝的取捨，以及授權條款差異等常見疑問。

為什麼某個網站突然無法下載？

多數情況源於平台改版。串流位址或簽章方式一旦調整，既有擷取器就會失效，需等待專案修正並發布新版本。官方建議先更新到最新版再測試，若問題持續，可查閱議題追蹤區是否已有回報。

應該選獨立執行檔還是 pip 安裝？

取決於環境管理需求。獨立執行檔自帶直譯器，適合不想設定 Python 環境的機器，且更新只需替換檔案；pip 安裝便於在既有專案中以程式方式呼叫，並能與其他套件共用相依關係，但需自行處理環境版本。

專案多久發布一次新版本？

節奏約為每月一次，遇到平台大幅改版時會加快。官方釋出頁面保存完整版本紀錄與校驗檔，使用者可依需求選擇穩定版本或跟隨最新版本。專案亦提供自動更新與版本檢查相關選項。

總結：yt-dlp 適合什麼使用者？

適合需要批次處理影音、重視參數控制與自動化整合的技術使用者；若涉及商業散布或平台授權爭議，則須先釐清授權與法規限制。

yt-dlp 的價值在於把頻繁變動的網站適配工作收斂為可替換的擷取器。197,720 顆星標與超過 1,700 個擷取器，反映的是影音平台長期缺乏統一取用介面的現實需求；以社群維護取代單一團隊的節奏，也讓修補能更快跟上平台改版。

採用前仍須衡量兩件事：擷取器的維護速度能否涵蓋實際使用的平台，以及下載行為在平台條款與當地法規下的合規界線。對需要批次處理與流程整合的技術使用者，這是一套成熟度相當高的工具；對需要商用授權與穩定技術支援的團隊，則應先確認所選版本的授權條件再行評估。
