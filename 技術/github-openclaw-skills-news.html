OpenClaw 技能清單開源：5.3 萬星收錄 5,300 項

2026年10月12日 20:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/VoltAgent/awesome-openclaw-skills

Awesome OpenClaw Skills 是 VoltAgent 維護的開源技能清單，在 GitHub 累積 53,040 顆星標與 5,049 次複製，採用 MIT 授權。它從 OpenClaw 的公開技能註冊表 ClawHub 篩出 5,300 多項社群技能，整理成 28 個類別，並明確標示哪些項目已被排除。專案於 2026 年 10 月 5 日仍有提交，本文從官方儲存庫出發，分析其篩選機制、類別結構、安裝路徑與安全須知。

Awesome OpenClaw Skills 是什麼？

Awesome OpenClaw Skills 是 VoltAgent 維護的開源技能清單，從 ClawHub 註冊表篩出 5,300 多項技能並分成 28 類，採 MIT 授權。

專案的定位是社群技能的目錄。OpenClaw 是一套在本機運作的 AI 助理，技能則用來擴充它的能力，讓它連接外部服務、自動化流程或執行特定任務；清單的用途是協助使用者找到並安裝合適的技能，同時作為應用場景的參考。所有收錄項目都來自 ClawHub，不接受個人儲存庫或外部來源的連結。

專案於 2026 年 1 月 25 日建立，由 VoltAgent 團隊維護，並以網站 clawskills.sh 作為瀏覽入口。清單本身不是可執行的軟體，而是一份經過人工整理的文件，價值在於把分散在註冊表中的數千項技能收斂成可搜尋的結構，並公開說明哪些項目被排除及其原因。

目標受眾涵蓋自行架設代理的開發者、評估代理工具鏈的技術團隊，以及需要為特定場景尋找現成流程的使用者。由於清單同時列出技能數量與類別分佈，它也常被用來觀察代理技能生態的組成與變化。

清單收錄哪些技能類別與數量？

清單分成 28 個類別，涵蓋 5,300 多項技能，其中編碼代理與 IDE 類約 1,184 項、網頁與前端約 920 項、DevOps 與雲端約 393 項、搜尋研究約 343 項。

類別結構以使用場景為主軸。目錄中規模最大的三類分別是編碼代理與 IDE、網頁與前端開發，以及 DevOps 與雲端，顯示技能供給明顯集中於軟體開發流程；其餘類別則延伸到行銷與銷售、通訊、生產力、圖像與影片生成、語音轉錄、智慧家居與遊戲等領域。

規模差異同樣值得注意。部分類別的項目數以千計，另有類別僅收錄二、三十項，例如自架與自動化、iOS 與 macOS 開發、Moltbook 等，反映社群投入程度並不平均。清單為較大的類別另設獨立頁面，讓使用者不必在單一文件中捲動數千行內容。

分類也具備檢索功能。每項技能以一行呈現，包含名稱、ClawHub 連結與一句描述，使用者可依類別縮小範圍，再進入技能頁面查看細節。這種以描述句為主的索引方式，讓清單在搜尋引擎與 AI 助理中都能被有效抽取。

清單的篩選機制如何運作？

清單只納入已發佈於 ClawHub 的技能，並排除可能為垃圾、名稱重複、描述低品質、加密金融類與經安全研究通報為惡意的項目，合計排除 7,215 項。

收錄門檻設在註冊表層級。專案要求技能必須已發佈於 ClawHub，不接受個人儲存庫、摘要頁或其他外部來源的連結；這項規則使清單的可維護性提高，也讓每一項收錄都能追溯回官方註冊資料。

排除標準則分成五類並公開數量。官方統計顯示，被排除的項目中，疑似垃圾或測試用帳號共 4,065 項，名稱重複或相似者 1,040 項，描述低品質或非英語者 851 項，加密、區塊鏈與金融交易類 886 項，經安全研究者通報為惡意者 373 項，合計 7,215 項未納入。

這種做法的意義在於資訊揭露。相對於只列出推薦項目的清單，專案同時說明過濾掉什麼、數量多少，讓讀者理解目錄的邊界；但清單本身也強調，收錄僅代表人工整理，並非安全稽核，這項聲明直接影響後續的使用方式。

專案累積 53,040 顆星標、5,049 次複製與 314 位關注者，逾 100 位貢獻者參與，採 MIT 授權，目前有 6 個未結議題，主要內容為 Markdown 目錄。

授權條款屬寬鬆類型。MIT 授權允許使用、修改與再散布，也允許整合進商業產品，僅要求在副本中保留著作權與授權聲明。清單本身以 Markdown 目錄為主，沒有主要程式語言，因此採用時不涉及執行環境或相依套件。

維護活躍度可從提交節奏觀察。專案目前有超過 100 位貢獻者與 6 個未結議題，最近一次提交為 2026 年 10 月 5 日更新官方 MCP 伺服器徽章，前一週的提交量超過 500 次，顯示清單在註冊表持續擴張下需要頻繁同步。

清單在代理技能生態中扮演什麼角色？

它把註冊表的技能供給轉為可檢索的目錄，位於 ClawHub 與使用者之間；相較個別技能頁面，清單提供跨類別的比較與數量分佈，便於評估生態重心。

它的位置介於註冊表與使用者之間。ClawHub 提供技能的發佈與安裝機制，清單則負責發現與分類；兩者分工後，使用者不必逐頁瀏覽註冊表，即可掌握有哪些類別、各有多少項目，以及哪些已被排除。

與一般開源工具相比，這類清單的影響力來自索引本身。當代理能力越來越依賴可複用的流程，能否快速找到對應技能就成為效率瓶頸；一份持續同步、並公開排除標準的目錄，能降低搜尋成本，也讓生態的重心與缺口變得可見。

商業化路徑則偏向贊助與導流。清單頁面設有贊助版位，並以社群資源的形式存在，本身不提供付費服務或授權費用。對採用者而言，這意味著使用門檻極低，但清單的維護節奏與收錄判斷仍取決於維護團隊。

如何快速開始使用這份清單？

可依類別瀏覽清單並以 openclaw skills install 安裝指定技能，或使用 npx clawhub install；亦可手動複製技能資料夾到全域或工作區目錄。

安裝路徑分為三種。使用 OpenClaw 命令列工具時，可直接依技能代稱安裝；若在完整工作區之外管理技能資料夾，則可改用 ClawHub 的命令列工具。以下為官方提供的安裝指令：

# 透過 OpenClaw CLI 安裝
openclaw skills install <skill-slug>

# 透過 ClawHub CLI 安裝（適合註冊表管理的技能資料夾）
npx clawhub install <skill-slug>

手動安裝則需注意優先順序。技能資料夾可放置於全域目錄或專案工作區目錄，載入優先序為工作區高於本機、本機高於內建；這種設計讓同一台機器可同時保有通用技能與專案專屬技能。官方亦提到，將技能的儲存庫連結貼進助理對話，由助理在背景完成設定，是另一種可行的方式。

實務上建議先確認技能來源與維護狀態，再依需求逐項加入，而非一次安裝大量技能，因為技能會直接影響代理可執行的操作範圍。

使用這些技能有哪些安全風險？

清單屬人工整理而非安全稽核，技能可能被原作者更新或替換；官方建議安裝前檢視原始碼，並透過 ClawHub 技能頁的 VirusTotal 報告與安全掃描工具確認風險。

風險提示是清單中少見的強制章節。官方明確指出收錄項目為整理而非稽核，技能可能在收錄後被原作者更新、修改或替換；文件中列舉的潛在風險包括提示注入、工具污染、隱藏惡意負載與不安全的資料處理模式，並要求使用者在安裝前自行檢視原始碼。

可用的查核資源也已列出。OpenClaw 與 VirusTotal 合作提供技能掃描，使用者可在 ClawHub 的技能頁面查看該技能是否被標記為高風險；清單另推薦 Snyk 的技能安全掃描器與 Agent Trust Hub，作為進一步驗證來源與信任分數的工具。若發現清單中的技能有安全疑慮，可透過議題回報。

對企業環境而言，這項聲明意味著導入流程仍需自建。清單能加速篩選，但無法取代內部的程式碼審查、權限控管與稽核紀錄；將技能納入既有供應鏈管理流程，是採用時較穩妥的做法。

總結：這份清單適合什麼團隊？

這份清單適合自行架設 OpenClaw、需要快速找到現成技能並評估生態重心的個人與團隊；若要求技能已通過安全稽核，仍須自行建立審查流程。

清單的價值在於把註冊表的規模轉化為可檢索的結構。透過 28 個類別、5,300 多項收錄與公開的 7,215 項排除統計，它讓使用者理解代理技能生態的組成與邊界；採 MIT 授權、以 Markdown 目錄呈現，也讓採用過程幾乎沒有技術門檻。

採用前仍須衡量現實條件。清單定位為人工整理而非安全稽核，技能可能隨時被原作者更新，因此導入前檢視原始碼與查核 VirusTotal 報告是必要步驟；對需要大量技能的團隊而言，分批評估與權限控管會比一次安裝更為穩妥。若目標是快速找出可用流程並掌握生態動向，這份清單具備明確優勢。
