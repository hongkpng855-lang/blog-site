Apple 開源容器工具：Mac 原生 Linux 容器引擎

2026年10月05日 08:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/apple/container

apple/container 是 Apple 於二零二五年五月開源的容器工具，截至二零二六年十月在 GitHub 累積 50,495 顆星標與 1,809 次複製，採用 Apache-2.0 授權，以 Swift 撰寫。它讓 Apple silicon 的 Mac 能以輕量虛擬機器的方式建立與執行 Linux 容器，並完整支援 OCI 標準映像。最新正式版本為 1.5.0，於二零二六年九月二十九日發布。

apple/container 是 Apple 開源的容器工具，以 Swift 撰寫、Apache-2.0 授權，在 Apple silicon 的 Mac 以輕量虛擬機器執行容器。

apple/container 是什麼？

此專案以命令列為主要介面，可在 Apple silicon 的 Mac 上建立與執行 Linux 容器，每個容器置於獨立的輕量虛擬機器。

根據專案自述，container 是一套可在 Mac 上建立與執行 Linux 容器的工具，做法是把每個容器放進獨立的輕量虛擬機器，而非共用單一 Linux 核心。工具同時消費與產出 OCI 相容的容器映像，因此可直接從任何標準容器登錄檔拉取映像，也能把自行建置的映像推回登錄檔，或在其他相容應用中執行。

它的定位與傳統容器執行環境不同。由於 macOS 沒有原生 Linux 核心，容器必須仰賴虛擬化層；Apple 的做法是把虛擬化、映像與行程管理交由名為 Containerization 的 Swift 套件處理，命令列工具本身則負責操作介面與背景系統服務。這種分工讓底層能力可被其他 macOS 應用直接引用，而不必綁定單一命令列工具。

apple/container 的開發背景是什麼？

專案於二零二五年五月三十日由 Apple 開源，主要語言為 Swift，採用 Apache-2.0 授權，可自由用於個人與商業專案。

專案於二零二五年五月三十日建立，由 Apple 的開源團隊維護，主要語言為 Swift，採用 Apache-2.0 授權，可自由用於個人與商業專案。它並非獨立成形，而是建立於同屬 Apple 開源的 Containerization Swift 套件之上；該套件負責低階的容器、映像與行程管理，本身亦累積 8,961 顆星標。

版本節奏反映專案已進入產品化階段。專案於二零二六年達到 1.0 正式版，其後持續以產品版本而非語意化版本發布，至九月二十九日推出 1.5.0。官方說明，命令列介面在同一主要版本內一般保持向後相容，但標示為實驗性的功能（例如 Kubernetes 子命令）不保證相容，使用者升級前需留意版本說明。

apple/container 有哪些核心技術亮點？

核心亮點包括每個容器使用獨立輕量虛擬機器的隔離模型、完整相容 OCI 映像、與 macOS 系統服務的原生整合，以及內建的 Kubernetes 實驗性支援。

第一項是隔離模型。每個容器執行於各自的輕量虛擬機器之中，而非共用同一個 Linux 核心，這使容器之間的隔離層級高於傳統共用核心的做法，代價則是每個容器需要獨立的虛擬化負載。由於虛擬化與網路能力依賴 macOS 26 的新功能，工具僅支援該版本以上的系統。

第二項是標準相容。工具消費與產出 OCI 相容映像，可直接對接 Docker Hub 等既有登錄檔，並支援多平台映像建置；使用者的既有映像資產不需轉換即可沿用。

第三項是與 macOS 的原生整合。工具以系統服務形式在背景執行，透過 XPC 提供應用程式介面，並針對 Apple silicon 最佳化。它另內建 Kubernetes 子命令，可在本機建立測試用叢集，並允許指定自訂 CNI 清單，此功能目前標示為實驗性。

apple/container 如何實現 Mac 上的 Linux 容器？

工具以輕量虛擬機器承載容器，由 Containerization Swift 套件管理虛擬化、映像與行程，並以背景系統服務與 XPC 介面串接。

運作核心是把虛擬化層產品化。每個容器對應一台輕量虛擬機器，由 Containerization 套件透過 macOS 的虛擬化框架啟動，並在同一套機制上處理映像分層、檔案系統掛載與網路設定，使容器享有接近原生容器的啟動速度，同時保有虛擬機器的隔離邊界。

對外的操作則由系統服務承擔。使用者在終端機執行命令後，命令列工具與背景服務溝通，由服務管理容器生命週期、映像快取與網路狀態；官方文件另提供技術概觀，說明主機與客體之間的整合方式，例如檔案系統共享與網路轉送。

apple/container 支援哪些功能與工具鏈？

工具支援 OCI 映像、多平台建置、資料卷、網路設定、資源用量檢視、日誌、主機整合與命令補全，並內建實驗性的 Kubernetes 子命令，可建立本機測試叢集。

在映像層，工具支援從標準登錄檔拉取與推送映像，並可指定目標架構進行多平台建置，以產生同時涵蓋多種平台的映像。在執行層，它提供資料卷掛載、網路設定、資源用量檢視與日誌輸出，讓容器在開發與測試情境中具備實用性。

在作業層，工具提供命令補全與主機整合設定，並附有 Shell 補全與系統設定文件。針對需要容器編排的場景，Kubernetes 子命令可建立本機節點並部署工作負載，最新版本另加入自訂 CNI 清單選項，讓開發者能在 Mac 上驗證叢集設定。

apple/container 與 Docker Desktop 有何差異？

兩者皆能在 Mac 執行容器；apple/container 為開源命令列工具，限定 Apple silicon 與 macOS 26；Docker Desktop 提供圖形介面。

最直接的差異是授權與收費。apple/container 以 Apache-2.0 授權開源，不含商業授權門檻；Docker Desktop 對大型企業另有付費要求。對需要控制成本或要求完全開源工具鏈的團隊而言，授權條款本身就是選擇因素。

第二項差異是系統限定與操作形態。apple/container 僅支援 Apple silicon 且要求 macOS 26，並以命令列為主要介面，沒有圖形化的容器管理面板；Docker Desktop 支援範圍較廣，並提供完整的桌面介面與擴充生態。對於已熟悉容器命令的使用者，兩者的操作習慣相近，官方快速入門即以執行一次性容器作為第一個範例。

apple/container 的專案數據與版本節奏如何？

截至二零二六年十月，專案累積 50,495 顆星標、1,809 次複製、逾七百七十次提交與超過一百一十位貢獻者，並已發布二十四個版本，最新為 1.5.0。

  • 110+貢獻者
  • 770+累積提交

這些數字反映的是一套由廠商主導、維持穩定節奏的基礎工具。專案自二零二五年五月建立以來累積逾七百七十次提交，貢獻者超過一百一十位，已發布二十四個版本，平均約每月推出一次更新，並於二零二六年達到 1.0 正式版。

如何快速開始使用 apple/container？

使用者需具備 Apple silicon 的 Mac 與 macOS 26，從發布頁下載簽署安裝套件，安裝後啟動系統服務，再執行 container run 指令。

前置條件是先確認硬體與系統版本。工具僅支援 Apple silicon 的 Mac，並要求 macOS 26 以上，因為它使用該版本新增的虛擬化與網路能力；官方明言不支援較舊系統，且不會處理無法在 macOS 26 重現的問題。

安裝方式為從 GitHub 發布頁下載已簽署的安裝套件，安裝時需輸入管理員密碼，以將檔案放入系統目錄。安裝完成後啟動系統服務，即可執行第一個容器。

# 啟動系統服務
container system start

# 執行第一個容器
container run --rm alpine echo hello

上述指令會拉取 alpine 映像、於輕量虛擬機器中執行並輸出 hello，完成後自動移除容器。官方另提供導覽教學，示範如何建置並發布一個自製的網頁伺服器映像；升級時可使用隨工具安裝的更新腳本，但需先停止既有服務。

apple/container 適合什麼團隊？

它適合使用 Apple silicon 且要求開源授權的開發與平台團隊，特別是需要在 Mac 本機執行容器或驗證 Kubernetes 設定的情境。

apple/container 的意義在於把容器執行能力沉澱到作業系統層。專案擁有 50,495 顆星標、逾一百一十位貢獻者與二十四個版本，以 Apache-2.0 授權開放，並將底層能力封裝為可被其他應用引用的 Containerization 套件，使容器執行不再只是第三方軟體的功能，而成為 macOS 的一部分。

對於使用 Apple silicon、重視開源授權與本地開發體驗的團隊，它提供了低門檻的替代路徑，尤其是需要在本機驗證 Kubernetes 設定的開發者。若團隊成員仍使用較舊的 macOS，或需要圖形化管理介面與跨平台支援，則仍須評估其他方案。

常見問題有哪些？

apple/container 的常見疑問集中在硬體要求、Docker 相容性、授權與 Kubernetes 支援；它僅支援 Apple silicon，映像格式相容。

apple/container 需要什麼硬體與系統？

需要配備 Apple silicon 的 Mac，並執行 macOS 26 以上版本；較舊的 macOS 與非 Apple 硬體皆不支援。

它與 Docker 的映像相容嗎？

相容。工具消費與產出 OCI 標準映像，可直接從標準容器登錄檔拉取，也能將映像推送至既有登錄檔。

apple/container 是免費的嗎？

是。專案以 Apache-2.0 授權開源，可自由用於個人與商業專案，不設商業授權門檻。

它可以在 Mac 上執行 Kubernetes 嗎？

可以。工具內建 Kubernetes 子命令，可建立本機測試叢集，並支援自訂 CNI 清單；該功能目前標示為實驗性，不保證版本間相容。

使用 apple/container 需要圖形介面嗎？

不需要。它以命令列為主要操作方式，透過背景系統服務執行，沒有隨附的圖形化管理面板。
