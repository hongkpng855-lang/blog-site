Immich 開源：自託管相片庫突破 11 萬星

2026年09月23日 00:00 • 閱讀時間 3 分鐘 • Eric Chan • 來源：GitHub

內容創作者： https://github.com/immich-app/immich

Immich 是 2022 年 2 月開源的自託管相片與影片管理方案，在 GitHub 累積 114,806 顆星標與 7,034 個分支，被廣泛視為 Google Photos 的替代選擇。它由 Flutter 行動應用、SvelteKit 網頁介面與 TypeScript 伺服器三部分組成，讓使用者把自動備份、人臉辨識與語意搜尋整套運行在自己的硬體上，並以 AGPL-3.0 授權釋出。在雲端相簿服務接連調整儲存政策與定價之後，把資料主權交回使用者手上的做法，正好回應了市場的疑慮。

Immich 是開源的自託管相片與影片管理方案，GitHub 星標 114,806。它把自動備份、人臉辨識與 CLIP 搜尋放回自有伺服器，採 AGPL-3.0 授權。

Immich 是什麼？

Immich 是自託管的相片與影片備份平台，支援自動上傳、去重、人臉辨識、物件搜尋與多用戶共享。使用者自行架設伺服器，資料不經過第三方雲端。

專案的自我定位相當直接，README 開頭寫的是高效能的自託管相片與影片管理方案。實際運作模式是一個由使用者自行部署的伺服器，搭配 Android 與 iOS 行動應用，以及一套網頁介面。行動應用在開啟時自動備份相簿，伺服器負責建立索引、比對重複檔案並產生縮圖，網頁介面則處理瀏覽、搜尋與共享。整個流程不需要連結任何外部雲端帳號，資料存放位置由部署者自行決定。

這種架構的代價是維護責任轉移。README 開頭即以警告框提醒使用者，務必依照三二一備份原則處理珍貴的相片與影片，意味著專案本身不承擔資料保存的保證。自託管並非免責，而是把備份策略的主導權與責任一併交回使用者。

Immich 的項目背景與資金來源為何？

專案於 2022 年 2 月 3 日建立，由 immich-app 社群維護，現由非營利組織 FUTO 支持開發。程式碼以 AGPL-3.0 授權釋出，官方網站為 immich.app。

專案建立於 2022 年 2 月 3 日，適逢各家雲端相簿服務陸續縮減免費額度，社群對自託管替代方案的需求快速上升。倉庫目前累積超過一萬一千次提交與三百多位關注者，貢獻者數以百計，其中約三成為長期活躍成員，其餘多為單次修補或翻譯貢獻。程式碼的主要語言為 TypeScript 與 Dart，前者用於伺服器與網頁，後者用於行動應用。

資金來源是理解這個專案走向的關鍵。官方網站將 FUTO 列為所屬公司，FUTO 是一個專注於資料主權的非營利組織，長期資助讓使用者保有資料控制權的開源軟體。這種安排在商業模式上相對少見，專案同時開設付費購買頁面與周邊商店，作為支持營運的補充管道。與依賴風險投資的開源專案相比，非營利資助降低了被收購或轉向封閉授權的機率，這也是社群願意長期投入的重要原因。

Immich 有哪些核心功能與技術架構？

架構分為 TypeScript 伺服器、SvelteKit 網頁與 Flutter 行動應用三層。涵蓋自動備份、去重、RAW 支援、人臉辨識與 CLIP 搜尋及多用戶共享。

功能清單以備份與檢索為兩條主線。備份端支援行動應用開啟時自動上傳、可選擇特定相簿備份、原始格式保留、LivePhoto 與 360 度影像處理，以及使用者自訂的儲存目錄結構。檢索端則提供依中繼資料、拍攝物件、人臉與 CLIP 向量的搜尋，並把 EXIF 資訊與地理位置整合進地圖檢視。人臉辨識與叢集功能可自動歸類同一人物的相片，合作夥伴共享則讓多用戶之間各自保留獨立相片庫。

共享與權限設計是另一個重點。系統支援多用戶、共享相簿、唯讀相簿、公開分享連結、典藏與最愛標記，以及每位使用者自有的儲存結構。管理端提供使用者管理、API 金鑰與 OAuth 登入，方便整合既有的身分驗證系統。行動端另有離線支援，網頁端則偏向管理與大量瀏覽，兩者分工明確。

Immich 3.2 版本帶來哪些新功能？

3.2 版新增 Docker compose 建置工具、重製搜尋介面與 Search API v2，並支援跨使用者臉部叢集、標籤觸發工作流與標籤重新命名。

最新穩定版本為 2026 年 9 月 15 日發布的 3.2.2，屬小型修補，主要修正重新指派人臉時的範圍問題。真正的功能更新集中在 9 月 10 日的 3.2.0，官方列出八項重點，其中三項值得留意。第一是 Docker compose 建置工具，讓使用者以網頁表單組合自訂的容器設定檔，降低初次部署的門檻。第二是全新的搜尋 API，支援在相簿範圍內搜尋，並允許以 AND 與 OR 組合多種過濾條件。

第三項是跨使用者的臉部叢集。同一個信任群組內的使用者可以共享人臉辨識結果，讓共享相簿中的人物自動歸類到自己既有的標籤之下，叢集運算的樣本數也因此增加，理論上有助提升辨識準確度。官方同時說明，啟用這項功能需要重置群組內所有人的人臉辨識結果，既有姓名與生日標記會遺失，屬於一次性成本。

Immich 如何安裝與部署？

官方建議至少 6GB 記憶體與 2 核心處理器，並預先安裝 Docker。部署時下載官方 compose 檔與環境變數範本，設定儲存路徑與資料庫密碼後啟動容器。

官方快速開始文件把安裝流程壓縮成三個步驟，前提是一台至少具備 6GB 記憶體與 2 核心處理器的機器，以及已安裝的 Docker 環境。使用者先建立一個工作目錄，下載官方提供的容器設定檔與環境變數範本，再於範本中設定相片儲存路徑、資料庫資料路徑與時區，並把預設的資料庫密碼改為隨機字串，最後啟動容器即完成。

需求門檻值得說明。6GB 記憶體對家用伺服器或舊電腦而言並非隨手可得，主因是系統同時包含資料庫、機器學習推論與影像處理元件，其中人臉辨識與語意搜尋會在首次匯入時大量消耗資源。官方文件亦提醒，資料庫資料不可放在網路共享目錄，儲存路徑則需要足夠的可用空間。對打算長期使用的使用者而言，硬碟容量與備份方案通常比處理器效能更值得優先規劃。

Immich 與 Google Photos 有何差異？

差別在資料位置與成本結構。Immich 把相片存於自有硬體，無訂閱費與容量上限，但需自行維護備份；Google Photos 免維護，卻受制於服務政策。

兩者的根本差異在於資料位置。Immich 把原始檔案保存在使用者自己的硬碟，伺服器只負責索引與介面，因此不存在容量上限與訂閱費用，服務政策變動也不會影響既有資料。相對地，Google Photos 提供免維護的體驗，代價是資料存放於第三方，儲存額度與功能調整由服務方決定。專案的 GitHub 主題標籤直接標示為 Google Photos 替代方案，定位十分明確。

功能層面各有取捨。Immich 的優勢在於可自訂儲存結構、支援原始格式與開放 API，並能依需求關閉或開啟機器學習功能；缺點是部署與升級需要技術能力，行動應用的穩定性也取決於使用者自身的網路設定。官方明確提醒使用者遵循三二一備份原則，正說明自託管並不免除資料遺失的風險。對重視資料主權的使用者，這種交換是值得的；對只想隨手備份的人，雲端服務仍是更低摩擦的選擇。

Immich 的數據表現如何？

倉庫累積 114,806 顆星標、7,034 個分支與 359 位關注者，共一萬一千餘次提交與三百多個版本，開放問題約 737 項，並以 AGPL-3.0 授權釋出。

數據反映的是一個高度活躍的長期專案。一萬一千餘次提交與三百多個版本標籤，平均下來每週都有數次提交，最新一次提交與本文取材時間同日。三百一十一次發布紀錄說明版本節奏穩定，這對自託管軟體格外重要，因為使用者需要可預期的升級路徑與修補頻率。開放問題約 737 項，對一個規模如此的功能集而言屬合理水位。

分支與星標的比例同樣值得觀察。7,034 個分支對應 114,806 顆星標，比例約為十六比一，低於一般工具型專案。較低的分支比例通常意味著使用者以部署而非修改為主，多數人取用官方映像檔而非自行編譯，這與專案提供官方容器映像的做法一致。

常見問題有哪些？

以下整理三個關於 Immich 的常見疑問，涵蓋硬體需求、與雲端服務的取捨，以及是否需要具備程式開發能力才能部署。

使用 Immich 需要付費嗎？

不需要。專案以 AGPL-3.0 授權開源釋出，可自由使用與修改。官方另設購買頁面與周邊商店，屬自願支持性質，並非使用軟體的前置條件，使用者亦可直接由官方映像檔自行部署。

部署 Immich 需要很強的技術能力嗎？

官方快速開始文件將流程壓縮為三個步驟，具備基本 Docker 操作經驗即可完成。3.2 版加入的 compose 建置工具以網頁表單產生設定檔，進一步降低了初次部署的門檻。長期維護則需理解容器升級與備份策略。

自託管是否代表資料一定安全？

不是。官方在 README 明確提醒使用者遵循三二一備份原則，說明自託管把保存責任交回使用者。硬碟故障、誤刪與設定錯誤仍是實際風險，完整備份方案與異地副本仍是必要條件。

總結：Immich 適合什麼團隊？

Immich 適合重視資料主權、具備基本伺服器維護能力的個人與小型團隊，尤其是相片量大、對雲端訂閱成本敏感，或需要自訂儲存結構與開放 API 整合的使用者。

把相片庫搬回自己的硬體，是 Immich 與雲端服務最根本的差異。它以三層架構涵蓋備份、檢索與共享，用 114,806 顆星標與約十六比一的分支比例，說明這種取向已獲大量實作者採用；非營利組織的資助背景，也讓專案在授權與方向上相對穩定。

需要留意的是維護成本。官方對硬體的要求並不低，人臉辨識與語意搜尋在首次匯入時相當耗資源，跨使用者叢集功能更需重置既有標記。對願意投入時間規劃備份與升級流程的使用者，Immich 提供的是可長期掌握的控制權；對希望零維護的使用者，雲端服務仍是更務實的起點。
